# 팀 세션 운영 규칙 (TEAM_RULES)

## 구성

- **PM** (리더): 사용자의 지시를 직접 받는 유일한 창구. 작업을 분석해 구현담당1/2에게 배정하고, 본인도 코딩한다.
- **리서치담당** (부리더): 조사·탐색·분석·설계 검토 전담. 코드 파일을 **작성/수정하지 않는다** (Read/Grep/WebSearch 등 읽기 전용). 결과는 PM에게 보고한다.
- **구현담당1 / 구현담당2** (팀원): PM이 배정한 코딩 작업을 수행한다. 완료 후 PM에게 보고하고, PM이 요청하면 PM의 코드를 리뷰한다.

## 워크플로

1. 사용자가 PM에게 지시한다.
2. PM은 조사·분석·설계 판단이 필요하다고 보면 **리서치담당과 먼저 의견을 조율**한다 (SendMessage).
3. PM은 작업을 쪼개 구현담당1/2에게 배정한다. 배정 메시지에는 반드시 포함:
   - 목표, 대상 파일/폴더, 완료 조건, 건드리지 말아야 할 영역
4. 구현담당은 작업 완료 시 PM에게 보고: 변경 파일 목록 + 요약 + 검증 결과.
5. **코드리뷰 규칙**
   - PM이 코딩한 결과 → 구현담당1/2 중 **쉬고 있는 세션**에게 리뷰 요청.
   - 구현담당1/2가 코딩한 결과 → **PM**이 리뷰.
   - 리뷰어는 버그/누락/규칙 위반 위주로 지적하고, 승인 여부를 명확히 답한다.
6. 사용자에게 최종 보고는 PM이 한다.

## 충돌 방지

- 같은 파일을 두 세션이 동시에 수정하지 않는다. PM이 배정 시 파일 소유를 나눈다.
- 다른 세션이 소유한 파일을 고쳐야 하면 먼저 PM에게 알린다.
- `git commit`은 PM이 자주 수행한다 (씬 수정 전엔 반드시). `git push`는 사용자가 요청할 때만.

## 메시지 형식

- 보고/요청 시 첫 줄에 `[역할 → 역할] 제목` 형식으로 시작한다.
  예: `[구현담당1 → PM] 타워 스폰 로직 구현 완료`
- 리뷰 결과는 `승인` / `수정 요청` 중 하나로 시작한다.

## 모델 정책

- **PM**: Fable 5 (`claude-fable-5`)
- **리서치담당 / 구현담당1 / 구현담당2**: Sonnet 5 (`claude-sonnet-5`) 기본값
- 새 세션은 `.claude/team/start.sh <역할>`로 띄우면 자동으로 Sonnet 5가 적용된다.


## 커밋 전 점검 (PM)

새 스크립트나 에셋을 만든 뒤에는 **푸시 전에 반드시** 실행한다:

```
python3 Tools/check_meta.py
```

`.meta`에는 GUID가 들어 있고 씬은 컴포넌트를 그 GUID로 참조한다.
`.meta` 없이 커밋하면 다른 컴퓨터에서 클론했을 때 Unity가 새 GUID를 발급하고,
그 스크립트를 쓰는 씬 참조가 전부 Missing Script가 된다.

Unity가 `.meta`를 만드는 시점이 스크립트를 만든 직후가 아니라 **에디터가 임포트할 때**라,
`git add`를 먼저 하면 매번 놓친다. 실제로 세 번 놓쳤다.
