## ⚠️ 네 환경의 제약

**너는 컴파일을 검증할 수 없다.** `Tools/compile_check.sh`는 로컬 Unity 설치본을 쓰는데
클라우드엔 Unity가 없다(돌려도 exit 2로 실패한다). 그래서:

- **`main`에 커밋하지 마라.** 시작하자마자 `git checkout -b cloud/2026-09-05-resume`로
  브랜치를 파고 거기서만 작업하고 거기로만 푸시한다. 로컬 PM이 컴파일 확인 후 합친다
- **큰 리팩터링·타입 변경·메서드 시그니처 변경 금지.** 깨져도 아무도 못 알아챈다
- **직렬화되는 enum에 값을 끼우지 마라**(맨 뒤에만)
- **`Tools/generate_*.py`를 절대 돌리지 마라.** 로스터에 쓰는 파괴적 스크립트다
- **씬(`Assets/Scenes/SampleScene.unity`)을 손으로 고치지 마라.** 맵 생성기가 다시 만드는
  파일이라 손댄 건 사라진다. 고칠 게 있으면 `Assets/Editor/MapGenerator.cs`를 고친다
- `python3 Tools/check_meta.py`는 돌려도 된다 (Unity 불필요)
- 커밋은 반드시 `git commit -m '...' -- <파일 나열>` 형태로. `git add <디렉터리>` 금지
- **`war3map.j` 원문은 네게 없다**(로컬 스크래치에만 있다). 원작 확인이 필요한 일은
  손대지 말고 보고서에 「원문 확인 필요」로 남긴다

## 이미 확정된 사실 (다시 뒤집지 마라)

- **우리 몹 HP 커브는 원작과 동일하다(K=1).** 몹 대상 고정피해는 환산 없이 원작값 그대로가 정답
- **와포루의 「스토리에 450만 마법피해」는 원작에도 배선이 없다.** 만들지 않는 게 정확한 이식
- **스모커 보상은 3,000골드다**(5,000이 아니다)
- **원작 툴팁은 원작 동작이 아니다.** 판정은 트리거·오브젝트 데이터 쪽
- **`critDamageMultiplier`가 238종 전부 1.0인 건 결측이 아니라 설계 선택**이다.
  배수분이 `critBonusDamage`에 흡수돼 있어 **채우면 두 번 곱해진다**
- **`UnitData.hp`를 읽는 코드가 없는 것도 정상**이다(원작도 아군 체력은 의미가 없다)
- **마나 상한 1000 · 시작 15**가 원작값이고 이미 들어갔다
- **라운드당 몹 수는 전 라운드 35 고정**이다(원작 트리거 확인). 「15→35 램프」는 폐기됐다
- **히든·불멸·영원은 조합이 아니라 채팅 코드로 만든다**(원작 트리거 67개). 우리는 조합식으로 만들고 있고, 그건 사장님 판단 대기다
- **우리 유닛 이름은 원작과 겹침이 0이다**(실측 확인). **이름으로 원작과 대조하려 하지 마라**
- **원작 등급별 화력은 단조 증가한다.** 우리 로스터가 비단조인 건 등급 서열이 원작과 달라서다 — 사장님 판단 대기
- ⚠️ **`c9db45e` 커밋 메시지의 「원작 조합에는 라운드 제한이 없다」는 범위를 안 밝힌 과한 단정이다.**
  `[조합]` 144개(안흔함~제한됨) 범위에만 해당한다. 정정은 `ORIGINAL_FUSION_RECIPES.md`에 있다
