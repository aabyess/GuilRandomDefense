## 0. 무엇이 빠져 있나

원작 플레이어 유닛 314 중 **40기의 무기 종류가 `ua1w = msplash`(투사체 광역)** 이다. 평타가 주 대상 주변에도 피해를 준다.

별개로 클리브 능력(ACce) 7개가 로스터 대응 유닛에 있다(ETERNAL_FILL_LIST §9).
근거는 전부 `war3map_new.w3u`·`.w3a`·`.j` 직접 디코드. 스톡 slk는 저장소·맵에 없다.

## 3. 우리 쪽 설계

**데이터** — `UnitData` 맨 뒤에:
- `attackSplashRadius`(원작 단위, 전체 피해 반경 = ua1f) · `attackSplashHalfRadius` · `attackSplashHalfFactor`(카이도용, 기본 0 = 없음)
- `attackCleaveFactor` · `attackCleaveRadius`(ACce nca1·aare)
- 값은 `Tools/sync_attack_splash_from_w3u.py`(새 도구)가 대응표·w3u·w3a에서. 세계 거리는 `÷ WorldScale.Value`(스킬 반경 `SkillLevel.WorldRange`와 같은 환산).

**코드** — `UnitAttacker.Update`의 평타 한 자리:
1. 주 대상에게 지금처럼 한 번(`TakeDamage`, 치명·온힛 스킬·게이지는 지금 그대로 주 대상에만).
2. 반경 > 0이면 `EnemyDummy.Active`에서 주 대상 위치 기준 반경 안의 **다른** 적에게 같은 `AttackDamage`로 `TakeDamage`(주 대상은 건너뜀 → 이중 타격 없음).
   대상마다 제 방어·상성이 곱해진다(TakeDamage가 이미 그렇게 함). 같은 레인 적만(`lane` 일치 — 남의 레인 적을 때리지 않게).
3. 클리브는 같은 자리에서 `AttackDamage × 비율`. 방어 무시 여부는 미확정이라 **기본은 방어 적용**으로 두고 주석.
4. 계측: SkillTelemetry 채널 「평타광역」을 따로(평타와 섞으면 기존 비교가 깨진다).
5. 방깎 특성(`ApplyArmorShred`)·치명은 주 대상만.

**멀티** — 진짜 유닛은 호스트에만 있어 피해 계산은 호스트 한 곳. 클라 표시는 적 체력 복제로 따라온다. 광역 타격 이펙트를 넣으면 RPC 하나(SkillPrefabVfx 재사용 가능).

**성능** — 평타마다 `EnemyDummy.Active` 전체 훑기. 레인에 적 35~70, 광역 유닛 수 기, 주기 0.5~1초 → 초당 수백 번 거리 비교. 문제 없음.

**시뮬·탐침** — `Tools/`의 밸런스 시뮬은 「dps로 총 HP를 녹이는 연속 풀」이라 동시에 몇 마리가 맞는지를 모른다 → 이 축은 **시뮬 밖**(문서에 명시).
실측은 판으로: 표적을 원작 간격으로 세운 줄에 유닛 하나를 두고 「평타」·「평타광역」 채널 피해와 맞은 수를 센다(AuraProbe 방식 + 줄 세우기).

## 4. 영향 크기 어림

- 적 간격: 원작 스폰 0.65초 × 적 이속 300(1라운드) = 195(원작 단위). 빠른 라운드는 더 벌어지고, 이감·스턴·모퉁이에선 뭉친다.
- 줄지어 걷는 적 기준, 반경 R 안의 적 수 ≈ 1 + 2×⌊R ÷ 195⌋:
  R 200~385 → **3마리**(주 대상 + 앞뒤 하나씩) · R 400~580 → **5마리** · R 600 → 7마리.
- 즉 그 29행 유닛의 **평타 피해가 걷는 줄에서 3~5배**, 뭉친 자리(U자 모퉁이·스턴·이감 오라 안)에선 그 이상. 레인에 35마리가 반경 300 안에 다 뭉치는 극단이면 35배지만, 경로 길이상 현실적 상한은 10배 안팎으로 본다(실측 필요).
- 평타 비중이 큰 등급(희귀·전설)일수록 체감이 크고, 스킬 비중이 80~99%인 영원·초월은 작다(오늘 탐침: 영원 넷의 스킬 비중 81~100%).
- 온힛 스킬·게이지는 안 늘어난다(주 대상만) → 스킬 발동 빈도·마나 간격 측정치는 그대로.

## 5. 넣는 순서 제안

1. msplash 중 「ua1f만 있는」 행(카이도·카벤딧슈 제외) — 데이터·도구·코드·탐침. 값이 갈리는 로스터(황준석·최영민)는 결정 뒤.
2. 클리브 7(방어 적용으로, 미확정 주석).
3. 카이도 절반 반경·카벤딧슈는 스톡값 근거가 나올 때.
4. 밸런스 재측정(R1~R20 승률이 움직일 것 — 특히 희귀함 5·전설적인 4).

## 6. PM 결정이 필요한 것

- (가) 한 로스터에 광역 값이 여럿일 때의 규칙(최댓값 / 평타 스탯 출처 따라가기).
- (나) 절반·1/4 반경 스톡값을 0으로 볼지(카이도의 절반 계수 포함).
- (다) 클리브 광역 피해의 방어 적용 여부(가설: 원작은 방어 무시).
- (라) 같은 레인 제한을 둘지(원작엔 레인 구분이 없지만 섬이 떨어져 있어 실질 차이 없음).
