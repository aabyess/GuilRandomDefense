# 멀티 재접속 설계 (제안 — 코드 대기, PM 검토용)

> 작성: 구현담당2, 2026-09-26 · 브랜치 `mp`. PM 지시: 코드 전에 제안 먼저.

## 1. 지금 동작 (실측)

| 상황 | 지금 |
|---|---|
| 판 도중 클라가 **끊김**(망·잠자기·앱 종료) | 호스트 `PlayerLeft` → 원작 `Gone1~4` 그대로: 그 사람 유닛·위습·레인 적 제거, 사망 표식, R01G +1. **되돌릴 수 없음** |
| 판 도중 클라가 **[나가기]** | 같음(끊김과 구별 안 함) |
| 끊긴 사람이 다시 들어오려 함 | 막힘 — 판 시작 때 세션을 닫고(`IsOpen=false`), 시작 뒤 입장은 `NetSession`이 끊는다 |
| 호스트가 끊김 | 판 끝(호스트 이전 없음) — 친구들은 첫 화면으로 「호스트와 연결이 끊겼습니다」 |

원작(워크3)에도 재접속은 없다 — 한 번 나가면 끝이다. **재접속은 원작에 없는 우리 추가 기능**이라 「전부 원작대로」 원칙과 부딪힌다 → PM·사장님 결정이 먼저 필요하다(§5).

## 2. 왜 필요할 수 있나

친구 베타는 집마다 망이 다르다. 오늘 한 기계 안에서도 판 중 Photon 끊김이 두 번 났다(`NetDiagnostics`). 와이파이가 1초 끊기거나 노트북 덮개를 닫으면 **그 사람 유닛이 전부 사라진다**(원작 Gone). 원작에선 「나감 = 본인 선택」에 가까웠지만, 우리 쪽 끊김은 대부분 본인 선택이 아니다.

## 3. 제안 — 「끊김 유예」 (B안, 권장)

**[나가기]는 원작대로 즉시 Gone. 망 끊김만 N초(제안 60초) 동안 자리를 붙잡아 두고, 그 안에 같은 사람이 돌아오면 그대로 이어 한다.**

1. **같은 사람 알아보기**: 설치마다 한 번 만드는 식별값(GUID, PlayerPrefs)을 `StartGameArgs.ConnectionToken`으로 보낸다.
   호스트는 `PlayerJoined`에서 `runner.GetPlayerConnectionToken(player)`로 읽는다(둘 다 SDK에 있음, 확인함). 닉네임은 겹칠 수 있어 쓰지 않는다.
2. **나가기와 끊김 구별**: [나가기]를 누르면 클라가 먼저 `RPC_LeavingOnPurpose`를 보내고 끊는다(방장의 「방 닫기 알림」과 같은 방식) → 호스트는 바로 Gone.
   예고 없이 `PlayerLeft`가 오면 끊김으로 본다.
3. **유예 동안(호스트)**: 그 슬롯을 「끊김」으로 표시하고(팀판 「플레이어 2 | 연결 끊김 57초」), **유닛·레인·보상은 그대로 둔다**
   — 유닛은 알아서 싸우고(호스트가 돌림), 적도 계속 나온다(원작 규칙상 레인은 주인이 있어야 막으니, 오래 비면 그 레인이 쌓이는 건 감수).
   세션은 이 동안만 다시 연다(`IsOpen=true`, 목록엔 안 보임). 모르는 식별값으로 들어오면 끊는다.
4. **돌아오면**: 같은 식별값 → 같은 슬롯의 새 NetPlayer를 그 사람 입력권한으로 스폰. Fusion이 현재 씬과 모든 거울을 늦게 들어온 사람에게 보내 준다
   (지금 구조가 원래 「스폰될 때 겉모습을 세움」이라 그대로 된다). 세이브 제출값은 호스트가 이미 들고 있다.
5. **유예가 지나면**: 그때 원작 Gone(유닛·위습·레인 적 제거, 사망, R01G +1, 「〇〇님이 게임에서 나가셨습니다」).
6. **클라 화면**: 끊기면 첫 화면에 「호스트와 연결이 끊겼습니다」 + **[다시 참가]**(마지막 방 코드 기억). 누르면 같은 방으로 다시 붙는다.

### 늦게 들어온 사람 쪽에서 손봐야 하는 것(지금은 「판 시작 전에 다 있음」을 전제로 짰다)
| 무엇 | 문제 | 처리 |
|---|---|---|
| `PlayerContext.occupied` | 씬이 먼저 뜨고 NetPlayer가 나중에 오면 Awake 때 좌석이 비어 보인다 | NetPlayer.Spawned에서 게임 씬이면 `SetOccupied` 다시 |
| 난이도 | DifficultyManager.Awake가 MatchConfig.Difficulty를 못 볼 수 있다 | NetGameState.Spawned에서 늦게 `ApplyMode` |
| 로컬 ID·카메라 | LocalPlayerId가 씬 로드 뒤에 정해질 수 있다 | 정해진 순간 카메라 `FocusOnLocalLane` 다시 |
| 이미 쌓인 알림 | 끊긴 동안의 알림은 못 받는다 | 감수(표시용) |

## 4. 다른 안

- **A. 재접속 없음(원작 그대로 = 지금)**: 가장 단순. 끊기면 그 사람은 끝. 친구 베타에서 불만이 나올 수 있다.
- **C. 끊겨도 자리 영구 유지**: 레인이 무주공산으로 쌓여 남은 사람이 진다(원작 패배 규칙) — 오히려 나쁘다. ✗
- **호스트 끊김 대비(호스트 이전)**: Fusion에 기능은 있지만 우리 구조(호스트가 게임 전체를 들고 있음)에선 상태를 새 호스트로 옮기는 일이 매우 크다. 이번 범위 밖. ✗

## 5. 결정이 필요한 것

1. **원작에 없는 재접속을 넣을지**(B안) — 아니면 A안(지금 그대로).
2. 넣는다면 **유예 시간**(제안 60초).
3. 유예 동안 그 레인 적을 **계속 보낼지**(제안: 계속 — 원작 규칙은 그대로 두고 자리만 붙잡는다) 아니면 **멈출지**.
4. [나가기]는 원작대로 **즉시 Gone** — 확인 창(「나가면 유닛이 모두 사라집니다」)을 띄울지.

## 6. 작업량(B안)

NetSession(유예 표·식별값 대조·세션 다시 열기) · NetLauncher(식별값 보내기·[다시 참가]·나가기 예고) · NetPlayer(늦은 입장 보정) · 팀판 「연결 끊김 N초」 표시(GameHud `// MP:` 한 곳).
검증: 빌드 두 개로 클라 강제 종료 → 30초 뒤 다시 참가 → 같은 슬롯·유닛 유지 / 70초 뒤 → Gone 확인.

## 7. 결정 (PM, 2026-09-26) — 코드는 v1.1.0 빌드가 나간 뒤

1. **B안(끊김 유예)** — 원작에 재접속은 없지만 이건 게임 규칙이 아니라 망 안정성 문제다. 의도한 [나가기]는 원작대로 즉시 Gone, 망 끊김만 봐준다(판 10번 중 2번 끊김 실측).
2. 유예 **60초**.
3. 유예 동안에도 그 레인에 **적을 계속** 보낸다(원작 규칙 유지). 데스카운트가 쌓이는 것도 그대로.
4. [나가기] 확인 창: **「나가면 유닛이 모두 사라집니다. 나갈까요?」**
- 방장 끊김 = 판 끝은 범위 밖. 모두에게 이유를 보여 주는지만 확인 — 이미 된다(1-a' 검증: 방장 [나가기] → 「호스트가 방을 닫았습니다」, 끊김 → 「호스트와 연결이 끊겼습니다」, 둘 다 첫 화면으로).

## 8. 구현·검증 (2026-09-26, 구현담당2)

**코드**
- `NetSession`: 접속 식별값(`GetPlayerConnectionToken`)을 입장 때 받아 둔다. 판 도중 예고 없는 퇴장이면 NetPlayer를 거두지 않고 60초 유예하고, 세션을 다시 연다(`IsOpen`, 목록엔 안 보임). 같은 식별값이 들어오면 `AssignInputAuthority`로 그 NetPlayer를 넘긴다. 만료되면 `NetDeparture.Apply`(원작 Gone)를 부르고 거둔다. 식별값이 없거나 이미 죽은 사람이면 바로 Gone.
- `NetPlayer`:
  - `[Networked] GraceLeft`(팀판 표시).
  - `RPC_LeavingOnPurpose`.
  - 늦은 입장 보정: 좌석 `SetOccupied`, 카메라 `FocusOnLocalLane`, 이름·세이브 재제출 안 함.
- `NetLauncher`:
  - `ConnectionToken`(설치마다 GUID, PlayerPrefs).
  - GameAuthority.Provider를 StartGame **전에** 꽂음(재접속 때 씬이 먼저 떠도 클라가 호스트 일을 안 하게).
  - [나가기]는 먼저 예고 RPC를 보낸다.
  - 판 도중 끊기면 방 코드를 기억하고 [다시 참가]를 띄운다.
- `NetLobbyUi`:
  - 첫 화면에 [다시 참가].
  - 게임 중 「메뉴」 버튼(GameHud에 원작 배치만 있던 것)에 네트 판에서만 확인 창을 붙였다. 친구는 「나가면 유닛이 모두 사라집니다. 나갈까요?」, 방장은 「방장이 나가면 모두의 판이 끝납니다. 나갈까요?」.
- `// MP:` 수정:
  - `GameHud` 팀판 「연결 끊김 N초」.
  - `DifficultyManager.ApplyReplicatedMode`(늦은 입장 난이도, `NetGameState.Render`가 부름).
- 앱을 그냥 닫는 것(Cmd+Q)은 끊김으로 본다. 유예 안에 다시 켜서 같은 방 코드로 참가하면 이어진다. [나가기]만 즉시 Gone이다.
- 테스트 옵션: `-mpToken`, `-mpDropAt`(예고 없이 끊기), `-mpRejoinAfter`, `-mpTestMenu`.

**검증** (GRD-dev, 한 기계에서 창 여러 개, 식별값은 `-mpToken`으로 갈라서)
1. **유예 안에 다시 참가**:
   - 친구가 판 중 끊김 → 호스트 「끊김 유예 시작: 슬롯 1 60초」, 팀판 「플레이어 2 | 연결 끊김 51초」.
   - 친구 첫 화면에 [다시 참가]와 「60초 안에 [다시 참가]를 누르면 이어서 할 수 있습니다」.
   - 12초 뒤 다시 참가 → 호스트 「재접속: 슬롯 1 제자리로(남은 유예 47초)」.
   - 친구는 게임 씬에 `LocalPlayerId=1` · 좌석 {0,1} · 난이도 보통으로 들어온다. 3라운드 자기 레인, 골드 52가 이어졌다.
   - 친구 유닛 5기(id 1050~1054)가 끊기기 전·후 그대로다. 유예 동안에도 그 레인에 적이 계속 나왔다.
2. **60초 만료**: 끊긴 친구A가 돌아오지 않음 → 60초 뒤 「끊김 유예 끝 → 퇴장 정리: 유닛 5 · 위습 4 · 레인 적 70 제거, 사망, 스토리 체력 감소 레벨 2」.
3. **[나가기] 즉시**:
   - 친구B가 게임 중 「메뉴」 → 확인 창(PM 문구) → [나가기].
   - 호스트는 유예 없이 즉시 「퇴장 정리: 유닛 5 · 위습 2 · 레인 적 37 제거」, 「퇴장: … ([나가기])」.
- 예외: 모든 창 0.

**남은 것 / 알려진 점**
- 재접속한 친구 화면에서 이미 Gone으로 나간 다른 사람 자리는 「사망」이 아니라 「비어있음」으로 보인다. 그 사람의 NetPlayer가 없어서 좌석을 모른다. 표시만의 차이다.
- 방장 끊김 = 판 끝(범위 밖, §7).
