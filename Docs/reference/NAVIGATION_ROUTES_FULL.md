# "항법"(진행 루트) 전수 — 5택1, 원문 확정

조사: 리서치담당 / 2026-09-06
요청: PM — 「"도움소 잠금" 하나로 나머지를 추측하지 말고 항법 전체를 전수하라」

## 결론 한 줄

**항법은 4개가 아니라 5택1이다.** 전부 `Trig_onedill_Tech_Actions` 안에
있고, **한 유닛(`H0C4`, 4개 인스턴스=4자리)의 "영웅 스킬 배우기" 이벤트로
구현된 진짜 5지선다 특성 선택**이다 — 한 번 배우면 그 능력을 즉시
add→remove해서 재선택을 막는, WC3의 표준 "일회성 스킬트리 분기점" 패턴이다.

## ① "항법" 문자열 전수

`war3map.j` 전체에서 "항법"이 들어간 문자열은 정확히 6가지, 전부
`Trig_onedill_Tech_Actions`(선택 순간의 안내 문구 5개) 또는 그 결과를 소비하는
다른 트리거들("항법효과:" 접두, 4곳)에서만 나온다 — 흩어진 별도 시스템이
아니라 **이 트리거 하나가 유일한 진입점**이다.

## ② 5개 선택지 — 이름·포기하는 것·얻는 것

`InitTrig_onedill_Tech`가 `EVENT_UNIT_HERO_SKILL`(스킬 배우기)을 4개 자리
유닛(`H0C4`)에 등록하고, `GetLearnedSkillBJ()`로 어느 버튼을 눌렀는지 갈라
5개 분기 중 하나만 실행한다:

| 선택지 | 배우는 능력 | 효과(원문 그대로) |
|---|---|---|
| **패왕의길** | `A17C` | `R02E` 연구완료(다른 곳에서 안 읽힘, 표시용으로 보임) + **`udg_Damage_level_Fixed[플레이어]` +2**(전역 피해 스케일 변수로 추정, 별도 확인 필요) + `udg_Tech_Onedill_int`=1(치장 플래그, 특정 특성 스킬의 "chest 이펙트" 표시 여부에만 쓰임, 이전 조사 확인) |
| **연합세력 항법** | `A0Z6` | **`udg_Tech_union[플레이어]`=true**만 켠다 — 이 트리거 안엔 다른 효과 없음, 값을 읽는 곳은 별도 확인 필요 |
| **도박광** | `A0ZY` | **`udg_Dobak_Tech_int[플레이어]`=1** — 이미 다른세계 도박(`Trig_Unit_Gemble_4`) 조사에서 확인한 그 변수다. 실패 시 위로 아이템(럭키토큰) 수량 공식이 `1+Dobak_Tech_int`라 **이 항법을 고르면 도박 실패 시 위로품이 1개→2개로 는다.** |
| **도움소 강화** | `A17D` | `R037` 연구완료 + **`udg_Manso[플레이어]`(도움소 유닛)의 `A0ID`(해루석)·`AOeq`(대지진)·`A0JR`(버스터콜) 능력을 전부 레벨 2로 만든다.** 🔴 **우리가 이 세 스킬을 레벨1 값만 구현했다면, 이 항법을 고른 플레이어는 원작에서 레벨2 값을 쓴다 — 레벨2 수치를 아직 조사 안 했으면 밀도/수치가 그만큼 결측이다.** |
| **도움소 잠금** | `A17E` | `R036` 연구완료 + **`udg_Tech_No_support[플레이어]`=true**(이미 확인한 그 플래그 — 아이템 도박이 축소-13종 풀로 바뀐다) |

**포기-보상 쌍이 명확한 건 "도움소 강화"↔"도움소 잠금" 하나뿐이다** —
강화는 도움소 스킬을 레벨2로 올리고, 잠금은 도움소를 아예 안 쓰는 대신
아이템 도박 품질을 올린다(정확히는 "잠금"이 도움소를 물리적으로 막는지,
아니면 단지 그 항법을 안 골랐다는 표시일 뿐인지는 `udg_Tech_No_support`가
다른 곳(도움소 사용 자체)에서도 읽히는지 확인이 더 필요하다, 이번엔 아이템
도박 풀 갈림에서만 확인했다). **"패왕의길"·"연합세력"·"도박광" 셋은
포기하는 대상이 뚜렷하지 않다** — 원작이 "5택1 중 하나만 고른다"는 구조
자체로 나머지 넷을 포기하는 형태라, 개별 페어링(A를 포기하면 B를 얻는다
식)이 아니라 **"5갈래 중 하나만 영구 선택"**이 맞는 설명으로 보인다.

## ③ 언제·어디서, 몇 번

**영웅 스킬(스킬트리 버튼) 학습 이벤트**로 구현돼 있다 — 특정 게임 시점(아마
게임 시작 시 또는 특정 라운드에 열리는 UI)에 5개 버튼 중 하나를 "배우면"
확정되고, `UnitAddAbilityBJ`→`UnitRemoveAbilityBJ`로 그 능력 자체를 바로
회수해 **재선택을 원천 차단한다** — WC3의 표준 "1회성 스킬트리 분기"
패턴이다. **한 번 고르면 못 바꾼다.** 정확히 어느 시점(라운드/UI)에 이
선택창이 뜨는지는 `H0C4` 유닛이 언제 생성/배치되는지를 봐야 하는데 이번엔
안 팠다 — 필요하면 이어서 확인 가능.

## ④ 🔴 `ACQUISITION_RESEARCH.md`의 "특성포인트 20개+변화 1회" — **원문에 없다, 확인 안 됨**

`Trig_onedill_Tech_Actions`(항법 선택의 유일한 진입점) 원문 어디에도
**"특성포인트"·"변화"를 지급하는 코드가 없다.** `war3map.j` 전체에서
"특성포인트" 텍스트를 검색해도 "항법"과 얽힌 문맥이 하나도 안 나온다.
**이 claim은 이번 조사로 확인 안 됐다** — `ACQUISITION_RESEARCH.md`는 이미
프로젝트 규칙("조사 문서를 원문 대조 없이 지시로 옮기지 말 것")이 저신뢰로
분류해둔 문서이고, 이번이 그 사례로 보인다. **"항법 보상=특성포인트20개"는
원작에 없거나, 이 트리거가 아닌 완전히 다른 시스템과 혼동됐을 가능성이
높다** — 폐기를 권한다(다른 근거가 나오기 전까지).

## ⑤ 각 선택지가 켜는 플래그와 읽히는 곳

| 플래그 | 켜는 선택지 | 읽히는 곳(확인된 것만) |
|---|---|---|
| `udg_Damage_level_Fixed[]` +2 | 패왕의길(다른 3개 발생원도 있음, 아래 참고) | **확정, 🔴 방향 정정 — [[damage-level-fixed-round-unit-resolved]](DAMAGE_LEVEL_FIXED_ROUND_UNIT_RESOLVED.md).** "전역 피해 스케일"이 아니라 **적 취약도 축**이다. `Round_Unit`은 특수유닛이 아니라 **매 라운드 4명 각자 라인에 스폰되는 그 라운드의 일반 몬스터 자체**(`Trig_Round_10ver_Actions`가 라운드마다 `udg_Round_UnitType[udg_Level]`로 스폰, "10ver"는 라운드10과 무관 — 트리거 버전번호). `A11S`(=`percentDamageTaken`, 원작공식 `0.20+0.05×레벨`) 레벨을 `Damage_level_Fixed+14`로 설정 — **레벨이 높을수록 그 라인의 적이 스킬 피해를 더 받는다(플레이어 유리)**. 패왕의길만 골라도 레벨14(일반 적 계수0.90)→16(보스급 계수1.00)로 그 라인 전체 적이 보스급 취약도를 갖는다. `Hidden_Aokiji`(+2)·`Eternal_Lucci`(+2)·`IM_dragon`(+4) 세 히든 이벤트도 같은 변수를 누적시킴(항법 없이도 최대+8, 히든 이벤트 달성조건 자체는 `[미확인]`, 다음 조사) |
| `udg_Tech_Onedill_int[]`=1 | 패왕의길 | 각 특성 스킬의 "chest 특수효과 한 번만 보여주기" 부가 연출 게이트(이전 조사 확인, 배타/제한과 무관) |
| `udg_Tech_union[]`=true | 연합세력 항법 | **확정** — `Trig_UnitJohabCounter_Actions`(유닛 조합/카운터 이벤트, 아마 로스터에 유닛이 들어올 때마다)에서 `if Tech_union==true then if GetUnitPointValue(트리거유닛)>100 then CreateNUnitsAtLoc(1,'e0IX',...,udg_Wisp_Regen,...)` — **포인트값 100 초과(등급 특수함 이상) 유닛이 카운트될 때마다 랜덤위습(`e0IX`, 흔한 소모성 위습) 1개를 `udg_Wisp_Regen` 위치에 추가 지급.** 항법 5택1 중 유일하게 "경제(위습 수급) 버프" 계열이다 |
| `udg_Dobak_Tech_int[]`=1 | 도박광 | `Trig_Unit_Gemble_4`(다른세계 도박) 실패 시 럭키토큰 수량 `1+Dobak_Tech_int` — 확정 |
| `udg_Tech_No_support[]`=true | 도움소 잠금 | `Trig_item_Gemble_Func006C`(아이템 도박 전체/축소 풀 갈림) — 확정. 도움소 자체 사용을 막는지는 `[미확인]` |
| `A0ID`/`AOeq`/`A0JR` 레벨→2 | 도움소 강화 | 해당 능력을 직접 레벨업(레벨2 수치 자체를 우리가 조사했는지는 별도 확인 필요) |
