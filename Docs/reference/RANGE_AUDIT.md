### ⚠️ 2채널 122종에 대해 PM 확인이 필요하다
이 표는 **반경을 준 적이 없는데 122종이 이미 적용됐다.** 그러면 그 122종의 범위는 **무엇으로 채웠나?**
**우리 런타임이 `range 0`을 「무제한」으로 읽으므로, 기본값 0으로 들어갔다면 그 122종이 맵 전체를 때린다.**
**이건 우리 표의 문제가 아니라 적용 쪽 문제라 내가 확인할 수 없다 — 구현담당1에게 확인이 필요하다.**

## 정정 93건의 내역

| 유형 | 건수 | 내용 |
|---|---|---|
| 지수표기 → 십진수 | **56** | `2e+06` → `2000000` (앞 커밋에서 이미 고침, 목록에 포함) |
| 계열-지역 반경 + RRD별 단일/범위 재판정 | **23** | `ORIGINAL_GATED_SKILLS_14` |
| 그룹 반경을 전역이 아니라 계열 안에서 해석 | **14** | `ORIGINAL_UNLISTED_SKILL_EFFECTS`(로빈 525·350 등) |

### `GATED_SKILLS_14` 23행이 왜 틀렸나 — **값이 아니라 「단일/범위」가 틀렸다**

옛 표는 **한 트리거의 반경 하나를 그 트리거의 모든 RRD에 똑같이** 붙였다. 그런데 실제로는 **같은 트리거 안에서도
RRD마다 단일 대상과 범위가 섞인다**:

```
Dragon_Skill_1_T  옛: 475.00 (3행 모두)
                  새: #1 범위=475.00 · #2 단일=0 · #3 단일=0
Sabo_Skill_4      옛: 415.00 (4행 모두)
                  새: #1 범위=415.00 · #2·#3·#4 단일=0
```

→ **반경 숫자 자체는 맞았고, 단일 대상 RRD에까지 범위를 씌운 것이 오류다.**
**범위가 아닌 것을 범위로 넣으면 맞는 적 수가 늘어 밸런스가 조용히 세진다.**
새 값은 **`#순번:단일/범위=값`** 꼴로 RRD별로 적었다.

  셋 중 하나만 빠져도 조용히 틀린다.

## 🔴 `gate` 컬럼 소급 검증 — **같은 버그가 여기에도 있었다. 13행 정정**

PM 예상이 맞았다. `gate`를 **「스킬트리거 이름」만으로** 끌어왔는데, **한 스킬트리거를 여러 유닛이 공유**한다:

- **18종의 스킬트리거를 2명 이상이 공유**하고,
- 그중 **9종은 부르는 유닛에 따라 게이트가 다르다.**

| 스킬트리거 | 유닛A | 유닛B |
|---|---|---|
| `DP_Skill_3` | `H09D` **1/6** | `H09E` 1/8 |
| `DP_Skill_2` | `H09D` **1/9** | `H09E` 1/10 |
| `Snake_2` | `H0B2` **1/15** | `H0B3` 1/12 |
| `Snake_3_Kingkobra` | `H0B2` **마나 85** | `H0B3` 마나 75 |
| `Sandi_skill_1` | `H09G` **1/6** | `H09H` 게이트 없음 |
| `Yamato_Dash` | `H0BD` **1/3** | `H0BE` 게이트 없음 |
| `Sinobu_Skill_3` | `h084` **체력50 AND 1/8** | `h086` 1/10 |
| `Kaido_Skill_1_8` | `h07M` **게이트 없음** | `h0AD` 체력100 AND 절대쿨11s AND 1/7 |
| `Kaido_Dragon_buster` | `h07M` **게이트 없음** | `h0AD` 체력100 |

→ **키를 `(유닛ID, 스킬트리거)`로 바꿔 13행을 정정했다.** 정정 목록에 함께 넣었다(`RANGE_CORRECTIONS.csv` **총 106행**).

> **이것으로 같은 뿌리의 사고가 셋이 됐다**: 그룹 변수 반경(14행) · 게이트(13행) · 그리고 앞서의 유닛ID/능력ID 매핑.
> **원작은 「이름」을 재사용한다 — 트리거도, 그룹 변수도, 능력도.**
> **무엇을 끌어오든 키에 「누구의 것인지」를 반드시 포함해야 한다.**
