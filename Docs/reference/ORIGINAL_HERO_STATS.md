# 원작 영웅 스탯 (STR/AGI/INT) — 전면 조사

조사: 리서치담당 / 2026-09-06
요청: PM ③ + ㉠~㉣

## 0. 한 줄 요약

원작에서 **시작 스탯은 전부 0**, 성장은 **주스탯 +0.85 / 나머지 +0.21 per 레벨**, **최대 레벨 24**,
경험치는 **적 1기 죽을 때마다 그 라인 주인의 영웅 전원에게 +1**, 스탯이 피해에 들어가는 길은
**주스탯 × 800 (엔진)** 하나뿐이다. 스킬 계수 2,000~50,000의 편차는 **스탯 크기로 설명되지 않는다** —
모든 영웅의 스탯 곡선이 동일하기 때문이다. 계수는 스킬별 설계값이다.

## ㉠ `StrAttackBonus=800.0` 검산

### 원작이 개조한 게임플레이 상수 (스톡 TFT 대조)

스톡값 출처: [TFT vs RoC explained via a MiscGame diff — 3ICE.HU](https://forum.3ice.hu/viewtopic.php?t=979)
`StrAttackBonus`가 「힘」이 아니라 **주스탯**에 걸린다는 근거: 스톡값이 1.0이고,
[Attributes — Wowpedia](https://wowpedia.fandom.com/wiki/Attributes) / [Hero (Warcraft III) — Wowpedia](https://wowpedia.fandom.com/wiki/Hero_(Warcraft_III))가
「주 능력치는 기본 공격력을 1점당 1 올린다」로 기술한다. 두 값이 정확히 일치한다.

### 스탯이 실제로 하는 일 — 이 맵에서는 셋뿐이다

| 스탯 | 효과 | 경로 |
|---|---|---|
| **주스탯**(STR/AGI/INT 중 `upra`) | **공격력 +800/점** | 엔진 `StrAttackBonus` |
| **AGI** | 공격속도 **+1%/점** | 엔진 `AgiAttackSpeedBonus` |
| **INT** | 마나재생 +0.08/점, 그리고 `A0WP` 체력재생 오라 **+5%/점** | 엔진 + `A0WP` |

`A0WP`(`ACnr` 파생, **자기 대상 range 1**)는 **체력재생 오라**다. 피해 오라가 아니다.
- 근거: 같은 `ACnr`을 base로 쓰는 유일한 다른 능력 `A0VS`의 제작자 이름이 「**라이프 리제너레이션 오라1**」이다. 맵 안에서 확정된다.
- 값: `Oar1` = 레벨1 0.00 → 레벨31 1.50, **정확히 레벨당 +0.05**. 레벨 = INT 값.
- **38기 전원이 보유**(주스탯 무관). 갱신 시점: 레벨업 트리거(`gg_trg_heroLevel...2`, `A0WP<21`일 때만), 조합, 도움소 INT 구매.

STR이 체력을 안 주고(`StrHitPointBonus=0`) AGI가 방어력을 안 주므로(`AgiDefenseBonus=0`),
**방어 쪽으로 가는 스탯 효과는 이 맵에 하나도 없다.**

### 🔴 `A11V`「영웅-힘 공격력증가」는 원작에서 작동하지 않는다

`AItg`(아이템 공격력 보너스) 파생, `alev=36`, `Iatt` = 레벨1 0 → 레벨35 **20,400**(정확히 **레벨당 +600**),
레벨36만 30,000으로 튄다. 도움소·조합·레벨업 트리거가 모두 `SetUnitAbilityLevelSwapped('A11V', 유닛, STR값)`을 호출한다.

**그런데 `A11V`를 실제로 붙이는 곳이 원작 어디에도 없다:**
- 어떤 유닛의 `uabi`에도 없음 (0기)
- 어떤 유닛의 `uhab`(영웅 능력)에도 없음 (0기)
- 어떤 아이템(`war3map.w3t` 38개)도 주지 않음
- `war3map.j`의 `A11V` 등장 22곳이 **전부 `Get`/`Set`UnitAbilityLevel**이고 `UnitAddAbility`가 한 건도 없음

`SetUnitAbilityLevel`은 능력이 없으면 아무 일도 하지 않는다. → **STR 1점당 +600 공격력 경로는 원작에서 죽어 있다.**
제작자가 만들어두고 붙이지 않은 것으로 보인다. **우리도 넣으면 안 된다.**
(레벨36의 30,000도 도달 불가다. 모든 호출부가 `A11V 레벨 < 35`를 조건으로 걸어 35에서 멈춘다.)

**모든 `hrif` 기반 영웅 36기의 스탯 곡선이 완전히 동일하다**(시작 0/0/0, 주스탯 +0.85, 나머지 +0.21).
따라서 같은 레벨에서 스탯 값은 영웅마다 같고, **계수 2,000~50,000의 25배 편차는 순수한 스킬별 설계값**이다.
스탯 크기 차이가 아니다. → PM의 가설(「스탯 크기가 편차를 설명하나?」)은 **아니다**로 닫힌다.

단, **주스탯이냐 부스탯이냐**는 4배 차이를 만든다(0.85 vs 0.21). 원작 제작자는 대체로
자기 주스탯을 읽게 배선해뒀다(티치 STR형→STR 읽음, 초록소 INT형→INT 읽음).

### 레벨별 스탯과 공격력 기여 (hrif 기반 36기 공통, 도움소 구매 0회 기준)

| 레벨 | 주스탯 | 부스탯 | 주스탯×800 = 공격력 | AGI형이면 공속 |
|---|---|---|---|---|
| 1 | 0 | 0 | +0 | +0% |
| 5 | 3 | 0 | +2,400 | +3% |
| 10 | 7 | 1 | +5,600 | +7% |
| 15 | 11 | 2 | +8,800 | +11% |
| 20 | 16 | 3 | +12,800 | +16% |
| **24 (최대)** | **19** | **4** | **+15,200** | **+19%** |

비교: 초월함 영웅의 기본 공격력(`ua1b`)은 20만 안팎(예 `H08X` 후지토라 200,000).
→ **최대 레벨의 주스탯 기여는 기본 공격력의 약 7.6%.** 스탯은 이 맵에서 **주역이 아니다.**

예외 — `H05N` 타시기만 시작 스탯이 있다(아래 ㉣):

| 레벨 | STR | AGI | INT | STR×2,500 (타시기 스킬 계수) |
|---|---|---|---|---|
| 1 | 10 | 11 | 1 | 25,000 |
| 10 | 13 | 26 | 4 | 32,500 |
| 24 | 19 | 50 | 10 | **47,500** |

> 📌 **우리 문서 정정**: `ORIGINAL_UNLISTED_SKILL_EFFECTS.csv`의 타시기 2행 비고가
> 「STR항 = 25,000(레벨1) ~ 약 32,500(레벨10)」으로 적혀 있는데, **최대 레벨은 10이 아니라 24**다.
> 상한은 32,500이 아니라 **47,500**이다.

## ㉡ 경험치 → 레벨 문턱

`war3mapMisc.txt`:
```
MaxHeroLevel=24
NeedHeroXP=33,75,116,152
NeedHeroXPFormulaA=1.03
NeedHeroXPFormulaB=15.0
(NeedHeroXPFormulaC 없음 → 기본 0)
```

**표는 레벨 2·3·4·5의 「누적」 경험치**이고, 표를 넘어가면 재귀식으로 잇는다:

```
필요(N) = 필요(N-1) × A + B × N + C        (A=1.03, B=15.0, C=0)
```

출처: [How does "Need Hero XP Table" work? — The Hive Workshop](https://www.hiveworkshop.com/threads/how-does-need-hero-xp-table-work.254089/)
**검증**: 스톡값(표 200,500,900,1400 / A=1, B=100, C=0)을 이 식에 넣으면
`500 = 200×1 + 100×3`, `900 = 500 + 100×4`, `1400 = 900 + 100×5` — 정확히 재현된다.

라운드당 35마리면 **최대 레벨까지 약 160라운드분**. 한 판에 만렙은 못 찍는다.
레벨 2~5 구간만 유독 싸다(33/42/41/36) — 표로 직접 덮어쓴 구간이라 공식과 무관하다.

### 🔴 특성 하나가 이 곡선을 통째로 건너뛴다

`Trig_T_Ability_hero`의 `H05N`(타시기) 분기:
```
call AddHeroXPSwapped(5000, GetTriggerUnit(), true)
call ModifyHeroStat(bj_HEROSTAT_STR/AGI/INT, GetTriggerUnit(), ADD, 3)   ← 각 +3
   조건: 특성 포인트(PLAYER_STATE_RESOURCE_FOOD_USED) >= 1, 소모 1
```
**5,000 경험치 = 레벨 23**이다. 그 외 `AddHeroXPSwapped` 호출: 600×2, 325, 300×3, 250 (모두 `GetEnumUnit()` 대상).

## ㉢ 그 경험치는 누구에게 가는가 — **킬한 유닛이 아니다**

원작에 `AddHeroXP` 호출은 **단 하나**다(`war3map.j:14734`):

```jass
function Trig_EnemyDeath2_Func014A takes nothing returns nothing
    call AddHeroXP(GetEnumUnit(), 1, true)
endfunction
...
call ForGroup(udg_Exp_Hero_Group[udg_Gold_PlayerInt], function Trig_EnemyDeath2_Func014A)
```

- `udg_Gold_PlayerInt = GetUnitUserData(GetTriggerUnit())` — **죽은 적이 속한 라인의 주인**. 골드 지급과 같은 변수다.
- 그 플레이어의 `udg_Exp_Hero_Group` **전원**에게 +1. **킬 귀속이 아니다.**
- `showEyeCandy = true` (경험치 텍스트 표시)

`HeroExpRange=0.0` · `GlobalExperience=0` · `SummonedKillFactor=0.0`이므로
**엔진이 주는 경험치는 0**이다. 경험치는 오직 이 트리거에서만 나온다.

### `udg_Exp_Hero_Group`에 들어가는 유닛

**조합으로 만들어진 초월함/영원한 영웅(`H*`)뿐**이다. 각 `Trig_Eternal_*` 조합 트리거가
유닛 생성 직후 두 줄을 실행한다:
```jass
call GroupAddUnitSimple(GetLastCreatedUnit(), udg_Exp_Group)
call GroupAddUnitSimple(GetLastCreatedUnit(), udg_Exp_Hero_Group[GetConvertedPlayerId(GetTriggerPlayer())])
```
게임 시작 시 `udg_Exp_Hero_Group[0..4] = CreateGroup()`로 비어 있게 초기화된다(`war3map.j:2474`).

## ㉣ 시작 스탯 = **0 / 0 / 0** (타시기·야마토 제외)

### 근거 — 맵 자체가 자기 검증을 한다

| 조건 | 유닛 수 | base 분포 |
|---|---|---|
| `upra`(주 능력치) 지정 | 36 | **전부 `hrif`** |
| 성장치(`ustp`/`uagp`/`uinp`) ≠ 0 | 39 | `hrif` 36 + `Hvwd` 3 |
| 성장치 ≠ 0 인데 `upra` 없음 | 3 | `H05N`·`H0BD`·`H0BE` (전부 `Hvwd`) |
| `ustr`/`uagi`/`uint`(시작 스탯) 지정 | 27 | **전부 `Hvwd`** |

읽는 법:
- **`hrif`(라이플맨)는 비영웅**이라 주 능력치가 없다 → 영웅으로 만들려면 `upra`를 직접 지정해야 한다.
  실제로 `upra`를 지정한 36기가 전부 `hrif` 기반이다. **시작 스탯은 안 건드렸으므로 라이플맨의 0을 그대로 상속한다.**
- **`Hvwd`(워든)는 스톡 영웅**이라 주 능력치를 상속한다 → `upra` 불필요. 실제로 그 3기만 `upra`가 없다.
  대신 워든의 **스톡 시작 스탯을 지워야** 해서 `ustr/uagi/uint`를 명시했고, 그 27기가 전부 `Hvwd` 기반이다.
- `ustr`을 지정한 27기 중 **값이 0이 아닌 건 `H05N` 타시기 하나뿐**(10/11/1). 나머지 26기는 전부 0/0/0
  (「흔함영웅」 더미 등).

이게 영웅 판정에 대한 교차검증도 된다: 레벨업 트리거가 `EVENT_PLAYER_HERO_LEVEL`로 등록돼 있고
(`gg_trg_heroLevel_______________2`), 실제로 이 유닛들에서 발화한다.

### 성장치

| 유형 | STR/lvl | AGI/lvl | INT/lvl | 유닛 |
|---|---|---|---|---|
| STR 주스탯 | **+0.85** | +0.21 | +0.21 | 11기 |
| AGI 주스탯 | +0.21 | **+0.85** | +0.21 | 10기 |
| INT 주스탯 | +0.21 | +0.21 | **+0.85** | 15기 |
| `H05N` 타시기 (Hvwd) | +0.42 | **+1.70** | +0.42 | 1기 |
| `H0BD`·`H0BE` 야마토 (Hvwd) | +0.21 | **+1.06** | +0.21 | 2기 |

**주스탯:부스탯 = 0.85 : 0.21 ≈ 4 : 1.** 타시기는 정확히 그 2배(1.70/0.42), 야마토는 1.25배(1.06/0.21).

## 도움소 — 「능력치 증가」 (`H0B7`)

상점이 파는 유닛이고, 팔리는 순간 트리거 `Trig_Money_trade2_______u`가 발화한다.

| 항목 | 값 |
|---|---|
| 유닛 | `H0B7` 「능력치 증가」 (base `hfoo`) |
| **가격** | **`ugol` = 2,500** (목재 0, 식량 0) |
| 재고 | `usma`=4(최대), `usrg`=115, `usst`=1825, `urqc`=1 |
| 선행 | `ureq = Rhfl` = 업그레이드 「초월함 유닛 조합 완료」 |
| 툴팁 | 「초월함 영웅 유닛의 능력치를 **랜덤하게 1 증가**시킵니다」 |

동작(`Trig_Money_trade2_______u_Actions`):
```jass
call RemoveUnit(GetSoldUnit())
set udg_stat_int = GetRandomInt(1,3)        ← 1=힘 2=민첩 3=지능, 각 1/3
  udg_stat_int==1 → ForGroup(Exp_Hero_Group[플레이어]) : STR +1
  udg_stat_int==2 → ForGroup(Exp_Hero_Group[플레이어]) : AGI +1
  udg_stat_int==3 → ForGroup(Exp_Hero_Group[플레이어]) : INT +1
```
- **그 플레이어의 등록된 영웅 전원**에게 적용된다(1기만이 아니다). 경험치와 같은 그룹이다.
- 어느 스탯이 오를지는 **고를 수 없다.** 2,500엔에 1/3 확률의 +1이다.
- 부수 효과: STR 분기는 `A11V` 레벨을 STR 값으로 세팅(단 `A11V`는 어디에도 안 붙어 있어 **무효**),
  INT 분기는 `A0WP` 레벨을 INT 값으로 세팅(**유효** — 체력재생 +5%/점).
- 이 트리거는 `H0B7`이 팔릴 때만 발화한다: `GetUnitTypeId(GetSoldUnit())=='H0B7'`.

기대값: 2,500엔당 주스탯 +1/3점 → **주스탯 1점 = 7,500엔 = 공격력 +800.**
즉 **엔당 공격력 약 0.107**. (참고: 레벨 24까지 올려서 얻는 주스탯 19점 = 공격력 +15,200.)

## 미확인 / 주의

- `H0B7`의 `usst=1825`·`usrg=115`가 각각 재고 보충 주기/시작 재고 중 무엇인지 필드 의미 미확정. `[미확인]`
- `A0WP` 갱신 조건이 경로마다 다르다: 레벨업 트리거는 `A0WP < 21`, 조합·도움소는 `< 31`.
  **레벨업만으로는 INT 20을 넘겨도 오라가 21에서 멈춘다.** 의도인지 버그인지 판단 불가. `[미확인]`
- 스톡 `hrif`(라이플맨)의 STR/AGI/INT가 0이라는 것은 **비영웅이라 주 능력치 자체가 없다**는 데서
  나온 결론이다. `UnitBalance.slk` 원문을 직접 보지는 못했다. 확신도 **높음(추정 아님에 가까움)**이나
  「원문 확인」은 아니다.
