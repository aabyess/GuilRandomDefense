# ca753e0 전반 과소집계 감사 — 2026-09-06

`영원_윤현모`의 A0BL 사례(description은 인용하는데 어떤 effect도 그 값을 가진 적이 없음,
`ca753e0`에서 도입)가 그 파일 하나만의 문제가 아니라 `ca753e0`("③-b 2채널 유닛 단위
재배정") 전반의 시스템적 과소집계일 수 있다는 PM 가설을 검증했다. 읽기 전용 감사.

## 결론 — 시스템적 과소집계 확인 안 됨

집계 방식(파일별 "새로 추가된 인용 개수" vs "새로 추가된 effect 개수" 비교)으로는
증명도 반증도 못 한다. 세 가지 발견:

### ① 가짜 양성 클래스 발견·검증

"+1 인용절, +0 effect" 모양을 보인 파일 14개(희귀함_박수찬·유재헌·배병규·서민성·
선효진·양재모·엄태웅·배성령·배현진·박은석·박민수, 전설적인_박성호, 변화됨_강재규 외 1개).
그중 2개(희귀함_박수찬·유재헌)를 diff 전체로 직접 확인한 결과 **과소집계가 아니다** —
이 커밋은 1차(주) 배정 자체를 통째로 교체했고(새 skillName·새 description·기존 effect
블록의 attackType/multiplier를 제자리 수정), "2차 배정(...)" 절 텍스트는 그 같은 1차
배정을 다시 서술한 것이지 새 능력이 아니다. 인용절 세는 정규식이 이 경우를 구분 못 한다.

### ② 다중 능력 파일도 깨끗한 격차가 안 나옴

새 화살표형 인용이 3개 이상 추가된 파일(전설적인_정윤식·불멸_신지우·영원_최상호·
영원_김정래 등)은 대체로 "인용 1개당 effect 2개"로 맞아떨어져 균일한 템플릿으로 보인다.
그런데 정작 `영원_윤현모` 자신은 이 비율에 안 맞는다(전체 "2차 배정" 언급 6개, 그중
화살표-ID형 4개 — A0CB는 서로 다른 더미 경로 두 개로 두 번 인용됨 — 인데 새 effect는
10개 붙었다. 깔끔한 1:1도 1:2도 안 나온다). 즉 **집계 방식만으론 A0BL이 정확히 0개를
받았는지, 예상과 다른 값을 받았는지를 못 가른다** — 개별 인용마다 값 추적이 필요한
별도의 더 깊은 작업이다.

### ③ 불멸_고도현(A0EM 파일)은 같은 원인이 아니다

이 파일이 `ca753e0`가 건드린 목록에 있는 건 맞다(13줄 변경). 하지만 이 커밋에서
**새 "2차 배정" 절 0개 추가, 새 effect 0개 추가, 화살표-ID 인용 순증감 −1**(하나가
빠지고 새로 추가된 건 없음)이다. 즉 A0EM 인용은 `ca753e0` 이전부터 있었다 — 이 커밋은
이 파일 구조를 거의 안 건드렸다. **A0EM의 "일치하는 값 없음" 문제는 A0BL과 원인이
다르다** — 더 이른 커밋(예: `2a8cb51` 또는 최초 `generate_unit_skill_damage_effects.py`
실행)을 따로 추적해야 한다.

## PM에게

`ca753e0`의 광범위한 과소집계 증거는 이번 패스에서 못 찾았다 — 의심스러워 보였던
패턴 하나는 집계 휴리스틱의 가짜 양성이었고, 진짜 다중인용 파일들은 값 대조 없이는
격차를 증명할 방법이 없다. **A0EM과 A0BL은 같은 원인이 아니다.**

## 재현

`git show --stat ca753e0`로 대상 파일 목록을 얻고, 각 파일의 diff에서 새로 추가된
"2차 배정(트리거·더미 채널): ... → AXXXX)" 절 개수와 새로 추가된 `- kind: 0` effect
블록 개수를 비교했다. 1차 배정 교체(스킬 전체 재배정)와 2차 배정 추가(새 능력 얹기)를
구분 못 하는 게 이 방법의 한계다 — 다음에 쓰려면 diff의 `-`/`+` 라인을 같이 봐서
"완전히 새 unified diff hunk로 추가된 절"만 세야 한다.
