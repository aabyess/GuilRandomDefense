# 특성 26분기의 「승급 후(레벨 2)」 수치는 어디 있나 (2026-09-05, 리서치담당)

| ⑤ 교체 능력 자체(1·2차 표에 이미 있음) | **6** (호킨스·루피·로빈·브룩·샹크스·시키) |

## ① w3a에 레벨 2 값이 있는 것 — 3개뿐 `[파일확인]`

| 능력 | 캐릭터 | 레벨 1 → 2 |
|---|---|---|
| `A0AL` | 도플라밍고 6변신 | `ahdu` 4.5 → **6** (지속시간) |
| `A0IE` | 우솝 9도움소 독약1 | `Nab3` 20→**25** · `Nab4`/`Nab5` 200,000→**300,000** · `adur`/`ahdu` 5→**7.5** |
| `A0ES` | 레일리 B명왕의 패기 | `Had1` −20 → **−25** (방어력 감소) |

**이 3개는 그대로 옮기면 끝난다.**

## ② 트리거가 `레벨==2`로 분기하는 것 — 4개 `[파일확인]`

| 캐릭터 | 조건 | 레벨 2에서 추가되는 것 |
|---|---|---|
| 후지토라 `A0GR` | `GetUnitAbilityLevelSwapped('A0GR',…)==2` | `Trig_Huji_meteor` 실행 → **315,000 [CHAOS/NORMAL]** |

| 센고쿠 `A0D8` | 1/20 확률 안에서 `==2` | 더미 `e0K6` 추가 생성 |

## ③ 레벨을 **수치로 곱하는** 것 — 4개 `[파일확인]`

| 캐릭터 | 식 | 레벨 2 결과 |
|---|---|---|
| 제트 `A09E` | `레벨 × 100,000 + 200,000` | **400,000** (레벨1은 300,000) |
| 아카이누 `A0HG` | 반복 횟수 `< 5 + 레벨` | **7회** (레벨1은 6회) |
| 핸콕 `A0IN` | 간격 `0.03 + 0.05 ÷ 레벨` | **0.055** (레벨1은 0.08 — **레벨이 오르면 값이 작아진다**) |
| 거프 `A0GY` | 레벨을 정수변수에 담아 사용 | **용도 `[미확인]`** — 담기만 하는 것까지 확인 |

**이 셋은 「레벨 2 값」이 따로 없고 식에 레벨이 들어간다** — 우리 쪽에선 레벨별 값 두 개로 펼쳐 넣으면 된다.

## ④ ⚠️ 새로 찾은 채널 — **특성 플래그 변수 → 강화 트리거** (6개)

`A0D0`·`A10F`·`A069`·`A0R2`는 **w3a에 레벨 2 값도 없고, 트리거가 레벨을 읽지도 않는다.**
그런데 **아무 일도 안 일어나는 게 아니다.** 특성 분기가 능력 레벨을 올리면서 **동시에 캐릭터 전용 변수를 세팅**한다:

```jass
call IncUnitAbilityLevelSwapped('A0D0',GetTriggerUnit())
set udg_Tichi_TR_AddInt[플레이어]=3          ← 진짜 효과는 이쪽
```

그 변수를 그 캐릭터의 평타 트리거가 읽어 **강화판 트리거로 갈아탄다**:

| 캐릭터 | 플래그 | 기본 → 강화 | 실제 차이 |
|---|---|---|---|
| 키드 | `udg_bool_kid_tr` | `Kid_Skill_Mana` → **`Kid_Skill_Mana_Tr`** | `1,000,000+α` **1타** → `400,000+α` **3타** |
| 루치 | `udg_bool_lucchi_tr` | `Luchi_Skill_1` → **`Luchi_Skill_1_Kick2`** | 피해 0건 → **400,000 [MAGIC] ×2 + 최대체력 비례 [CHAOS]** |
| 로우 | `udg_Law_Bool` | `Law_Skill_2` → **`Law_Skill_2_reinforce`** | 피해식은 **동일**(현재체력×0.2) — 차이는 피해 밖에 있다 |
| 검은수염 | `udg_Tichi_TR_AddInt=3` | `Tichi_skill_4` → **`Tichi_skill_4_tr`** | `GetRandomInt(1,3)==3` 분기로 강화판 |
| 프랑키 | `udg_bool_franky_tr` | `Franky_Skill_1` 내부 분기 | 더미 `e06I` 추가 |
| 나미 | `udg_NamiT_Bool` | `Nami_Skill_1` 내부 분기 | 더미 `e0NI` 추가 |

**「능력 레벨을 올린다」는 겉모습이고, 실제 강화는 별도 트리거 이름(`_Tr`·`_reinforce`·`_Kick2`)에 들어있다.**
`alev=2`만 보고 「레벨 2 값이 없으니 원작에도 없다」로 판정하면 여기서 틀린다.

## ⑤ 능력교체 6개 — PM 예상대로 1·2차 표에 있다

`A0WK`·`A0JU`·`A0FL`·`A0R1`·`A136`·`A0T4` 전부 `alev`가 1(또는 미지정)인 **단일 레벨 능력**이다.
→ **교체 후 능력 자체의 수치가 곧 레벨 2 값**이고, 이미 뽑아둔 표에서 찾으면 된다.
(`A10S` 로우·`A107` 나미 둘은 능력교체로 분류돼 있지만 **실제 강화는 ④의 플래그 채널**이었다 — 분류를 고쳐야 한다.)

## ⚠️ 남은 불확실

- **`ACbh` 껍데기 4개의 스톡 레벨 2 상속** `[미확인]`: `A0D0`·`A10F`·`A069`·`A0R2`는 `Hbh1=0`·`Hbh3=0`을 **레벨 1에만** 써뒀다.
  워크에서 레벨 2 필드를 안 쓰면 **기반 능력(`ACbh`)의 레벨 2 기본값을 따른다**. 그게 0이 아니면 **의도치 않은 크리티컬이 붙는다.**
  스톡 정의를 못 봐서 확정 못 한다 — 다만 **우리 쪽엔 그런 상속이 없으므로 실질 영향은 없다.**
- 거프 `A0GY`가 담은 레벨 값의 **용도** `[미확인]`.
- 로우 `Law_Skill_2` vs `_reinforce`의 **피해식이 같다** — 차이가 범위·횟수·부가효과 중 무엇인지는 안 봤다 `[미확인]`.
