# `I00E`/`I00F` 정체·획득경로 — ⓐⓑ는 검증 완료, ⓒ는 도구 한계로 확정 못함

조사: 리서치담당 / 2026-09-07, `Tools/w3x`로 `war3map.w3t`(아이템 원문
데이터)를 직접 파싱해 재확인. `w3t` 전용 파서가 없어서 `w3u.py`를 그대로
재사용했다(포맷이 동일 — 원작유닛수/원작유닛들/커스텀수/커스텀들 구조는
w3t도 똑같다, 재확인해서 정상 파싱됨).
요청: PM — ⓐ원작 이름·툴팁 ⓑ무엇을 하는가 ⓒ**어떻게 얻는가**. 기존
"랜덤 특수 도박/다른세계 유닛 도박, 우리에 없음" 추정을 검증하거나 기각.

## 결론 — **ⓐⓑ는 추정이 아니라 원문 그대로였다(검증 완료). ⓒ는 확정 못한다(도구 한계, 아래 근거).**

## ① ⓐ 이름·툴팁 — `war3map.w3t` 원문 직접 추출(재확인, 기존 추정과 일치)

```
I00E  base=rlif
  unam = 랜덤 특수 도박
  utip = 돈 도박 중급(W)          ← ⚠️ 아래 참고, 복붙 잔재
  utub = 아래의 유닛 중 1개를 얻습니다.
         랜덤 위습
         고대의 배
         변화 회수
  igol = 100 (골드비용)  ihtp = 7  ilev = 1  ilvo = 1  uhot = W
  iabi = (없음)  ureq = (없음, 전제조건 없음)

I00F  base=rlif
  unam = 다른세계 도박
  utip = 다른세계의 유닛 도박(F)
  utub = |cffff8200원랜디 확장팩은 공식카페 cafe.naver.com/clanopcr 에서
         다운로드 하실수있습니다.
         |cffff0000확장팩 인증은 맵 중앙 유닛을 클릭하시면 됩니다!|r

  igol = 3000  ihtp = 7  ilev = 1  ilvo = 1  uhot = F
  iabi = (없음)  ureq = h08B,R02P (유닛 h08B 보유 + 연구 R02P 완료 필요)
```

**둘 다 "미상"이 아니다** — `unam`(이름)·`utub`(설명)이 원작에 처음부터
멀쩡히 들어 있었다. 우리 자산의 `ItemData_I00E_미상.asset`/`_I00F_미상.asset`
이름표만 갱신이 안 된 상태다(이건 코딩 영역이라 내가 안 고친다).

**⚠️ `I00E`의 `utip`이 `I00D`("돈 도박 중급")와 글자 그대로 같다** — `unam`/`utub`은
`I00E`답게(랜덤 특수 도박) 새로 썼는데 `utip`만 복붙하고 안 고친 원작의
잔재로 보인다. `uhot`(단축키)도 `I00D`·`I00E` 둘 다 `W`로 같고, `base`도
둘 다 `rlif`로 같다 — **`I00E`는 `I00D`를 복제해서 만든 파생 아이템**일
가능성이 높다(이름·설명만 새로 쓰고 나머지 필드는 원본을 그대로 물려받음).

## ② ⓑ 무엇을 하는가 — 원문 그대로, 기존 추정과 정확히 일치

- **`I00E`**: 골드 100 소모, 즉시 "랜덤 위습 / 고대의 배 / 변화 회수" 중
  1개를 얻는 도박. 성공/실패 구분 문구가 없다(`I00D`의 "60% 확률로"와
  달리 확률 문구 자체가 없음) — **셋 중 하나가 100% 나오는 것으로
  보인다(실패가 없는 도박)**, 단 어느 비율로 셋 중 하나를 고르는지는
  `iabi`가 비어 있고 `war3map.j`에도 이 아이템 리터럴이 0건이라 **원문
  어디에도 그 확률 값이 없다** — 지어내지 않고 `[미확인]`으로 남긴다.
- **`I00F`**: 골드 3000 소모, 17% 확률로 "랜덤전용"(다른세계) 등급 유닛
  획득, 실패시 없음. 99초마다 재사용 가능 횟수 1회 충전(쿨타임형).
  `h08B` 유닛 보유 + 연구 `R02P` 완료가 전제조건.

**기존 "랜덤 특수 도박/다른세계 유닛 도박"이라는 이름 자체가 이미
원작 `unam` 그대로였다 — 추정이 아니라 정확한 원문 인용이었다. 검증
결과 기각할 부분이 없다.**

## ③ ⓒ 어떻게 얻는가 — **확정 못한다, 도구가 못 보는 영역이라는 근거까지 확인**

세 갈래로 확인했고 **전부 0건이었다**:

1. **`war3map.j` 리터럴 검색**: `'I00E'`/`'I00F'` 전수 0건(대소문자 무시
   검색도 0건). `AddItemToStockBJ`류 상점재고 함수 호출 자체가 파일
   전체에 **한 건도 없다**(이미 `ITEM_GATES_I00A_D_E_F_RESOLVED.md`에서
   확인된 것과 동일 — 재확인 완료).
2. **`war3map.w3u`(유닛) 전 필드 검색**: 이번에 새로 한 것 — **아이템
   ID 패턴(`I` + 영숫자3글자)이 들어있는 유닛 필드를 458개 유닛×전체
   필드에서 정규식으로 훑었다. 0건.** 유닛의 "판매 유닛 목록"(`useu`
   필드)은 실재하고 실제로 쓰인다(예: `o02P`(메타몽) `useu=H0BS`,
   `h062`(도박소) `useu=h06F,h0AX,H0AZ,H0AW`) — **그런데 이건 전부
   유닛ID만 담고, 아이템ID를 담는 필드는 이 맵의 어느 유닛에도 단
   하나도 없다.** 즉 **`I00E`/`I00F`만이 아니라 아이템 38종 전체가
   `.w3u` 안에 "이 상점이 이 아이템을 판다"는 정적 필드를 안 갖고
   있다** — 이건 이 두 아이템만의 문제가 아니라 이 맵의 아이템 판매
   시스템 전체가 이 방식으로는 안 보인다는 뜻이다.
3. **`war3mapUnits.doo`(맵 배치 원본) 접근**: PM이 먼저 시도해서 `None`을
   받았다고 알려준 것을 내가 독립적으로 재현했다 — `Archive.read('war3mapUnits.doo')`가
   **나도 `None`을 받는다**(`war3map.doo`는 20,006바이트로 정상 읽히는데
   `war3mapUnits.doo`만 `None`이다). `Tools/w3x`가 다루는 파일
   목록(`README.md`: w3u/w3a/w3q/w3h/w3t/wts/j)에 애초에 `.doo`가 없다
   — **이 도구가 원래 다루도록 만들어진 범위 밖이다.** 상점별 정적
   재고 목록(개별 배치 유닛이 갖는 "판매 목록" 오버라이드)은 WC3에서
   `.doo`에 저장되는 경우가 흔한데, 이 맵은 보호맵이라 파일명 해시가
   달라 못 꺼낸다.

**결론: ⓒ는 이번 조사 범위(`Tools/w3x`가 읽는 j/w3u/w3a/w3q/w3t/wts)로는
원천적으로 확정 불가능하다.** 추측하지 않는다 — `[미확인: war3mapUnits.doo
접근 불가로 판정 불가, PM도 동일 결과 확인함]`으로 남긴다.

## 그나마 나온 간접 단서 — 지어낸 값 아님, 원문 텍스트 그대로

`I00F`의 `utub`(설명문)이 그 자체로 획득 방법을 말하고 있다: **"확장팩
인증은 맵 중앙 유닛을 클릭하시면 됩니다!"** — 이건 상점 재고 목록이
아니라 **맵 중앙에 배치된 특정 유닛을 직접 클릭해서 사는 방식**임을
암시한다(일반 다중품목 상점이 아니라 전용 판매 유닛 하나). 그 "맵 중앙
유닛"이 정확히 어느 유닛ID인지는 `.doo`가 있어야 확정되는데 그건 위
③의 한계 그대로다. `I00E`는 이런 서술이 없어 특별한 단서가 없다 —
`I00D`와 판박이 필드(`uhot=W`, `base=rlif`, 복붙된 `utip`)인 것으로 볼
때 **`I00D`를 파는 상점이 `I00E`도 같이 팔 가능성이 있다**는 정황
추론은 가능하나, 이것도 확정이 아니라 정황이라고 명시한다.
