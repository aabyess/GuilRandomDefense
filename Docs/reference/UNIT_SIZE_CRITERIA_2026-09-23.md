# 유닛 스킨 크기·자세 결함 판정 기준 (2026-09-23)

작성: 구현담당2 / 2026-09-23. PM 채택.
실측: PM이 유니티 브리지로 돌림(`ClaudeBridge/outbox/1258.txt` units 전수 213종, `1259.txt` bakesize 19건, `1260.txt` clipsample·idleview).

## 결론 — **FBX 파일 크기는 판정 기준이 아니다**

blender가 커밋된 유닛 FBX를 전수 실측해 규약(키 1.8m) 이탈 17건을 찾았다.
그중 **16건은 게임에서 멀쩡했다.** `ArtBinder.FitToHeight`가 0.02m짜리도 23m짜리도 키 20에 맞춘다.
실제로 깨진 건 **안흔함_박준희 1건**이었다. 원인은 크기가 아니라 뼈대와 메시가 서로 다른 좌표계에 있는 것이었다.

판정은 **유니티 산출물**(프리팹 + Idle을 입힌 모습)로 한다. 파일 크기는 참고만 한다.

## 판정 기준

| # | 대상 | 결함 조건 | 도구 |
|---|---|---|---|
| ① | 사람형(아바타 isHuman) | units 키 ≠ 목표값(`ArtBinder.UnitHeight`, 흔함은 ×0.85) **또는** 몸 위쪽 y < 0.8 **또는** 「Idle을 입히니 뼈가 사방으로 흩어졌습니다」 경고 | `units` |
| ② | 모든 스킨 유닛 | 프리팹의 뼈 퍼짐 최대축 > 렌더러 경계 최대축 × 3 | `bakesize <프리팹>` |
| ②' | ②에 걸린 것 | Animator 평가 뒤 구운 크기가 ×2 이상 튐 → 레인에서 깨짐 확정 | `clipsample <프리팹>` |
| ③ | 소지품이 머리 위로 나온 사람형(칼·후광 등) | 몸 높이 < 전체 키의 85% → blender `height_top_z`로 몸 기준 키를 잡는다 | blender 재수입 |
| ④ | `ArtBinder.FourLeggedModels` 등록 모델(배·짐승·물고기·소품·Generic 원뿔형) | 가장 긴 축 ≠ `UnitHeight` × 등록 배수. 방향은 사진으로 본다 | `units` |
| ④' | 목록에 **없는** 뼈 없음/Generic 모델 | 가장 긴 축이 키가 아니면 「경계 상자 규칙에 눕기」 후보 → 목록 등록 검토 | `units` |
| ⑤ | blender 출고 전(새 스킨) | 재수입 시 세계 크기 0인 메시가 있거나, 뼈 퍼짐 / 메시 경계 > 3이거나, **키 < 0.1m**면 **출고 금지**. 그 밖의 키 1.8 이탈은 경고만 | blender 배치 |

- ②의 3배는 `MapGenerator.MaxFigureSpread = 3`과 같은 잣대다.
- 흔함 목표 키 = `UnitHeight` × `ArtBinder.CommonHeightScale` 0.85. 의도된 값이다.
  목표값은 **숫자로 외우지 말고 `UnitHeight`에서 유도한다.** 09-23 오후에 20 → 30으로 올랐다(흔함 17 → 25.5).
  아래 근거표의 키 20·17은 **UnitHeight 20 시절** 측정값이다.
- ⑥ 🔴 **문턱을 목표값에 비례하는 양(배율)에 걸면, 목표값을 바꾸는 순간 조용히 어긋난다.**
  09-23 하루에 같은 병을 네 번 봤다 — 위습칸 깊이 · 미니맵 범위 · 팀 패널 높이 · 아래 FitToHeight 문턱.
  숫자를 박기 전에 「이 숫자가 기대는 다른 값이 바뀌면 이것도 바뀌어야 하나?」를 묻고, 그렇다면 그 값에서 **유도**한다.
  - FitToHeight 이력: 09-23 오후까지는 배율이 1000을 넘으면 키 맞추기를 **건너뛰었다**(점이 됨). 이 1000은 원래
    「잰 높이가 0으로 나오는 사고」(09-08 이호준 7,062배)를 막으려던 것인데 **배율**에 걸려 있어서, 목표 키를 20 → 30으로 올리자
    경계에 있던 모델(907·700배)이 1361·1050배로 넘어가 점이 됐다(아래 사례).
  - **09-23 이후(`b7fcea4f`)**: 배율로는 **건너뛰지 않는다.** 진짜 극소형도 그냥 키운다. 배율이 **500을 넘으면 경고만** 남긴다
    (「원본이 너무 작다 — 세우긴 하지만 blender가 1.8m 규약으로 다시 내보내야 한다」) → 재출고 대상이 로그에 드러난다.
    500인 이유: 목표 30에서 1.8m 규약 모델의 배율은 약 17이다. 500이면 **규약에서 30배 넘게 벗어난 것만** 걸린다 — 넉넉하면서 조용하지 않다.
    (구현담당2 제안, PM 반영)

## 🔴 사례 — 목표 키를 올리자 멀쩡하던 3종이 점이 됐다 (2026-09-23 오후)

`UnitHeight`를 20 → 30(×1.5)으로 올린 뒤, 아래 표에서 **정상**이던 극소형 모델이 게임에서 키 0.02짜리 점이 됐다(PM outbox 1288).

| 유닛 | 노드 배율 @ 목표 20 (1259) | × 1.5 @ 목표 30 | 1000배 상한 |
|---|---|---|---|
| 특별함_임장혁 | 907 | **1361** | 초과 → 건너뜀 → 점 |
| 흔함_양재모 | 700 | **1050** | 초과 → 건너뜀 → 점 |
| 흔함_최상호 | 공용 Idle 클립 원본(0.022m)을 인형으로 쓰고 있었다(`ModelOverrides` `("idle", ...)`) | | |

ArtBinder 로그 「배율 1361배」·「1050배」가 소수점까지 계산과 맞았다. 1000은 목표 키와 무관한 **고정 문턱**이라,
목표를 올리면 경계에 있던 모델이 조용히 넘어간다(위 ⑥).
조치: blender가 세 모델을 1.8m로 다시 뽑음(배율 약 17배로 내려감). 문턱은 「건너뛰기 없음 + 500배 경고」로 바뀜(⑥, `b7fcea4f`).
확인(PM 배선·맵생성 뒤): 건너뜀 경고 3 → 0건 · Idle 리타게팅 실패 29 → 0건 · 임장혁 30.00 · 양재모 25.50 · 최상호 25.50 · 박준희 30.00.

교훈: 이번 17건 조사에서 극소형 4종을 「FitToHeight가 흡수했으니 정상」으로 닫았는데, **상한 근처(700~907배)라는 여유 부족**은 결함 후보로
적었어야 했다. ⑤의 blender 출고 검사에 「키 0.1m 미만이면 출고 금지」를 더한다(목표 30이면 배율 300배 이하 — 상한까지 3배 여유).

주 — 안흔함_이재윤: 「메시 로컬 198.4 × 오브젝트 배율 1/44라서 유니티가 198로 읽는다」는 가설은 **실측으로 기각**됐다.
원본 FBX를 임포트한 상태가 자산 경계 3.58×5.04×4.47, 노드 배율 1.00이다. 유니티가 1/44를 정점에 구워 넣었다.
아바타는 isValid·isHuman True(24뼈 매핑)다. 앞뒤 22.55는 원숭이 자세 때문이다.

「y 2.0이라 누웠다」로 보였던 노건완·안흔함_강재규는 누운 게 아니다. **Y가 앞뒤 몸길이**였다.

### 게임에서 깨짐 — 안흔함_박준희 (1건)

| 측정 | 값 |
|---|---|
| 원본 FBX 메시 | 노드 배율 0.01. 구운 메시 y −12.25 ~ 0 (거꾸로 매달림). 렌더러 경계 0.13 |
| 원본 FBX 뼈 55개 퍼짐 | (4.07, **0.93**, **12.05**). 뼈대가 Z로 눕고 메시 노드 대비 약 100배 |
| 프리팹 렌더러 경계 | 6.18 × 20.45 × 4.21 (휴식 자세라 멀쩡해 보임) |
| 프리팹 뼈 퍼짐 | **(646, 148, 1915)**. 렌더러의 약 94배로 ② 위반 |
| units | 몸 위쪽 (0.00, 0.01, −1.00) 누움 + 「뼈가 사방으로 흩어졌습니다」 경고 |
| clipsample (공용 Idle, isHuman) | 구운 크기 (4.19, 12.58, 2.21) → t=0 **×44**, t=5.48 **×74**, Rebind만 해도 ×45. Siren_1_0 2683 이동 |
| 대조군 김용태 같은 클립 | ×0.77 (T자에서 팔이 내려온 정상 변화) |

원인: glb→fbx(assimp) 변환본이라 메시 노드와 뼈대 노드의 배율(0.01 대 1)과 축(뼈는 누움, 메시는 뒤집힘)이 따로 논다.
휴식 자세에선 bindpose가 상쇄해서 멀쩡해 보인다. 하지만 아바타가 누운 100배 뼈대로 만들어져서 어떤 사람형 클립도 못 입는다.
기존 특례 `UnitModelPostprocessor.ImportScales` 100과 `ArtBinder.ModelAdjustments` X180은 휴식 자세 모습만 고치는 반창고다.

조치: blender 재출력. 메시와 아마추어를 한 좌표계로 맞추고, Hips를 원점·+Z 위·키 1.8로 둔다.
🔴 새 FBX를 반영하는 **같은 커밋에서** 반창고 두 개를 지우고 `GetVersion`을 올린다. 안 지우면 100배·뒤집기가 한 번 더 걸린다(09-13 상붕카 「두 번 눕는다」와 같은 구조).

## 쓰는 법 (브리지 명령)

```
units <파일> <시작> <개수>                   # 전수. 표에 이름이 나오니 순번 밀림은 무관(단, 모델 배선이 끝난 뒤에 찍을 것)
bakesize Assets/Prefabs/Generated/Unit_<이름>.prefab
clipsample Assets/Prefabs/Generated/Unit_<이름>.prefab
idleview <파일> Assets/Prefabs/Generated/Unit_<이름>.prefab <씬 앵커 이름> [거리배율]
```

- 「파일이 이상하다」와 「게임에서 이상하다」는 다르다. 전자는 blender 표로, 후자는 위 명령으로 가른다.
- units(프리팹)와 **맵 인형은 따로 본다.** 인형은 MapGenerator가 자리 폭에 맞춰 따로 재운다 — 「레인은 멀쩡해도 인형은 점」, 반대로
  「인형은 서 있어도 레인에선 깨짐」(박준희) 둘 다 있었다. 인형 확인: `big Map 0 <이름>`(그 이름 인형의 경계) · `inspect <오브젝트 이름>`.
- units의 「몸 위쪽」은 Hips→Head로 잰다. 그래서 **Hips 뼈가 골반에서 떨어진 리그는 멀쩡해도 기울어 보인다.**
  사례: 히든_석성례 (0.25, 0.87, 0.42) (outbox 1261). 휴식 자세 사슬 계산값 (0.29, 0.82, 0.49)과 같았고,
  실제 몸의 축인 Spine→Head는 (0, 0.97, 0.23), 정면 사진도 정상이었다. 기울어짐이 나오면 `rig`로 Hips 자식 위치부터 볼 것.
  → 09-23에 units를 **양 UpperLeg 중점→Head**로 재도록 고쳤다(ClaudeCommands.UnitLineup).
- 📌 미결: **다음에 히든_석성례를 손볼 때** blender에서 Hips 머리를 양 허벅지 중점으로 옮긴다. 지금은 Idle에서 멀쩡하다.
  다만 다른 클립(걷기·공격)의 엉덩이 궤적은 확인하지 않았다.
- 맵 인형은 흩어짐을 감지하면 바인드 포즈로 되돌린다. 그래서 **사진에선 서 있어도 레인에선 깨질 수 있다.** ②에 걸리면 반드시 ②'까지 볼 것.
