# 원작 1,559종 ↔ 우리 239종 이름 매핑 — 축 찾기 (2026-09-04, 리서치담당)

> 출처: `ORD11.089.w3x`의 `war3map.w3u`(유닛 이름·등급 색) + `war3map.j`(프리플레이스 유닛 = 맵 안의 조합표 전시). 전부 `[파일확인]`. 매핑 자체를 완성한 게 아니라 **"무엇으로 맞추면 되는가"를 확정**한 문서다.
> 원자료: `combine-table/ORIGINAL_TABLE_11089_RAW.txt`(543개 전시 유닛 좌표+이름), `combine-table/ORIGINAL_RECIPES_11089_AUTOSEG.txt`(자동 분절한 레시피 140줄, 노이즈 있음).

## 결론 — 축은 셋이고, 셋 다 잡혔다

1. **등급별 개수**가 거의 일치한다 (아래 표). 1,559종 중 플레이어 유닛은 **229종**뿐이고, 나머지 1,330은 적·위습·이펙트·건물·스킬용 분신이다.
2. **조합표가 맵 안에 물리적으로 깔려 있다** — `war3map.j`가 543개 전시 유닛을 좌표로 배치한다. 같은 y가 한 줄, x 왼쪽→오른쪽이 "재료… → 결과"다. **우리 `RECIPES_LOW.md`·조합표 이미지와 같은 표다** — 사용자가 찍어 준 이미지가 바로 이 전시 구역이다.
3. **"동일 승급" 패턴이 원작에도 있다** — `우솝×2→저격왕 우솝`, `쵸파×2→쵸파 럼블볼강화`. 우리 `강주혁×2→강주혁(알라)`, `문필환×2→문필환(오네쇼타)`와 같은 구조라 **이 4~5개가 앵커**가 된다.

## 2. 조합표 전시 구역 — 좌표에서 레시피가 나온다

`war3map.j` 프리플레이스 구간의 `set u=CreateUnit(p,'h00D',99.5,-6874.8,270)` 같은 줄 627개 중 등급 색이 있는 543개가 조합표다. 예:

```
y≈-4394 : h008 쵸파(흔함, x=-984)  h002 조로(흔함, x=-1240)  →  h00D 브룩(안흔함, x=-574)
y≈-4138 : h004 상디(흔함)           h001 나미(흔함)            →  h00O 니코 로빈(안흔함)
```

자동 분절(같은 줄에서 x 간격 420 초과면 다른 레시피)로 뽑은 **흔함→안흔함 레시피** (`[파일확인]`, 분절 노이즈 제거 후):

| 재료 | 결과 |
|---|---|
| 나미 + 상디 | 니코 로빈 |
| 조로 + 쵸파 | 브룩 |
| 해군 총병 + 나미 | 하찌 |
| 버기 + 나미 | 페로나 |
| 상디 + 조로 | 이나즈마 |
| 쵸파 + 루피 | 베포 |
| 해군 칼병 ×2 | CP9 후쿠로 |
| 해군 총병 ×2 | CP9 블루노 |
| **우솝 ×2** | **저격왕 우솝** (동일 승급) |
| **쵸파 ×2** | **쵸파 럼블볼강화** (동일 승급) |
| (분절 실패) | 타시기 · 에이스 · 프랑키 · 좀비 — 줄이 다른 블록과 붙어 재료를 못 잘랐다 |

우리 `RECIPES_LOW.md` 안흔함: 흔함 2개 조합 9종 + 동일 승급 4종 + 뽑기 전용 1종 = 14. 원작: 조합 ≥10 + 동일 승급 ≥2 = 14. **개수가 같고 구조가 같다.** 완전 동형은 아니다(우리 표는 후기 버전이라 레시피가 일부 바뀜) — 그래서 **1:1 대응은 앵커 몇 개 + 등급 내 순서**로 잡아야 한다.

## 3. 어떻게 매핑하나 — 제안 절차 (`[제안]`)

1. **앵커 고정**: 동일 승급 쌍(원작 우솝·쵸파 / 우리 강주혁·강재규·문필환·박민수)과 뽑기 전용(원작 압살롬 `h010`, 우리 이호준 "볼보이")을 먼저 짝짓는다. `RECIPES_LOW.md`가 이호준을 "원작 압살롬 포지션"이라고 이미 적어뒀다 — 원작 압살롬은 특별함이고 도박 전용(`GAMBLING.md` 5차)이므로 **정확히 그 자리**다.
2. **별칭 활용**: 우리 안흔함 별칭 `알라→코알라`, `재규어`, `오네쇼타`, `로이킴`은 사용자가 붙인 원작 캐릭터 힌트일 가능성이 높다(코알라는 원피스 캐릭터). 사용자에게 "별칭이 원작 누구냐"를 물으면 앵커가 4개 더 생긴다 — **이게 제일 싼 방법이다.**
3. **등급 내 전시 순서**: 원작 전시 구역은 등급별 블록에 줄 순서가 있다(RAW 파일의 y 내림차순). 우리 조합표 이미지도 같은 표를 찍은 것이라 **줄 순서가 보존됐을 가능성**이 높다 — 흔함 9·특별함 33·특수함 6은 개수가 정확히 같으니 **순서만으로 1:1이 될 수 있다.** 검증은 앵커와 어긋나지 않는지로 한다.
4. **레시피 그래프 대조**: 위 1~3으로 흔함·안흔함이 잡히면, 특별함 이상은 "재료 조합이 같은 결과"로 전파한다. 자동 분절 파일(`AUTOSEG`)은 노이즈가 있어 **블록 x 경계를 손으로 정한 재분절**이 필요하다 — 코딩 작업이라 구현담당 몫.
