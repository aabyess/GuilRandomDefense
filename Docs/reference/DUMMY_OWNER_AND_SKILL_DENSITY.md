# ① 구현담당1이 매칭 못 한 23행 — **전부 존재하는 유닛이었다. 미해결 0**

## 왜 못 찾았나

매칭을 **더미 이름의 접두사**(`@초월 로우…`)로 했기 때문이다. 그 접두사는 **제작자가 붙인 라벨**이고,
실제 주인은 트리거가 정한다. 라벨이 틀린 경우가 실제로 있다(아래 §1-3).

## 방법

각 더미의 **부모 트리거 → 진짜 주인 유닛**을 세 경로로 역추적했다:
1. `SaveTriggerHandle(udg_HashAttack, '<유닛ID>', 0, gg_trg_X)` — 유닛ID로 트리거를 등록하는 방식
2. `Trig_X_Conditions`의 `GetUnitTypeId(GetAttacker()/GetTriggerUnit()) == '<유닛ID>'`
3. 둘 다 없으면 **호출자 체인**을 타고 올라가 1·2에 닿을 때까지 (최대 5단)

**79행 전부 주인 확정.** `DUMMY_CHANNEL_MISSING.csv`에 `진짜주인_유닛ID` · `진짜주인_이름` ·
`진짜주인_등급` · `이름표기_등급` · `표기_불일치` 열을 추가했다.

## §1-3. 더미 이름의 등급 표기가 실제와 다른 것 — **10건**

| 더미 | 이름 | 표기 | 실제 |

| `e0EK`·`e0IN` | %**제한됨**변화 도플 둔화 | 제한됨 | **변화된 / 초월함** (`h05S`·`H09D`·`H09E` 공유) |

**「%제한됨변화」 접두사는 「제한됨 또는 변화된」을 뭉뚱그린 라벨**로 보인다. 등급 판정에 쓰면 안 된다.

## §1-4. 이건 「H\* 영웅 축 커버리지 갭」과 **같은 것이 맞다**

로우·아오키지·상디·루치가 안 잡힌 이유는 전부 같다 — **주인이 `H*` 영웅**인데
우리 CSV는 `h*` 축(`h01H` 특별함 로우 / `h02L` 희귀함 / `h03C` 전설적인)만 잡고 있었다.
`SKILL_COVERAGE_BY_GRADE.md` ④의 갭과 동일한 원인이다.

# ③ 도움소 `H0B7`의 `GetRandomInt(1,3)` 위치 — **`ForGroup` 바깥이다**

```jass
function Trig_Money_trade2_______u_Actions takes nothing returns nothing
    call RemoveUnit(GetSoldUnit())
    set udg_stat_int = GetRandomInt(1,3)                    ← 여기서 한 번만 굴린다
    if (udg_stat_int==1) then call ForGroupBJ(udg_Exp_Hero_Group[p], ...STR +1)
    if (udg_stat_int==2) then call ForGroupBJ(udg_Exp_Hero_Group[p], ...AGI +1)
    if (udg_stat_int==3) then call ForGroupBJ(udg_Exp_Hero_Group[p], ...INT +1)
```

`udg_stat_int`를 **한 번 굴려 전역에 저장**하고, 그 값으로 세 `if` 중 **하나만** 골라 `ForGroup`을 돈다.
→ **그 플레이어의 영웅 전원이 같은 스탯을 +1 받는다.** 구현담당3의 `f55ad4b`가 맞다.
