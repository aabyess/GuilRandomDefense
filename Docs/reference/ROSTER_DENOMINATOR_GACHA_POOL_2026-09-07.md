# "원작 로스터"의 진짜 기준 — `Trig_tier_Random`(원작 자신의 가챠 풀) 발견

조사: 리서치담당 / 2026-09-07, `war3map.j`(`Trig_tier_Random_Actions`)
직접 확인.
요청: PM — "원작이 스스로 어떻게 세는지"(도박 결과 풀·조합표)로 로스터
정의를 검증. 특별함 33 vs 42, 안흔함 14, 희귀함 48/45 갈림 해소.

## 결론 — **원작 자신의 가챠 풀을 찾았다. 이게 가장 권위있는 "로스터" 정의다**

`Trig_tier_Random_Actions`가 맵 초기화 시 **특정 사각형 안에 서
있는 유닛들을 그대로 등급별 랜덤 그룹(`udg_Random1`~`udg_Random5`)에
쓸어담는다** — 이게 원작이 "이 등급엔 이런 유닛들이 있다"를 직접
정의하는 자리다(이름 문자열 파싱이 아니라 **엔진이 실제로 뽑는
행위 그 자체**).

```jass
call ForGroupBJ(GetUnitsInRectAll(gg_rct_Ran0),function Trig_tier_Random_Func032A)     // → Random1
call ForGroupBJ(GetUnitsInRectAll(gg_rct_Ran_1),function Trig_tier_Random_Func033A)    // → Random2
call ForGroupBJ(GetUnitsInRectAll(gg_rct_Ran_2),function Trig_tier_Random_Func034A)    // → Random3
call ForGroupBJ(GetUnitsInRectAll(gg_rct_Ran_3),function Trig_tier_Random_Func035A)    // → Random3(같은 그룹)
call ForGroupBJ(GetUnitsInRectAll(gg_rct_Ran_4),function Trig_tier_Random_Func036A)    // → Random4
call ForGroupBJ(GetUnitsInRectAll(gg_rct_Ran_5),function Trig_tier_Random_Func037A)    // → Random4(같은 그룹)
call ForGroupBJ(GetUnitsInRectAll(gg_rct_Ran_6),function Trig_tier_Random_Func038A)    // → Random5
call ForGroupBJ(GetUnitsInRectAll(gg_rct_Ran_7),function Trig_tier_Random_Func039A)    // → Random5(같은 그룹)
call ForGroupBJ(GetUnitsInRectAll(gg_rct_Model_Pack_R1Unit),function ...Func040A)      // → Modelpack_R_unit
call ForGroupBJ(GetUnitsInRectAll(gg_rct_UniqueSpecial),function ...Func041A)          // → Random_UniqueSpecial
```
`Random4`는 이미 `unique_rerole`(희귀함 리롤)이 실제로 사용하는 걸로
확정된 풀이다 — 이 라인이 그 근거다.

## 방법 — 619개체 좌표 + 사각형 경계를 직접 대조

대조해 **어느 유닛타입이 어느 사각형 안에 서 있는지**를 계산했다
(문자열 매칭이 아니라 순수 기하 판정).

| 사각형 | 좌표 | 들어있는 유닛 수(종) | 목적지 그룹 |
|---|---|---:|---|
| `Ran0` | (-4352,-3904)~(-2016,-3712) | **9** | Random1 |
| `Ran_1` | (-768,-7168)~(-448,-3744) | **13** | Random2 |
| `Ran_2` | (608,-7648)~(832,-3776) | 17 | Random3 |
| `Ran_3` | (1888,-7456)~(2144,-3744) | 16 | Random3(합산) |
| `Ran_4` | (3264,-8352)~(3552,-3584) | 20 | Random4 |
| `Ran_5` | (4576,-8672)~(4864,-3808) | 22 | Random4(합산) |
| `Ran_6` | (5952,-8800)~(6240,-3456) | 21 | Random5 |
| `Ran_7` | (7360,-7424)~(7648,-3296) | 15 | Random5(합산) |

## ① 특별함 33 — **PM·구현담당1의 이름파싱과 완전히 독립적인 방법으로 정확히 일치**

이름에 "특별함" 들어간 전체 48기 중 "더미"/"위습" 포함 15기를 뺀
**33**(PM·구현담당1)과, **좌표로 잰 33**(이번 조사)이 정확히
일치한다. **서로 다른 두 방법(문자열 필터 vs 물리 배치)이 같은
숫자에 도달했다 — 33 확정.** 내가 앞서 낸 "42"는 색접미사만 보고
`h056`(노획물품)·`h061`(목재8필요)·`h063`/`h064`/`h09Y`(공격더미
3종)·`h06N`/`h06O`/`h07H`(장난감/전리품류)·`h08D`(금화마커) 등
**캐릭터가 아닌 항목 9개를 같이 세는 바람에 생긴 과다 집계였다** —
정정한다.

## ② 안흔함 13 — **PM의 "14"와 1명 차이, 그 1명이 `h00H`(좀비)다**

PM의 이름-필터는 14를 냈다(`h00A`~`h00O` 중 더미·위습 4기 제외).
**좌표 기준(가챠 풀)은 13이다 — `h00H`(좀비)가 빠진다.** 확인:
```
h00H 좌표: (Ran_1 사각형 밖)
```
**`h00H`는 이름에 "안흔함"이 붙어 있고 더미·위습 표기도 없어서
이름-필터로는 정상 캐릭터로 보이지만, 원작 맵에는 애초에 이
가챠풀 사각형 안에 서 있지 않다** — 즉 **원작 엔진 자신이 이
유닛을 "뽑을 수 있는 안흔함 목록"에서 빼놨다는 뜻**이다. 이건
오늘 다른 조사(`LOW_GRADE_ABILITY_ACTIVATION_2026-09-07.md`)에서
독립적으로 확인한 것과 정확히 들어맞는다 — **`h00H`는 `uabi`에
`A029`([조합] 버튼)만 있고 실전 능력이 0개인, 이미 "죽은 슬롯"으로
확인된 그 유닛이다.** 이름표는 안흔함이지만 **원작 스스로도 이
유닛을 안 뽑는다** — 두 개의 독립된 신호(가챠풀 배치·능력 유무)가
같은 결론을 가리킨다. **안흔함 로스터는 14가 아니라 13이 맞다.**

## ③ 희귀함 — 45(이름, 정정) vs 42(가챠풀), 차이 3은 "히든/특수 별도경로" 3종

PM의 "48"은 재확인 결과 **더미 3개(`e0EL`U희귀함류마·`e0IR`U희귀함쵸파
— 둘 다 `base=ewsp`/`uabi=Aloc,Avul`뿐인 순수 더미, `h06O`장난감)를
"더미"라는 글자가 없다는 이유로 캐릭터로 잘못 셌다** — 이 3개를
빼면 **45**가 된다(이건 내가 `upoi=90`으로 낸 45와 정확히 일치).

**가챠풀(42)과 이름-필터(정정후 45)의 차이 3은 `h05X`(레일리)·
`h05Y`(고대의 배)·`h05Z`([히든]파이러츠 도킹6)다** — 이 셋은
`Ran_4`/`Ran_5` 사각형 밖에 있다. **이유는 이미 알고 있다** — 셋
다 표준 가챠(`unique_sell` 등급별 판매, `unique_rerole` 등)가 아니라
**완전히 별도의 전용 획득 시스템**(레일리=`h05Y` 도박, 고대의배=
`A023` 도박, 도킹6=히든조합)을 쓴다(이미 이번 세션 여러 문서에서
확정됨). **로스터에서 빠진 게 아니라 "표준 가챠 풀 밖의 특수
경로"라 이 사각형에 없을 뿐**이다.

**PM 질문("폼 변형이 도박 풀에 각각 들어가는가")에 대한 답 — 안 갈렸다,
왜냐하면 카이도·빅맘 폼 변형은 애초에 희귀함이 아니라 불멸의 등급이라
이 사각형(희귀함용)에는 안 나온다.** 불멸의 급 가챠풀이 있는지는
아래 ④에서 다룬다.

## ④ 상위 등급(전설적인·제한됨·초월함·영원한·불멸의)엔 이 방식의 가챠 풀이 없다

`Trig_tier_Random_Actions`가 실제로 채우는 그룹은 `Random1`~`Random5`
+`Modelpack_R_unit`+`Random_UniqueSpecial` **7개뿐**이다.
`udg_Random6`/`udg_Random7`은 선언만 되고 이 함수에서 한 번도 안 쓰인다
(전역에서 그 변수 자체가 다른 데서도 안 읽힌다, 사실상 죽은 변수로
보인다). **즉 이 "사각형에 세워두고 통째로 스캔" 방식 가챠는 흔함·
안흔함·특별함·희귀함·랜덤전용(다른세계) 5개 등급 전용이고, 상위
5개 등급(전설적인·제한됨·초월함·영원한·불멸의)은 이 메커니즘으로
안 뽑힌다.**

`Ran_6`+`Ran_7`(36기)은 좌표상 우연히 남는 사각형이라 "전설적인"으로
잠정 표시했지만, **이게 실제로 어디 쓰이는지(Random5가 어느 트리거에서
읽히는지)는 이번엔 확인 못했다** — `udg_Random5`를 읽는 자리를 못
찾았다(`Random1`~`Random3`을 읽는 `Func043~045A`는 확인했지만
전부 `dobakGroup1/2/3`이라는 또 다른 그룹으로 옮기는 것뿐이라 최종
소비처가 아니다). **`Ran_6`/`Ran_7`=전설적인은 `[미확정]`으로 남긴다.**

**상위 5개 등급의 "원작 로스터"는 다른 자기-기준으로 찾아야 한다** —
후보로 보이는 것: 이미 확인된 **밴 시스템 레지스트리**(`Eternal`
27종·`IM` 11종·`Forever` 7종·`Limited` 8종, `BAN_SYSTEM_SPEC_2026-09-07.md`)나
`ORIGINAL_HIDDEN_RECIPES.csv`(히든조합 결과물 목록) 쪽이 "상위
등급을 원작이 스스로 세는 곳"에 더 가까울 수 있다 — 이건 다음
조사로 넘긴다.

내가 결정 안 하고 둘 다 제시한다.
