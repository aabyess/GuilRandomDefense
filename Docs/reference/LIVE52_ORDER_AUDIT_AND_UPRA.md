# ① 기존 52행 — **2·3단계 감사 결과: 9행이 살아 있는 오차**

52행은 1단계(base 대조)와 4단계(게이트)만 돌았다. **2단계(`atar`)와 3단계(오더)를 돌렸다.**

| | 행 |
|---|---|
| ✅ 통과 | **41** |
| 🔴 **미작동 — 순수 연출** | **8** |
| 🔴 **피해 아님 — 공격력 증가** | **1** (`e055`, 앞서 보고) |
| 🟡 값은 맞으나 능력ID 오기 | **2행** (`e08G` 중복 행) |
| ✅ 작동 — **내 매핑 오류였다** | **1** (`e0CJ`) |

**2단계(`atar`)에서 걸린 행은 0이다** — 52행에 패시브류(`ACbh`/오라)가 없다. 전부 시전형이라 3단계가 판정했다.

### ⚠️ `e0DB`·`e0IP`는 **이중 계상이었다**

`ORIGINAL_SKILL_DAMAGE_TABLE.csv`에 이미 이 행들이 있다:
```
h02O,전설적인,골.D.에이스 해적왕의 아들,트리거,Trig_Legend18,200000.00,…
h02O,전설적인,골.D.에이스 해적왕의 아들,트리거,Trig_Legend18,400000.00,…
```
`e0DB`/`e0IP`의 200,000은 **같은 `Trig_Legend18`의 `ForGroup` 피해**다. 두 번 세고 있었다.

## 🟡 `e08G` — 값은 맞고 **능력ID가 틀렸다**

```
e08G uabi = A0X3(AIfb, Idam=50,000) · A0B3(AOws, Wrs1=50,000)
오더 = "stomp"  → AOws = A0B3
```
표는 `A0X3`로 적혀 있었다. **`stomp`는 `A0B3`에게 가고 `A0X3`(AIfb)는 미작동**이다.
두 능력의 값이 **우연히 둘 다 50,000**이라 **결과 수치는 맞다.** 능력ID만 `A0B3`로 정정했다.
(앞서 `Idam`을 `[미확인]`으로 남긴 건이 여기서 닫힌다 — 이 행의 근거는 `Idam`이 아니라 `Wrs1`이었다.)

## ✅ `e0CJ` — **내 매핑이 틀렸다. 이 행은 유효하다**

```
e0CJ uabi = A0LG(AOww, Oww1=180,000) 하나뿐
오더 = "whirlwind"
```
나는 `AOww`의 오더를 `windwalk`로 가정했다. **근거 없는 추측이었다.**
**더미가 한 능력만 갖고 오더가 하나뿐이면 그 오더는 그 능력을 향한다** — `AOww`의 오더는 `whirlwind`다.
**`e0CJ` 180,000은 그대로 유효하다.**

> 📌 이 두 건(`e08G`·`e0CJ`)이 검사 자체의 한계를 보여준다.
> **오더 문자열 ↔ base 매핑표는 내가 만든 것**이고, 틀리면 멀쩡한 행을 죽인다.
> 그래서 **걸린 10건을 전부 코드로 직접 읽었다.** 자동 판정만 믿었으면 2건을 잘못 지웠을 것이다.

## 요약 — 지금 게임에서 도는 오차

# ② 원작 주스탯(`upra`) 분포

## 1. 분포 — **39기** (36기 + `upra` 없는 3기)

| | STR | AGI | INT | 계 |
|---|---|---|---|---|
| **`upra` 명시 36기** | **11** | **10** | **15** | 36 |
| `upra` 없는 3기 (`Hvwd` 기반, 워든의 주스탯 상속) | 0 | **3** | 0 | 3 |
| **합계** | **11** | **13** | **15** | **39** |

`upra` 없는 3기는 성장치로 주스탯이 드러난다: `H05N` 타시기(0.42/**1.70**/0.42) · `H0BD`·`H0BE` 야마토(0.21/**1.06**/0.21) — 셋 다 **AGI**.

## 2. 등급별

| 등급 | STR | AGI | INT | 계 |
|---|---|---|---|---|
| **초월함** | **11** | **12** | **15** | **38** |
| **영원한** | 0 | **1** | 0 | **1** |

**스탯을 가진 원작 유닛은 초월함 38기 + 영원한 1기(`H0BK` 루피-기어피프스)뿐이다.**
그 아래 등급에는 영웅 스탯 축 자체가 없다 → **초월함 이상에만 배정하면 된다.**

비율로: **STR 28% · AGI 33% · INT 38%** (거의 1:1:1, INT가 약간 많다).

## 3. `GetHeroStatBJ`를 읽는 스킬 30건 — **25건은 주스탯, 예외는 타시기 5건**

| 유닛 | 주스탯 | 읽는 스탯 · 계수 | 판정 |
|---|---|---|---|
| `H0BT` 조로 | STR | STR ×50,000 / 21,000 ×2 / 15,000 / 7,500 / 7,000 / 6,000 | ✅ |
| `H0B4` 키드 | STR | STR ×50,000 / 20,000 / 5,000 ×2 | ✅ |
| `H090` 티치 | STR | STR ×50,000 / 3,000 / 2,000 ×2 | ✅ |
| `H09A` 징베 | STR | STR ×17,500 | ✅ |
| `H092` 사보 | STR | STR ×15,000 | ✅ |
| `H09D` 도플라밍고 | STR | STR ×10,000 | ✅ |
| `H095` 아카이누 | STR | STR ×5,000 | ✅ |
| `H0BL` 초록소 | INT | INT ×5,000 | ✅ |
| `H08V` 나미 | INT | INT ×3,500 | ✅ |
| `H0B5` 키자루 | AGI | AGI ×3,500 | ✅ |
| **`H05N` 타시기** | **AGI** | AGI ×5,000 ×3 ✅ / **STR ×6,000 · 4,000 · 3,500 · 2,500 ×2** | 🔴 **5건이 부스탯** |

### 🔴 예외는 **타시기 하나뿐**이고, 그게 시작 스탯의 이유다

타시기 `H05N`은 **원작에서 시작 스탯이 0이 아닌 유일한 유닛**(STR **10** / AGI 11 / INT 1)이다.
성장은 AGI 1.70(주스탯)이지만 **스킬 5건이 STR을 읽는다.**

**제작자가 STR 기본값 10을 준 이유가 이것이다.** 성장이 0.42뿐이라
레벨 24에도 STR = 10 + 0.42×23 = **19**밖에 안 되는데, 시작값 10이 없었으면 레벨 1에서 STR 0 → **모든 STR 스킬이 0**이 된다.

| 레벨 | 타시기 STR | ×2,500 | ×6,000 |
|---|---|---|---|
| 1 | 10 | 25,000 | 60,000 |
| 24 | 19 | 47,500 | 114,000 |

→ **구현 시 「AGI 주스탯 + STR 시작 10」을 한 세트로 옮겨야 한다.** STR 기본값을 0으로 두면 이 유닛의 스킬 5건이 초반에 죽는다.

## 4. 배정에 바로 쓸 요약

- **대상 등급**: 초월함 38기 + 영원한 1기. 그 아래는 스탯 축 없음
- **분포**: STR 11 : AGI 13 : INT 15 (28% : 33% : 38%)
- **성장**: 주스탯 **+0.85** / 나머지 **+0.21** (전 유닛 동일). 예외 3기 — 타시기 0.42/**1.70**/0.42, 야마토 0.21/**1.06**/0.21
- **시작 스탯**: 전부 **0/0/0**. **타시기만 10/11/1**
- **계수 배정 원칙**: 유닛의 주스탯을 읽는 스킬에 큰 계수(50,000급)를, 부스탯을 읽는 스킬에 작은 계수(2,500~6,000)를 준다 — 타시기가 정확히 그 형태다(AGI 5,000 vs STR 2,500~6,000)
