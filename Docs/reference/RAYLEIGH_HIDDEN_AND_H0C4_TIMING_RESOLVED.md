# 레일리 히든 판매 정체 + H0C4(항법) 배치 시점 확정

조사: 리서치담당 / 2026-09-06
요청: PM — 「`UPGRADE_SHOP.md` "레일리 히든 아이템 판매"가 `IM_lailiey1`과
같은 것인지, 38종 아이템에 대응이 있는지」+「`H0C4` 배치 시점」

## ① "레일리 히든 아이템 판매" — **`IM_lailiey1`과 다르다. 아이템도 아니다.**

원작 로스터에 "레일리"란 이름의 유닛이 **최소 4종** 있다(전부 `unam`
원문 확인):

| 유닛ID | 등급 | 비고 |
|---|---|---|
| `h03A` | 전설적인 | "로저해적단 부선장" — 일반 로스터 등급 |
| `h049` | 불멸의 | "명왕" — **`IM_lailiey1`, 채팅언락 결과유닛(어젯밤 스윕 대상)** |
| `h05J` | 불멸의 | "명왕...소환됨" — 전투중 일시소환용 변형(별개 인스턴스) |
| **`h05X`** | **희귀함** | **"[히든]...세계의 진실을 아는 자" — 여기가 정답** |

**`h05X`가 "레일리 히든 아이템 판매"의 정체다.** `h05X`의 능력 목록
(`uabi`)에 **`A0OE`("판매-특수")**가 있다 — `war3map.w3a` 툴팁 원문:
`"특수 유닛을 판매합니다. ◎판매시 흔함 선택위습 1기 획득 ◎특성포인트 1
획득 ◎시전시간 3초"`. **이건 아이템이 아니라 "이 유닛을 판매하면"
발동하는 능력이다** — `UPGRADE_SHOP.md` §5의 "판매-특수" 항목이 바로 이거고,
그때 이미 "레일리라는 이름이 직접 나오진 않는다"고 정확히 적어뒀던 게
맞았다(대신 소유 유닛이 `h05X`라는 걸 이번에 확정).

**`h05X`를 얻는 법**: `war3map.j`의 `CreateBuildingsForPlayerN`류 맵초기화
함수에 `CreateUnit(p,'h05X',...)` 직접 배치가 2곳 있다 — **게임 시작 시
맵에 미리 놓여 있는 유닛**이다(도박/조합으로 얻는 게 아니라 처음부터
존재). 판매하면 위습1+특성포인트1, 아니면 다른 조합 재료로도 쓸 수
있다(`h05X,h028,h018` 조합 레시피 하나 확인, 대사 "실버즈 레일리: 검을
쓰는건 오랜만이군" — 더 강한 폼으로 업그레이드하는 선택지도 있다는 뜻,
"팔 것이냐 더 키울 것이냐"의 트레이드오프로 보인다).

### 곁다리 — `!레일리 도박-고대의 배`(`A0OD`)는 진짜 못 쓰는 능력으로 보인다

`UPGRADE_SHOP.md`가 예전에 "27% 확률로 레일리 획득, 목재7"이라고 적어둔
그 능력(`A0OD`, base `Aroa`)을 이번에 다시 찾아 **어느 유닛의 `uabi`에도,
어느 트리거의 `UnitAddAbilityBJ`에도 안 걸려 있는지 전수 확인했다** —
`war3map.w3u`/`war3map.w3t`/`war3map.j` 전체에서 `A0OD`가 자기 자신의
w3a 정의 말고 **다른 곳에 0건.** ⚠️ 이건 어젯밤 `DisableTrigger` 오판과는
**다른 종류의 신호다**(트리거 활성상태가 아니라 "이 능력을 가진 유닛이
아예 없다"는 정적 소유권 부재라 더 강한 신호이지만, 그래도 단정하지
않는다) — **`[미확인, 접근 불가 가능성 높음]`으로만 남긴다.** "고대의
배 판매 → 특성포인트"(8갈래 목록)는 이 도박 능력과 이름이 겹쳐서 혼동된
것으로 보이며, 실제 특성포인트 경로는 위 `A0OE`(판매-특수) 쪽이 맞다.

### 38종 아이템 대조 — **없다, 아이템 아님이 이걸로 재확인**

`ITEM_POOL_FULL_CENSUS.md`의 38종(`I000`~`I011`) 테이블 전체에 "레일리"
관련 항목 0건 — "레일리 히든 아이템"이라는 이름과 달리 **애초에 아이템
계열이 아니었다**는 게 최종 확정이다.

## ② `H0C4`(항법 선택 건물, "항해일지") 배치 시점 — **게임 시작 시, 맵초기화 단계**

`H0C4`(내부 이름 `unam`="항해일지", 모델 MagicVault, `uabi=Asud,AHta,AInv,Avul`
— 전투 없는 순수 UI건물)는 `CreateBuildingsForPlayer1`/`CreateBuildingsForPlayer3`
(그리고 대칭적으로 2·4번도 있을 것) 함수에서 `H089`(다른 시작 건물)와
**나란히, 게임 시작 맵초기화 시점에 직접 배치된다**(라운드/퀘스트/트리거로
나중에 "열리는" 게 아니다):

```
function CreateBuildingsForPlayer1 ...
  set gg_unit_H089_0464 = CreateUnit(p,'H089',...)
  set gg_unit_H0C4_0702 = CreateUnit(p,'H0C4',...)
endfunction
```

**결론: 항법은 라운드1부터 즉시 선택 가능하다.** 별도 언락 조건이나
"몇 라운드부터 열림" 같은 게이트가 없다 — 게임 시작하자마자 이 건물이
있고, 5개 스킬트리 버튼 중 하나를 배우면(`EVENT_UNIT_HERO_SKILL`) 그
즉시 확정되는 구조(`NAVIGATION_ROUTES_FULL.md` 기존 조사와 일치).
구현 관점: **씬 시작 시 즉시 선택 UI를 노출하면 된다**, 라운드 진행
트리거에 걸 필요 없다.
