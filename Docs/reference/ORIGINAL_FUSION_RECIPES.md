# `ORIGINAL_FUSION_RECIPES.csv` — 무엇을 어떻게 걷었나

> 이 문서는 구현담당2가 작성했다. **CSV(`c9db45e`)와 그 커밋 메시지는 리서치담당이 만들었고,
> 나(구현담당2)는 만들지 않았다.** 여기 적은 내용은 그 커밋 메시지와 CSV 파일 자체에서
> 읽을 수 있는 것만 옮겼고, 모르는 부분은 전부 **"미확인"**으로 남긴다. 리서치담당 본인의
> 답이 오면 PM이 채운다.

## 무엇을 걷었나

`c9db45e`(리서치담당) 커밋 메시지: *"조합 엔진을 찾았다 — 'Johab'이 아니라 `Fusion3___main`이었고,
조건이 트리거가 아니라 능력 필드에 인코딩돼 있었다."*

CSV는 **144행**(헤더 제외, `wc -l` 145 확인)이다. **어떤 능력을 144개에 포함시켰는지의 정확한
필터 기준(예: 능력 이름에 `[조합]`이 들어가는 것만 걷었는지, `Fusion3___main` 템플릿을 쓰는
전부를 걷었는지)은 CSV 파일에도 커밋 메시지에도 명시돼 있지 않다.** PM이 정리한 배경 설명으로는
**"`[조합]`이라는 이름의 능력만 걷었다"**고 하는데, 이건 리서치담당 본인이 CSV나 커밋 메시지에
직접 쓴 문장이 아니라 PM이 전달한 요약이다 — **원 출처가 명시적으로 확인될 때까지 "미확인"으로
둔다.**

## 필드 의미표

CSV 헤더(BOM 포함, `능력ID,결과유닛ID,재료유닛ID들,재료개수들,골드,목재,툴팁원문`)와 커밋
메시지가 설명하는 원작 능력 필드의 대응:

| CSV 컬럼 | 원작 능력 필드 | 뜻 |
|---|---|---|
| 능력ID | (능력 자체의 ID) | `Fusion3___main` 계열 능력 하나의 식별자 |
| 재료유닛ID들 | `acat` | 재료로 쓰이는 유닛ID 목록(콤마 구분) |
| 재료개수들 | `alig` | `acat`과 병렬로, 각 재료의 필요 개수 |
| 골드 / 목재 | `asat` + `amat` | `asat`이 비용 종류(g=골드/w=목재)를 가리키고, `amat`이 금액이다.
CSV는 이미 `asat`으로 분류해서 골드·목재 두 컬럼으로 나눠 저장했다(리서치담당이 이미 해석해둔 것 — 원본 `asat`/`amat` 원시값 자체는 CSV에 없다) |
| 결과유닛ID | `atat` | 조합 결과로 나오는 유닛ID |
| 툴팁원문 | (능력 `aub1` 등 툴팁 텍스트) | 커밋 메시지: *"툴팁 원문(`aub1`)에 한글 캐릭터 이름이 그대로 들어 있다."* 재료ID 순서와 이름 순서가 나란해서 이 144개에 한해 유닛ID→이름 매핑이 풀렸다고 함(전면 해제 아님) |

## ⚠️ 알려진 한계

1. **`[조합]`(또는 유사) 이름을 안 쓰는 조합 경로가 있으면 이 144개에 안 걸린다.** 이게 이번
   불멸·영원·제한(강보명·김강민) 사례로 실제로 의심되는 지점이다 — 아래 "열려 있는 불일치" 참고.
2. **필터 기준 자체가 이 저장소 어디에도 재현 가능한 형태로 남아있지 않다**(위 "무엇을 걷었나"
   참고). 지금은 CSV 파일과 PM의 요약을 신뢰하는 것 외에 검증 수단이 없다.
3. `asat`/`amat`의 원시값(가공 전)이 CSV에 없어서, "골드"·"목재" 두 컬럼으로의 분류 자체가
   맞았는지 이 CSV만으로는 재검증할 수 없다.

## 열려 있는 불일치 — 불멸·영원·제한 3건

`Docs/reference/RECIPES.md`(사장님이 08-29에 제공한 조합표 이미지 4장을 전사한 문서,
`Docs/reference/combine-table/03_불멸_영원_제한.png` 등)에는 있는데 이 CSV 144개엔 없는 것 —
구현담당2가 직접 확인:

```
grep -c "정윤식|김용태|정준영|박은석|신지우|이승우|고도현|이이삭" ORIGINAL_FUSION_RECIPES.csv → 0
grep -c "김영원|조세민|이지원|문필환|서민성|김정래|윤현모"          ORIGINAL_FUSION_RECIPES.csv → 0
grep -c "강보명|김강민"                                              ORIGINAL_FUSION_RECIPES.csv → 0
grep -ci "save|라운드"                                                ORIGINAL_FUSION_RECIPES.csv → 0
```

- **불멸 7종의 "목재 10"** — 144개 CSV에 해당 인물이 전혀 등장하지 않는다.
- **영원 7종의 세이브 요구(5~35회)** — 위와 동일, "Save"라는 단어 자체가 CSV에 0건이다.
- **제한 "강보명"(41라운드 이전 조합가능)·"김강민"(골드 전용)** — 위와 동일, 전혀 등장하지 않는다.

**세 그룹 다 CSV에 아예 안 걸렸다는 사실 자체는 확인됐다.** 이게 (a) 144개 필터에서 애초에
빠진 것인지, (b) 원작에 이 조합 자체가 다른 방식(예: 트리거, 다른 능력 템플릿)으로 존재하는
것인지는 **미확인이다.**

## 결론 — 미해결

`c9db45e` 커밋 메시지의 "원작 조합에는 라운드 제한도 세이브 요구도 없다"는 **이 144개 안에서는
사실이지만, 불멸·영원·제한 등급까지 포함한 전체 원작 조합 시스템에 대한 결론인지는 미확인이다.**
PM이 리서치담당에게 확인을 요청한 상태다 — 답이 오기 전까지 이 문서는 열어둔다.
