### 왜 재료로 못 쓰는지 — 원문 근거

히든/영원/IM/포에버 조합의 재료 판정 필터는 전부 두 조건의 `GetBooleanAnd`다:

```jass

Trig_Hidden_Bal_Func003Func010001001002002 : return GetOwningPlayer(GetFilterUnit())==GetTriggerPlayer()
```

맵 전체 조합 필터를 세어보면 **유닛ID 판정 586건 / 소유자 판정 586건 — 1:1로 정확히 짝**이다.
즉 **모든 재료 판정이 「내 것」만 센다.** `Player(7)` 소유인 전시용 3기는 어떤 조합에도 걸리지 않는다.

## ③ 확률의 정확한 형태 — 「실패 판정 먼저」 구조에 주의

도박 둘은 **확률이 두 단계**다. 순확률을 곧바로 쓰면 안 되고, 원작 순서를 지켜야 결과 분포가 같다.

```jass
Trig_Unit_Gemble_0_Actions:            (h06B 초급)
    if GetRandomPercentageBJ()<=15.00 then   →  "실패 !"           (15%)
    else
        if GetRandomPercentageBJ()<=2.00 then →  h060 해적선        (85% × 2%  = 1.70%)
        else                                  →  udg_unit_dobakGroup1 에서 랜덤 유닛 (83.30%)

Trig_Unit_Gemble_2_Actions:            (h06C 중급)
    if GetRandomPercentageBJ()<=30.00 then   →  "실패"             (30%)
    else
        if GetRandomPercentageBJ()<=3.50 then →  h060 해적선        (70% × 3.5% = 2.45%)
        else                                  →  udg_unit_dobakGroup2 에서 랜덤 유닛 (67.55%)
```

랜덤 뽑기는 한 단계다. `GetRandomPercentageBJ()<=0.24` → **0.24%**, 성공하면 일반 유닛 분기를 통째로 건너뛴다.

## ④ 툴팁이 코드와 다른 곳 2건 `[파일확인]`

「원작 툴팁 ≠ 원작 동작」이 또 나왔다. **코드 쪽이 맞다.**

| 능력 | 툴팁 | 실제 코드 |
|---|---|---|
| `A16Z` 폐함대선 판매 | 「25%확률로 목재 1 획득 또는 25%확률로 해적선 획득」 | `<=50.00` → 목재1, **else 해적선** = **50 / 50** |
| `A0OD` 레일리 도박 | 「27% 확률로 레일리를 획득」 | `GetRandomInt(1,100)<=25` = **25%** |

(해적선 도박 `A023`의 40%, 도박 유닛의 85%·70%는 툴팁과 코드가 일치한다.)

## ⑤ 그 밖에 확인해둔 것

- **해적선을 파는 곳은 없다.** 유닛 1,559종의 모든 문자열 필드를 훑어 `h060`이 `useu`(판매 유닛)·`utra`(훈련)·`ubui`(건설) 어디에도 없음을 확인했다.
- **도박 풀에도 없다.** `udg_Modelpack_R_unit`←`gg_rct_Model_Pack_R1Unit`, `udg_unit_dobakGroup1`←`Ran0`+`Ran_1`, `dobakGroup2`←`Ran_2` — 이 rect 4개의 범위를 3기의 좌표와 대조했고 **하나도 안 걸린다.**
- **변수를 통한 간접 생성도 없다.** `set udg_… = 'h060'` 형태의 대입이 맵 전체에 0건이라, 위 9곳의 리터럴이 전부다.
- **처분 경로**: 해적선이 가진 `A0BB` 「판매-특수」 → 「흔함 선택위습 1기 + 목재 1」. 되파는 값이 있다.
- **고대의 배(`h05Y`)는 1회용**이다. `A023` 시전 시 성공·실패 양쪽 다 `RemoveUnit(GetTriggerUnit())`을 부른다. 획득처는 두 곳 — 아이템 `I00S` 사용(`Trig_item_up2`), 스토리 7단계 보상(`Trig_Story_reward7`, 전 플레이어에게 6000엔·목재4와 함께 지급).
- **아이스버그 `A0Q3`은 레벨 3까지 정의돼 있지만 레벨 3에는 도달할 수 없다.** 레벨 2에서 쓰면 트리거가 능력을 제거하므로 「0번 사용가능」 툴팁은 죽은 표기다.

## ⑥ 크립 보상의 함정 — 조건과 수령자가 다른 축이다 `[파일확인]`

```jass
Trig_creep_reward_Func002Func002C:
    udg_creep_Logic[ GetConvertedPlayerId(GetOwningPlayer(GetKillingUnitBJ())) ] == false   ← 죽인 플레이어

Trig_creep_reward_Actions (그 안):
    CreateNUnitsAtLoc(1,'h060', ConvertedPlayer(GetUnitUserData(GetTriggerUnit())), …)      ← 크립의 UserData 플레이어
    udg_creep_Logic[ GetConvertedPlayerId(ConvertedPlayer(GetUnitUserData(GetTriggerUnit()))) ] = true
```

**조건은 「죽인 사람」으로 보고, 보상과 1회 플래그는 「크립에 적힌 사람」에게 간다.**
남의 크립을 대신 죽여주면 조건은 내 플래그로 통과하고 보상은 크립 주인이 받는 상태가 만들어진다.
원작 버그인지 의도인지는 판단하지 않는다 — **원문이 이렇게 적혀 있다는 것만 기록한다.**
