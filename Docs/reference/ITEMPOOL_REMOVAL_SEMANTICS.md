# `ItemPoolRemoveItemType` 적용범위 전수 — I00S만 특별한 게 아니다, 전부 이렇다

조사: 리서치담당 / 2026-09-07
요청: PM — 아이템풀 제거가 `I00S`만인지 전체인지, 플레이어별인지
전역인지, 리필이 있는지.

## 결론 — **전부 제거가 맞다. 우리 `Roll()`을 다시 짜야 한다.**

## ① 전수 — 18곳 전부, 예외 없이 "방금 뽑힌/지급된 그 종류만" 제거

`ItemPoolRemoveItemType` 전체 18개 호출을 전부 나열했다. **패턴이
100% 동일하다**: `ItemPoolRemoveItemType(itpool[플레이어인덱스],
GetItemTypeId(방금생성된그아이템))` — **두 번째 인자가 항상 "직전에
만든 그 아이템의 타입"이다. 전체 풀을 비우는 호출은 하나도 없다.**

| 호출부 | 몇 회 | 무엇을 지울 때 |
|---|---|---|
| `ItemGet`/`ItemGet2`(실제 굴리는 함수) | 4회(각 함수당 전체+축소풀 2번씩) | **매번 굴린 직후, 그 아이템 타입을 굴린 사람의 풀에서 지운다** |
| `Trig_item_Gemble_Actions`(`H0BS` 도박) | 3회 | 도박 결과로 나온 아이템 타입 |
| `Trig_BossReward_Actions` | 5회 | 보스가 주는 확정 아이템 각각 |
| `Trig_Story_reward4~9_Actions`(6개) | 6회 | 스토리 보상으로 확정 지급되는 아이템 |
| `Trig_Quest_waporu`/`Trig_Quest_garp` | 2회 | 퀘스트 보상 아이템 |

**`I00S`를 특정해서 지우는 코드는 없다** — `I00S`가 `Trig_item_Gemble_Actions`나
`ItemGet`/`ItemGet2`로 뽑히면, **다른 21개 아이템과 완전히 같은 방식으로**
그 풀에서 사라질 뿐이다. **`I00S`는 특별하지 않다 — 아이템 38종
전체가 같은 규칙을 따른다.**

## ② 플레이어별인가 전역인가 — **플레이어별이다**

`itpool[0..10]`은 `Trig_ItemPooL_Actions`에서 `for i=0..10: set itpool[i]=CreateItemPool()`로
**11개의 서로 다른 `itempool` 오브젝트**를 만든다(WC3 네이티브
`CreateItemPool()`은 호출할 때마다 새 핸들을 반환한다 — 별칭이
아니다). 모든 `ItemPoolRemoveItemType` 호출이 `itpool[해당플레이어의
인덱스]`(`pid`/`pid+5`/`BossRectInt`/`GetForLoopIndexA()` — 전부 그
트리거를 유발한 **특정 플레이어**를 가리킴)만 건드린다.

**한 플레이어가 아이템을 뽑아도 다른 플레이어의 풀(`itpool[다른pid]`)은
전혀 안 건드려진다** — 4인 게임에서 각자 독립적인 22종/13종 풀을
갖는다. (이미 어제 "2단계×플레이어슬롯" 구조로 확인한 것과 일치,
이번엔 "제거"쪽까지 같은 결론임을 재확인.)

## ③ 리필 있는가 — **없다, 게임 시작 1회뿐**

`ItemPoolAddItemType` 전체 35회 호출(22+13개 아이템×1세트)이 **전부
`Trig_ItemPooL_Actions` 한 함수 안에만 있다.** 다른 어디에도
`ItemPoolAddItemType`가 없다 — **라운드마다도, 어떤 이벤트로도 절대
다시 안 채운다.** 이 함수 자체도 `ExecuteFunc("Trig_ItemPooL_Actions")`로
**맵 로드 시 딱 한 번만** 실행된다(vJass 스타일 라이브러리 초기화
체인의 일부, `TimerUtils___init` 등과 나란히).

## 최종 그림

```
게임 시작: 플레이어마다 전체풀(22종)+축소풀(13종) 각 1세트 생성
아이템을 얻을 때마다(도박이든 확정지급이든): 그 종류가 그 플레이어의
  풀에서 영구히 사라짐 — 재보충 없음
한 플레이어가 38종 중 이론상 얻을 수 있는 서로 다른 아이템은
  풀 소진과 함께 줄어들고, 다 뽑으면(또는 확정지급으로 미리 빠지면)
  그 아이템은 그 플레이어에게 두 번 다시 안 나온다
```

**우리 `Roll()`이 제거를 안 한다면, 같은 아이템이 무한히 중복으로
나올 수 있다는 뜻이라 원작과 다르다** — 구현담당2가 확인 중인 대로
"뽑을수록 줄어드는" 쪽이 맞다. **플레이어별로 독립된 풀 상태를
유지해야 하고(전역 공유 아님), 리필 로직은 만들면 안 된다(원작에
없음).**
