# 02번 밀도 재측정 — 원작과 같은 규칙("한 스킬 = 한 이름의 능력/트리거")으로 다시 셈

기존 `DENSITY_DECISION_ANALYSIS_2026-09-06.md`는 SkillData 파일의 raw `effects:` 블록 수를
셌다 — 원작 쪽(리서치담당, `한 스킬 = 한 이름의 능력/트리거`)과 단위가 달랐다(사과와 오렌지).
이 문서는 **우리 쪽도 같은 단위(원작 능력ID 개수)로 다시 세서** 1:1 비교한다.
그 파일은 건드리지 않고 이 문서를 새로 만든다.

## 방법

- 대상: `Assets/Data/Units/Roster/*.asset`에 `skill`/`skills`로 배선된
  `SkillData_원작능력_*.asset` + `SkillData_더미채널_*.asset` (재사용:
  `Tools/check_assignment_invariants.py`의 `resolve_skill_guids`/`build_guid_index`).
- 파일 하나가 대표하는 **원작 능력ID 개수** = `max(설명 안 bullet의 고유 AXXXX 개수,
  description 안 "→ AXXXX)" 인용의 고유 개수)` — 두 표기 중 어느 쪽도 완전하지 않다는 게
  이번 세션에 이미 확인됐다(11→21 파일 과소집계 사고) 그래서 더 큰 쪽을 쓴다. 둘 다 0이면
  (2차 배정 없이 그 자체로 완결된 능력 하나) 1로 센다.
- **cross-file 중복 능력ID는 안 지운다** — 두 로스터 유닛이 같은 스톡 능력 값을 원작에서
  각자 다른 캐릭터로 받은 경우(04번·`DENSITY_DECISION_ANALYSIS.md`③ 기준3의 그 사례들)라
  실제로 두 원작 능력이 맞다. 대신 목록만 뽑아 아래에 표시한다.
- 등급 그룹핑: 로스터 `grade:` 필드. `IsLadderGrade`(`Assets/Scripts/Data/UnitData.cs`)로
  `RandomUnit`(10)·`OtherWorld`(11)·`TranscendentWisp`(13) 제외(03번 확정).
- 원작 쪽 등급별 수치는 `Docs/reference/UNCOVERED_18_UNITS.md`의 **★★★ 최종 확정판**
  표(176/309·406개·2.31, 오더 재검증 반영 최신판)에서 그대로 인용 — 다시 안 잰다.
- 로스터 결손(별개 축)은 `Docs/reference/BLOCKERS_AND_ROSTER_DEFICIT.md`에서 인용.

## 결론 — PM 지정 5개 등급, 「원작에서 높다」가 아니라 「우리가 원작보다 높다」로 재확인

같은 규칙(등급평균 = 총능력ID/로스터 유닛수, 코버리지·밀도를 한 숫자로 합침)으로 다시
잰 결과, **사장님이 고른 5개(안흔함·특별함·초월함·불멸의·영원한) 전부 여전히 「우리가
원작보다 높다」** — 아무것도 「이미 일치」나 「결손」으로 뒤집히지 않았다. 다만 배율 차이가
꽤 크다:

- **불멸의(2.64배)·초월함(2.20배)·안흔함(2.33배)** — 여전히 뚜렷하게 과잉. 기준3 대상
  1순위로 유지.
- **특별함(1.28배)** — 여전히 과잉이지만 배율이 작다. 다른 넷보다 우선순위 낮음.
- **영원한(1.36배)** — PM이 우려한 대로 마진이 크게 줄었다(과거 추정 "75%→100%"로 보유율만
  보면 이미 따라잡은 것처럼 보였지만, 등급평균으로 다시 재니 원작도 같이 100% 보유·보유당
  4.33으로 올라와 있어서 배율 자체는 1.36배로 남는다). **다섯 중 가장 약한 과잉** — 기준3
  적용 시 가장 작은 수량만 자르거나 제외를 사장님께 다시 여쭐 만하다.

**로스터 결손(별개 축, 절대 밀도 삭감과 섞지 말 것)**: 전설적인 −3·제한됨 −2·초월함 −9·
영원한 −1·불멸의 −7 = 총 −22(+랜덤전용 −5 별도, 사다리 밖이라 이 비교엔 안 넣음). 특히
**불멸의·초월함·영원한은 「과잉(밀도)」과 「결손(로스터 자리)」이 동시에 걸린 등급**이다 —
같은 등급 안에서 일부 유닛은 과적재, 로스터 자체는 원작보다 좁다는 뜻이라 기준3(대표화)
후보를 고를 때 결손이 큰 등급(초월함 −9, 불멸의 −7)은 자르는 여유가 더 적을 수 있다는
점을 참고할 것.

## 재현

```
Assets/Data/Units/Roster/*.asset → grade: 필드로 그룹, resolve_skill_guids로 배선된
SkillData guid 목록 → 각 파일에서 bullet(· AXXXX)과 citation(→ AXXXX)) 정규식으로
고유 능력ID 집합을 뽑아 유닛별로 합집합 → 등급별로 합산.
```
스크립트는 1회성(커밋 안 함) — 재현하려면 이 문서의 "방법" 절 그대로 다시 짜면 된다.
