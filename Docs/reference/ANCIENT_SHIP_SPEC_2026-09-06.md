# 05번 「고대의 배」 구현 사양 (사장님 확정 2026-09-06)

원작 근거는 `ORIGINAL_PIRATESHIP_SOURCES.csv` 2번 행(`Trig_Acient_Ship`)과 `PIRATESHIP_SOURCES.md`.
**수치는 전부 원작에서 읽은 것이고 지어낸 값이 없다.**

## 왜 기존 도박과 다른 구조인가

우리 도박 6종(`Assets/Data/Gambling/`)은 전부 **상점 버튼**이다 — `GamblingShop`에서 돈·목재를 내고 누른다.
고대의 배는 그게 아니다:

```
기존 도박   상점 버튼을 누른다        → 확률 → 유닛 지급        (버튼은 계속 남는다)
고대의 배   내가 가진 유닛이 스킬 시전 → 확률 → 유닛 지급        (그 유닛이 사라진다)
```

**시전자가 곧 비용이다.** 그래서 `GamblingOptionData`에 옵션 하나를 더 얹는 걸로는 안 되고,
**「유닛이 스킬을 써서 자기를 소모한다」는 경로**가 새로 필요하다.

## 원작 동작 — `Trig_Acient_Ship`

| 항목 | 원작 값 |
|---|---|
| 시전자 | `h05Y` 고대의 배 |
| 진입 | `GetSpellAbilityId() == 'A023'` |
| 조건 | 목재 >= 4 |
| 비용 | **목재 4 — 성공·실패 양쪽 다 차감** |
| 확률 | **40.00%** (`GetRandomPercentageBJ() <= 40.00`) |
| 성공 시 | 해적선 1기, `udg_Mix_Loction`(조합 구역 중심)에 생성 |
| 소유자 | `GetOwningPlayer(GetTriggerUnit())` — 시전한 플레이어 |
| 횟수 | **고대의 배 1기당 1회** |
| 소모 | **성공·실패 양쪽 다 `RemoveUnit(고대의 배)`** — 배는 1회용 |
| 목재 부족 | **차감 없이 `stop` 명령만.** 배는 안 사라진다 |

⚠️ **실패해도 목재 4가 나가고 배도 사라진다.** 「실패 시 위로 보상」이 있는 우리 도박들과 반대다 —
`grantFailureReward` 같은 걸 붙이지 말 것. 원작에 없다.

⚠️ **목재 부족은 실패가 아니다.** 아무것도 차감하지 않고 아무것도 소모하지 않는다.
「조건 미달」과 「도박 실패」를 같은 경로로 처리하면 배를 잃는다.

## 고대의 배를 어떻게 얻는가 — 선행 문제

`h05Y`를 **얻는 경로가 우리에 없다.** 원작 단서 둘:
- `I00S` 고대의 배(희귀함) 아이템 — 「고대의배를 지급받습니다」 **지급형** (`EVENTS_FROM_MAP.md:126`)
- 스토리 9(어인섬) 클리어 보상 (`MISSING_SYSTEMS.md`)

**두 단서가 서로 다른 것을 가리킬 수 있다**(아이템 `I00S` ≠ 유닛 `h05Y`). 확정 전까지 **한쪽으로 굳히지 말 것.**
→ 리서치 요청 대상. 그때까지는 **유닛 `h05Y`와 그 시전 경로만 만들고, 지급은 임시로 열어둔다.**

## 우리 쪽 현황

- **해적선 유닛은 이미 있다** — `Assets/Data/Units/Roster/해적선.asset`. 새로 만들지 말 것.
- 확보된 해적선 경로 3개(뽑기 0.24% · 도박 초급 1.70% · 중급 2.45%)는 **이미 동작한다.**
  고대의 배는 **네 번째 경로**이고, **히든 6종 재료는 지금도 다 열린다** — 급하지 않은 이유가 이것이다.
- 원작 해적선 경로는 **총 9개**다. 우리가 3개, 이번에 4개가 된다. 나머지 5개(폐함대선 판매 · 아이스버그 조선 ·
  스토리5 보상 · 2단계 크립 · 맵 시작 배치)는 **각각 선행 시스템이 없어서** 이번 범위가 아니다.

## 구현 순서

1. **`h05Y` 고대의 배 유닛** — 로스터가 아니라 특수 유닛. 시전 능력 하나만 갖는다.
2. **시전 → 소모 경로.** 위 표 그대로. **목재 부족 분기를 먼저 만들고 검산할 것** — 여기서 틀리면 배를 잃는다.
3. **40% 판정 → 해적선 생성.** 생성 위치는 조합 구역 중심(우리 대응 위치 확인 필요).
4. 지급 경로는 **리서치 결과가 온 뒤.**

## ⚠️ 툴팁을 옮기지 말 것 (뿌리 ㉒)

이 표에서 원작 툴팁과 코드가 어긋난 사례가 **같은 CSV 안에 이미 있다**:
`Trig_sell_ship`(폐함대선 판매)은 **툴팁이 「25%/25%」인데 코드는 50/50**이다.
고대의 배의 40%는 툴팁과 코드가 일치하지만, **일치를 확인하고 쓴 것**이지 툴팁을 믿은 게 아니다.
