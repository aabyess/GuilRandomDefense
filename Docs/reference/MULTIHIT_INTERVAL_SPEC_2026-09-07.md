# 다단히트(hitCount>1) 원작 실제 동작 — 118건의 근사 사유 검증

조사: 리서치담당 / 2026-09-07, `war3map.j` 원문에서 "같은 RRD 값이
반복되는" 함수 9개를 표본으로 직접 추적.
요청: PM — 다단히트가 시간차를 두는지, 몇 초인지, 결과에 실질
영향을 주는지, 몇 가지 패턴인지. **축을 만들지 말지는 안 정한다,
원작이 뭘 하는지만 가져온다.**

## 결론 — **시간차가 진짜로 있다. 대부분 0.02~0.5초, 일부는 더 길다. 그리고 "hitCount>1"보다 더 큰 문제(가변 반복횟수)를 하나 더 찾았다**

## ① 메커니즘 — `Stage` 코루틴 + `SleepForStage`(네이티브 `TimerStart` 기반, 실제 초 단위)

`s__TrigVariables_SleepForStage(this, dur, stage)`는 이미 오늘 밤
확인한 그대로(`BAN_SYSTEM_SPEC_2026-09-07.md` ①) **네이티브
`TimerStart(...,dur,false,...)`를 그대로 부른다 — `dur`은 진짜
실시간 초다.** 다단히트는 **각 타격을 서로 다른 `Stage`에 배치하고,
그 사이를 `SleepForStage(dur, 다음Stage)`로 잇는 코루틴 루프**로
구현돼 있다. "Stage 분기는 다단히트를 표현하는 정상적인 방식"이라는
오늘 밤 다른 발견과 정확히 같은 구조다.

## ② 실측 간격 — 9개 표본, 0.01초~1.15초

`RRD(...)` 호출이 같은 함수 안에서 **같은 수치로 2번 이상** 나오는
함수를 `war3map.j` 전체에서 찾아 표본 9개를 골랐다. 각 함수의
`SleepForStage(...,dur,...)` 호출에 박힌 `dur` 값이 곧 그 단계
사이의 실제 대기시간이다.

| 함수 | 반복되는 값 | 실측 간격(초) | 비고 |
|---|---|---|---|
| `Trig_Tich1_danil_Actions`(h021, 검은수염) | 15000×2 | 0.01 / 0.13 | 넉백 유무로 갈리는 두 경로 각각 한 번씩(이미 확인된 그 함수) |
| `Trig_Legend26_tichi_crows_Actions` | 300000×2 | 0.02 / 0.07 | |
| `Trig_Ain_Skill_1_Actions` | 350000×2 | 0.46 / 0.25 / 0.05 | 첫 0.46초는 시전 애니메이션 대기(아래 ④ 참고), 실제 타격 간격은 0.25/0.05 |
| `Trig_Ain_Skill_2_Actions` | 350000×3 | 0.45 / 0.13 / 0.13 / 0.20 | 위와 같은 캐릭터의 강화판, 3연타 |
| `Trig_tahsigi_Actions`(타시기) | 500000×2 | **1.15**(첫 시전 대기) / 0.10(실 타격 간격) / 0.02 | 1.15초는 "공격 슬램" 애니메이션 재생 대기 — 타격 간격 자체는 0.10초 |
| `Trig_Tasigi_03_Actions`(타시기 3식) | 400000×"N"(아래 ③) | **0.10초 고정 간격으로 반복** | 루프 횟수가 고정 2가 아니라 가변(③) |
| `Trig_Nami_Skill_2_Actions` | 400000×2 | 0.16 | |
| `Trig_vivi_Skill_4_Mana_Actions`(비비) | 500000×2 | 0.10 / 0.02 / 0.05 | 이미 오늘 밤 확인한 그 함수(#1~#4 게이트) |
| `Trig_vivi_Skill_5_buff_Actions` | 400000×2 | 0.02 / 0.05 | |

**대부분 0.02~0.20초(눈 깜짝할 사이)이고, 두 건(`Ain_Skill_1`·
`tahsigi`)만 0.4~1.15초짜리 "첫 시전 대기"를 포함한다 — 그런데
그 긴 값은 대부분 "타격 사이 간격"이 아니라 "시전 애니메이션이
끝날 때까지의 대기"였다(②의 `tahsigi` 사례에서 직접 확인 — 1.15초
대기 뒤 첫 타격이 나가고, 그다음 진짜 타격 간격은 0.10초로 훨씬
짧다). **순수 "타격→타격" 간격만 추리면 표본 전체가 0.02~0.25초
범위 안에 들어간다.**

## ③ 🔴 더 큰 발견 — 반복 횟수 자체가 고정이 아니라 가변인 사례가 있다

`Trig_Tasigi_03_Actions`의 루프 지속 조건 원문:
```jass
function Trig_Tasigi_03_Func003Func002C takes nothing returns boolean
if(not(s__TrigVariables__get_integerB(GlobalTV)<(11+GetUnitAbilityLevelSwapped('Aamk',s__TrigVariables__get_unitA(GlobalTV)))))then
return false
endif
return true
endfunction
```
**반복 상한이 "11 + 캐스터의 `Aamk` 능력 레벨"이다 — 고정 2회가
아니라 최소 11회, 캐스터 스탯에 따라 더 늘어난다.** 우리 자산은
이 능력을 `hitCount: 2`로 근사해뒀다(원작 최소치의 5분의 1도 안 됨).
**이건 "타격 사이 간격 축이 없어서 생긴 근사"와는 다른 종류의
문제다** — 간격 축이 생겨도 **반복 횟수 자체가 상수가 아니라서**
그 축만으로는 못 고친다. 118건 중 이런 가변 루프형이 몇 건인지는
이번 표본(9개 중 1개)으로는 못 정하지만, **적어도 1건은 확인된
사실**이라 존재는 확정이다.

## ④ 결과에 실질 영향을 주는가 — **간격 크기에 따라 다르다, 상황별로 갈린다**

- **0.02~0.25초 범위(표본 대부분)**: 이 시간 동안 일반 라인몹이
  이동하는 거리는 미미하고(이동속도 400~600 기준 초당 4~6칸 정도면
  0.1초에 0.5칸 미만), 죽는 타이밍이 정확히 이 틈새에 걸릴 확률도
  낮다. **이 범위는 "즉시 N타"로 근사해도 실질 차이가 작을 가능성이
  높다.**
- **`tahsigi`의 1.15초 시전 대기**: 이건 "타격 간격"이 아니라
  "시전 준비 시간"이라 다단히트 판정과는 성격이 다르다 — 오히려
  이건 우리 스킬 시스템의 "쿨타임"이나 "캐스트 딜레이" 쪽 근사
  문제일 수 있어 이번 조사 범위(타격 간 간격) 밖이다.
- **`Tasigi_03`의 가변 반복(11회+)**: 간격(0.10초)이 짧아도 **횟수
  자체가 5배 이상 차이 나면 총 피해량이 크게 달라진다** — 이건
  간격보다 반복횟수 쪽이 더 큰 영향을 준다.

**결론: "간격을 재현할 축이 필요한가"라는 질문에는 표본 대부분(짧은
간격)에서 "영향 미미"에 가깝지만, 100% 확답은 아니다** — 적이 정확히
그 타이밍에 죽는 경계 케이스(라인몹 HP가 딱 그 사이값)에서는 즉시
N타(원작보다 항상 유리, 다 맞으니까)가 원작과 달라진다. **그리고
반복 횟수가 가변인 사례(③)는 간격과 별개로 지금도 틀려 있다.**

## ⑤ 패턴 — 최소 3가지로 갈린다(9개 표본 기준)

| 패턴 | 특징 | 표본 |
|---|---|---|
| **A. 고정 2연타, 짧은 간격(0.02~0.2초)** | 반복횟수 상수, 간격도 상수 | `Tich1_danil`·`Legend26_tichi_crows`·`Nami_Skill_2`·`vivi_Skill_5_buff` |
| **B. 시전대기+짧은 연타** | 첫 타격 전 긴 "준비" 딜레이(0.4~1.15초) + 그 이후는 A와 같은 짧은 간격 | `Ain_Skill_1`·`Ain_Skill_2`·`tahsigi` |
| **C. 가변 반복(캐스터 스탯 비례), 고정 간격** | 반복횟수가 상수가 아니라 `GetUnitAbilityLevelSwapped`로 늘어남 | `Tasigi_03`(11+레벨) |

**118건 전체가 몇 개씩 이 세 패턴에 속하는지는 이번 표본(9개)으로는
못 정한다** — 전수 분류하려면 118건 각각의 트리거를 열어 `RRD` 반복
여부와 `SleepForStage`/루프조건을 대조해야 한다, 이번엔 대표 사례로
구조만 확인했다.

## 남은 것 — `[미확인]`

- 패턴 B의 "시전대기"가 우리 스킬 시스템의 어느 축(쿨타임? 캐스트
  딜레이?)과 대응되는지 — 이번 조사 범위 밖.
- 패턴 C(가변 반복)가 118건 중 몇 건인지 — 최소 1건 확인, 전수는

## 판단은 PM 몫

**축을 만들지 여부는 안 정한다.** 다만 참고: 대부분(패턴 A, 짧은
간격)은 "영향 미미"로 보이므로 축 없이 "근사 아님, 원작과 실질
동일"로 재분류할 여지가 있다. **반대로 패턴 C(가변 반복횟수)는
간격 축과 무관하게 지금 값 자체가 원작보다 낮다** — 이건 다른
종류의 수정이 필요한 사안이라 같이 묶어서 판단하면 안 된다.
