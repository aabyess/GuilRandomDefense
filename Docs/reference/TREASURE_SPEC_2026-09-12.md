## 0. 트리거 전수 — "보물·탐색" 이름이 붙은 건 딱 하나뿐이다

`treasure`/`Treasure`/`search`/`Search`/`탐색`/`보물` 키워드로 전체 8,156개 함수명을 훑은
결과, **`Trig_treasure_*`(9개 함수) 하나뿐**이다. 다만 "탐색"이라는 능력을 쓰는 다른 유닛
전용 서브 트리거가 하나 더 있다(`Trig_sinobu_Exploration_*`, §6-2). 이름에 "탐색"이 없는
`sido`(시도) 계열(`Trig_Save_sido*`)은 세이브/로드 시스템이라 이 이벤트와 무관 — 검색은
됐지만 무관함을 확인만 하고 더 파지 않았다.

| 트리거 | 역할 |
|---|---|
| `InitTrig_treasure` | 플레이어 0~3의 `EVENT_PLAYER_UNIT_SPELL_EFFECT`(스펠 시전 완료)에 등록 |
| `Trig_treasure_Conditions` | 시전된 능력이 `AHta`(탐색)인지 체크 |
| `Trig_treasure_Actions` | 클릭 지점 주변에서 `n00H`(보물상자) 유닛을 찾아 `Trig_treasure_Func007A`를 실행 |
| `Trig_treasure_Func006002003` | 그룹필터 조건: `GetUnitTypeId()=='n00H'` |
| `Trig_treasure_Func007A` | **실제 보상 지급 로직 전부**(§4) |
| `Trig_treasure_Func007Func006/007/008C` | `udg_treasure`(1~3 랜덤값) 분기 조건 |
| `Trig_treasure_Func007Func009C` | `udg_treasurequest==9`(9번째 발견) 조건 |

## 1. 해금 조건 — 🔴 "10라운드 보스 처치 후"가 아니라 "10의 배수 라운드 시작 시"

보물상자(`n00H`)의 유일한 생성 코드는 `Trig_Round_10ver_Actions` 안, 다음 조건이 전부
참일 때다:

```
Stage[GlobalTV]==2               (Trig_Round_10ver_Func014C)
AND NOT Level==61                (Func014Func008C가 거짓 — 61이면 스킵)
AND Level<61                     (Func014Func008Func001C)
AND ModuloInteger(Level,10)==0   (Func014Func008Func001Func001C)
```

이 블록은 **보스 사망 여부와 무관하게, 그 라운드가 시작되는 시점에 곧바로** 실행되고,
**같은 스코프 안에서 그 직후 `ConditionalTriggerExecute(gg_trg_Enemy_Boss_create)`로 보스
전투도 같이 시작**한다(`75.40초 보스 타임리밋` 타이머도 이 블록에서 같이 켜진다). 즉
**보물상자는 10·20·30·40·50·60라운드가 시작될 때(보스전 시작과 동시에) 스폰되고, "보스를
잡아야 나온다"는 순서 관계는 코드에 없다.** `[파일확인]`

🔴 **"초고속 모드"는 이 맵에 존재하지 않는다.** `초고속`/`고속모드`/`speedmode` 등 어떤
철자로도 전체 JASS에 0건 — PM이 준 웹조사의 "초고속 모드는 1라운드부터 탐색 가능" 항목은
**근거가 없다.** 난이도 6종(쉬움~악몽, `DIFFICULTY_SPEC_2026-09-11.md`)과도 무관하게, 이
스폰 조건에는 `udg_Mode` 비교가 전혀 없다 — **난이도 무관, 항상 라운드 10/20/30/40/50/60
여섯 번뿐**이다. (61라운드 이후 "신세계" 구간엔 이 스폰 블록 자체가 안 돈다 — 신세계에서
보물상자가 새로 생기는지는 이번 조사로 못 찾았다, 관련 코드 0건 `[미확인]`.)

## 2. 탐색 조작 — 능력 `AHta`, 클릭 지점 기준, 쿨타임은 필드값 우선

`Trig_treasure_Conditions`가 잡는 건 `GetSpellAbilityId()=='AHta'` 하나뿐이다. `AHta`는
**단축키 R("탐색")**, `war3map_new.w3a`에서 직접 읽은 값:

| 필드 | 레벨1 | 레벨2 |
|---|---|---|
| `aare`(범위/AoE) | 750 | 750 |
| `acdn`(쿨타임, 실제 엔진값) | **100초** | **70초** |
| `adur`/`ahdu`(지속) | 3초 | 3초 |
| `aran`(사거리, `[엔진표준 추정]`) | (미지정, 상속) | **99999**(사실상 무제한) |

⚠️ **툴팁 텍스트(`aub1`)와 실제 필드값이 레벨2에서 다르다** — 툴팁은 "쿨타임 80초"라고
쓰여 있지만 `acdn` 필드의 실제 값은 **70초**다. 실행에 쓰이는 건 `acdn`이지 툴팁 문자열이
아니므로, **구현 시엔 70초를 써야 한다** — 이 맵 자체에 툴팁 오기가 있었다는 뜻이고, PM이
준 웹조사의 "쿨타임 100초"는 레벨1(기본) 값만 반영한 것으로 보인다(레벨2 존재를 몰랐을
가능성). `[파일확인]`

레벨2는 아이템 `I00K` 습득 시 부여된다(`Trig_item_up_Actions`:
`SetUnitAbilityLevelSwapped('AHta',GetTriggerUnit(),2)`) — 그 유닛 자신에게 걸리는
레벨업이라 **아이템을 먹은 유닛 개인** 단위다(플레이어 전체 아님). `[파일확인]`

`Trig_treasure_Actions`는 `GetSpellTargetLoc()`(클릭한 지점, 시전 유닛 위치가 아님)을
중심으로 `udg_treasure_range_int[pid]` 반경 내 `n00H` 전부를 찾는다 — **AHta 자체의
`aare`(750)가 아니라 별도 전역변수 `treasure_range_int`가 실제 탐지 반경으로 쓰인다**
(§5-2에서 이 값이 플레이어별로 나중에 바뀐다). `[파일확인]`

## 3. 보물 위치 — 단일 rect 내 완전 무작위, 사전 정의 좌표 목록 없음

```
gg_rct_treasure_chest_zone = Rect(-5856.0, -2400.0, 2464.0, 6080.0)   (맵에 딱 하나)
```

스폰 코드는 `GetRandomLocInRect(gg_rct_treasure_chest_zone)`를 **`udg_treasure_box_int`번
반복**해서 각기 독립적으로 뽑는다 — 이름표가 붙은 좌표 목록이나 서브존 배열은 없다.
`udg_treasure_box_int`는 기본 **7**(`InitGlobals`), 전설나미 조합 후 **9**(§5-2)로 전역
1회 변경된다(플레이어별 아님, 게임 전체 공용 상수). `[파일확인]`

⚠️ `AHta` 툴팁은 "창고,조합식 제외 랜덤한 위치"라고 적어 두었지만, **스폰 코드 자체에는
창고·조합식 지역을 걸러내는 조건이 없다** — 단일 rect 안에서 순수 무작위이므로, 창고·조합
구역이 실제로 제외되는 이유가 있다면 그건 **`gg_rct_treasure_chest_zone`이라는 rect 자체가
월드에디터에서 그 구역들을 미리 피해서 그려졌기 때문**이고, 런타임 필터링 로직은 아니다.
`[파일확인 — 배제 로직 0건]`

## 4. 찾는 판정과 보상표 — `Trig_treasure_Func007A` 전문 기준

`n00H`(보물상자)는 `Aloc`(Locust, 투명·선택불가) + 모델 `.mdl`(빈 모델) 유닛이라 **평소엔
전혀 보이지 않는다.** 판정은 순수하게: **클릭 지점으로부터 `treasure_range_int[pid]` 반경
내에 있는 `n00H` 전부**(유닛 종류 체크만, 시야·이동능력·탐지 조건 전혀 없음) — **원거리에서
찍어보는 "블라인드 서치"가 설계 의도**로 보인다. `[파일확인]`

🔴 **한 번의 시전으로 반경 내 상자가 여러 개면 전부 동시에 발견된다**(`ForGroupBJ`가 그룹
전체를 순회) — "1회 시전 = 최대 1개 발견"이 아니다. `[파일확인]`

찾은 상자마다 `udg_treasure=GetRandomInt(1,3)`으로 **1/3씩 균등 확률**로 세 보상 중 하나:

| `treasure` 값 | 보상 | 지급 유닛 | 지급 개수 |
|---|---|---|---|
| 1 (1/3) | 랜덤위습 | `e0IX` | `udg_TreasureChest[pid]`개(기본 1, §5-2 조합 후 2) |
| 2 (1/3) | 흔함선택위습 | `e018`, `gg_rct_StoryReward_Base1` 위치 | 〃 |
| 3 (1/3) | 안흔함 위습 | `e017`, `gg_rct_StoryReward_Base2` 위치 | 〃 |

보상은 **찾은 플레이어 개인에게만** 간다(`GetOwningPlayer(GetTriggerUnit())`). `[파일확인]`

## 5. 세이브 +2 / I002 카운트 — 전부 이 함수 맨 끝, 그러나 서로 다른 스코프다

`Trig_treasure_Func007A` 맨 끝은 **매번 상자를 찾을 때마다** 4인 전원을 도는 루프를 하나
더 돈다(보상 종류·treasurequest 값과 무관하게 항상 실행):

```jass
loop (1..4)
  call IncUnitAbilityLevelSwapped('A0MX', udg_Q_buliding_Cooperation[p])
  call SetItemCharges(udg_Item_Treasure[p], GetItemCharges(udg_Item_Treasure[p])+1)
endloop
```

**이 카운트는 발견한 사람만이 아니라 4명 전원에게 동시에 올라간다** — 즉 "누가 발견했는지"
와 무관하게 파티 전체가 공유하는 진행도다. `[파일확인]`

- `udg_Item_Treasure[p] = UnitItemInSlotBJ(udg_Q_Buliding[p], 1)`(모드선택 시 1회 대입,
  `Trig_Select_effect_Actions`). `udg_Q_Buliding[p]`는 `h07C` 유닛이고, 그 유닛의 슬롯
  0에는 게임 시작 시 정적으로 **`I002`("찾은 보물 개수")** 한 개가 놓인다
  (`UnitAddItemToSlotById(h07C,'I002',0)`, `CreateBuildingsForPlayer0~3`). `I002`는
  `war3map.w3t`에서 확인: `iabi='A109'`(⚠️ 무효과 스텁 — `item-research-traps` 메모리와
  동일 패턴), 순수 카운터용 아이템. `UnitAddItemToSlotById`의 슬롯 인자(0)와
  `UnitItemInSlotBJ`의 슬롯 인자(1)가 물리적으로 같은 슬롯을 가리키는지는 **이 두 네이티브의
  BJ 래퍼 소스가 맵 파일 안에 없어서(엔진 내장) 100% 확정은 못 하지만**, WC3 커뮤니티
  표준 관례상 `UnitItemInSlotBJ`가 1-인덱스를 0-인덱스로 변환해서 넘기는 게 일반적이라
  **`Item_Treasure[p] == I002` 인스턴스로 강하게 추정한다** `[엔진표준 추정, 상황증거로는
  거의 확정 — I002가 카운터 전용 스텁 아이템이라는 점과 완전히 일치]`. → **I002 충전량 =
  그 판에서 팀 전체가 지금까지 찾은 보물상자 총수.**
- `udg_treasurequest`(전역 정수, 플레이어 구분 없음)는 **상자를 찾을 때마다 무조건 +1**
  (`Trig_treasure_Func007A` 최상단). **정확히 9가 되는 순간**(`Func007Func009C`) 별도로
  "도전과제-트레저헌터" 완수 처리가 실행된다:
  ```jass
  전원에게 목재 +2, Q_buliding_Cooperation에서 A0MX 제거하고 A035로 교체(업그레이드 완료 표시),
  present_Save_playpoint[p] += 2, Save_playpoint[p] += 2   (전원, 루프 1~4)
  ```
  → **"세이브 +2"는 매 발견마다가 아니라, 팀 전체가 정확히 9번째 상자를 찾는 그 순간
  단 한 번만** 일어난다. `[파일확인]`

## 6. 탐색범위·보상 증가 — 나미(전설) 2배 보상은 실제로 있다, 단 "영원" 나미와는 다른 별개 유닛이다

### 6-1. 전설 나미(`h02P` 도둑고양이 나미, 능력 `A04X`) — PM 웹조사의 "2배 보상"이 정확히 여기서 나온다

`A04X` 툴팁 원문: *"도둑 고양이 나미를 한번이라도 조합했을 경우 탐색범위가 15% 증가하고
앞으로 보물 탐색 성공시 2배의 보상을 얻게 됩니다. 10라운드마다 리젠되는 보물상자의 개수가
2개 증가합니다(조합시 플레이어 전체 한번만 적용)."* — 이 세 문장이 `Trig_UnitJohabCounter_Actions`
(맵 전체를 도는 `UNIT_TYPE_GIANT` 진입 감지 트리거, `A04X` 레벨1 보유 + `Nami_legend_Boolean`
가드로 팀 전체 1회만 발동)의 실제 코드와 **전부 정확히 일치한다**:

```jass
udg_treasure_box_int      = 9        // 7+2, 툴팁의 "+2개"와 일치
udg_treasure_range_int[p] = 863.00   // 750×1.15=862.5≈863, 툴팁의 "+15%"와 일치
udg_TreasureChest[p]      = TreasureChest[p]+1   // 기본1→2, §4의 "지급 개수"가 그대로 2배가 됨
                                                   // = 툴팁의 "2배의 보상"과 정확히 일치
udg_Gold_Plus[p]          += 0.60    // 툴팁엔 없는 별도 보너스(공통 골드 배율)
```

**결론: PM 웹조사의 "나미(전설) 보유 시 보상 2배"는 사실이다 — 다만 그 실체는 "보상에
곱연산 2×를 거는" 게 아니라, "발견 시 지급 개수(`TreasureChest`)가 1에서 2로 늘어나는" 것이다.**
결과적으로 위습 개수가 정확히 2배가 되므로 체감상 완전히 동일하다. `[파일확인]`

### 6-2. 영원 나미(채팅 "날씨는맑음"/"nami tr" 획득) — 별개의, 더 큰 범위 보너스

`Trig_Eternal_Nami_Actions`(전설 나미와 무관한 별개 트리거, 채팅명령+5개 재료유닛 조건으로
나미를 **영웅으로 영입**)도 `treasure_range_int[p]`를 만진다: **`=940.00`으로 직접 대입**
(가산이 아니라 절대값 대입). 그 외 보상 배율·상자 개수 변경은 없다(§4 지급 개수엔 손대지
않음, `Gold_Plus`만 +0.20 별도 추가).

🔴 **둘 다 대입(`=`) 연산이라 가산되지 않는다** — 전설 조합(863) 후 영원 영입(940)이
일어나면 최종값은 940(더 최근에 실행된 대입이 이긴다), 반대 순서로 일어나면 최종값은
750이 아니라 여전히 863에 그친다(순서가 뒤바뀌면 863이 940을 못 덮어씀). **구현 시 이
순서 의존성을 그대로 두면 원작과 다른 결과가 나올 수 있다** — 두 이벤트의 실제 발생
선후관계(어느 게 먼저 오는 조합/영입 경로인지)는 이번 조사 범위 밖이라 `[미확인]`.

## 7. 모건(`h05H`)의 "100초마다 추가 탐색" — 근거 없음, AHta 쿨타임 오독으로 보인다

전체 JASS에서 `모건`/`Morgan`/`h05H`을 검색하면 **`CreateUnitsForPlayer7`의 정적 배치
1건뿐**이고, 모건 전용 트리거나 주기적 타이머는 0건이다. 모건의 `uabi`는 `AHta,A0EP,Avul`
— `AHta`는 §2의 그 "탐색" 능력 그대로(고유 능력이 아니라 다른 캐릭터들도 갖는 공용 능력),
`A0EP`("!탐욕-모건")는 평타에 11% 확률로 8배+마법피해 5만을 추가하는 **패스캐스트형
자동효과**(`base=ACbh`)로, 툴팁에 "◎탐색 사용 가능"이라는 문구가 있을 뿐 자동 재탐색과는
무관하다. **"100초마다 추가 탐색"은 AHta 레벨1의 쿨타임(100초)을 자동 발동으로 오독한
것으로 보인다 — 코드상 모건에게 주기적/패시브 탐색은 없다.** `[미확인 — 오히려 반증 근거 있음]`

## 5줄 결론 (PM 회신용 초안)

1. 상자는 "보스 처치 후"가 아니라 **10/20/.../60라운드 "시작"과 동시**에 스폰된다(보스전과
   겹침, 처치 여부 무관) — 난이도·모드 무관, "초고속 모드"는 이 맵에 없다.
2. 조작은 `AHta`(R키), 쿨타임은 툴팁(80초)이 틀렸고 실제 필드값은 L1=100초/L2=70초.
   상자는 Locust+빈모델이라 항상 안 보이고, 클릭 지점 반경 내 전부(제한 없이) 동시 발견됨.
3. 나미(전설, `h02P`)의 "2배 보상"은 실제로 있다 — 지급개수(`TreasureChest`)가 1→2로
   늘어나는 방식. 영원등급 나미 영입은 별개 트리거로 범위를 750→940 절대대입(가산 아님,
   순서의존).
4. I002는 발견마다 4인 전원 공용으로 +1(순수 카운터, 무효과 스텁), 세이브+2는 매 발견이
   아니라 팀 전체 9번째 발견 시점에 딱 한 번뿐.
5. 모건의 "100초마다 자동 탐색"은 근거가 없다(반증 있음) — 시노부(전설적인)의 별개 능력
   `A0YP`는 보상 없이 미니맵 핑만 하는 완전히 다른 시스템이니 혼동 주의.
