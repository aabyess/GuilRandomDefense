## ① `ItemPool` 구조 — 11개가 아니라 2단계×플레이어

```jass
function ItemGet takes unit v returns nothing
  local integer pid = GetConvertedPlayerId(GetOwningPlayer(v))
  local item it = PlaceRandomItem(itpool[pid], GetUnitX(v), GetUnitY(v))
  ...
function ItemGet2 takes unit v returns nothing
  local integer pid = GetConvertedPlayerId(GetOwningPlayer(v))
  local item it = PlaceRandomItem(itpool[pid+5], GetUnitX(v), GetUnitY(v))
  ...
```

`itpool[0..4]`(=`i<5`)는 **22종 전부**, `itpool[5..10]`은 **13종만**.
`pid`가 플레이어 인덱스라 **각 플레이어가 자기 전용 풀 사본을 쓴다**(공유
소모 아님).

### ① `H0BS` 비용·획득법 — **골드 0, "구매"가 아니라 스토리 보상으로 재고가 생긴다**

`H0BS` 자체 필드에 `ugol`(골드비용)=**0**이 명시돼 있다(값이 비어서 상속된 게
아니라 override로 0이 박혀 있음). 그런데 **아무 상점에도 `useu`(판매유닛
목록)로 안 걸려 있다** — 대신:

```jass
call AddUnitToStockBJ('H0BS', udg_Tech_Tree[플레이어], udg_Item_Int[플레이어]+1, 2)
```
**`udg_Tech_Tree[플레이어]`(그 플레이어 개인 상점 건물)의 재고로 직접
꽂아 넣는다.** 재고 수량 = `udg_Item_Int[플레이어]+1` — 이 카운터가 **도박
1회당 -1**, 그리고 **스토리 보상 트리거(`Trig_Story_reward6`·`_reward9`)에서
+1**된다. `Trig_Story_reward6`의 실제 내용을 열어보니:

```
"샤봉디제도까지의 스토리 진행완료 — 모든 플레이어에게 4000골드와 나무3개,
특별함 랜덤3기, 안흔함 랜덤2기를 지급합니다."
... udg_Item_Int[]+1, AddUnitToStockBJ('H0BS', 상점, Item_Int+1, 2) ...
```
**즉 골드로 반복 구매하는 게 아니라, 스토리 진행(챕터 단위)마다 도박 재고가
+1씩 늘어나는 구조다** — `A0LZ`(위습+목재)나 공격타입 축(골드3000)과는
완전히 다른, **"스토리 마일스톤 보상형" 획득 경로**다. 시작 시 `Item_Int=0`
이라도 `+1` 보정이 있어 **처음부터 1회는 항상 가능**하다.

**PM의 추측대로 도움소와 관련이 맞았다 — "항법"(원작 시작 시 고르는 진행
루트) 중 "도움소 잠금"을 선택하면 이 플래그가 켜진다.** 즉 **도움소를
포기하는 대가로 아이템 도박이 축소-13종(전설·초월·희귀 상위) 풀을 쓰게
된다** — 도움소 접근권과 아이템 도박 품질이 트레이드오프 관계다. 이건
"항법" 자체가 이미 `MISSING_SYSTEMS.md`가 정체 불명으로 닫아둔 3종 중
하나라, **항법 시스템을 다시 열 때 이 트레이드오프도 같이 반영해야 한다.**

### ③ `I00D`/`I00E`/`I00F`/`I00A` 게이트 — 이번엔 안 팠다(우선순위 3번, 시간상 보류)

### ④ 일반 몹처치 드랍 — **아니다, 확정**

`ItemGet`/`ItemGet2` 호출부를 `grep -c`로 재확인: **파일 전체에 정확히 3건**
(`ItemGet2`×1, `ItemGet`×2) — 전부 `Trig_item_Gemble_Actions`(도박)와
`Trig_Quest_sky_3_Actions`(스토리)뿐이다. **일반 몹 처치가 이 풀에서 아이템을
드랍하는 경로는 없다** — 재확인 완료, 결론 변경 없음.

### `I00L`(도움소 버스터콜) — **이중발동 우려 없음, 확정**

```jass
if GetItemTypeId(GetManipulatedItem())=='I00L' then
  set udg_item_Bustercall_bool[player]=true
endif
```
아이템을 습득하는 순간 **영구 플래그**만 켠다 — 별도의 독립 버스터콜 캐스트를
만드는 게 아니다. 이 플래그는 기존(이미 우리 게임에 있는) "전 게임 1회, 마나
500" 버스터콜 캐스트 트리거 **안에서** 읽혀 "성공 시 랜덤 대장 체력/마나/특성
스킬을 추가로 한 번 더 실행할지"만 결정하는 **보너스 애드온**이다(기존 세션
조사 "udg_item_Bustercall_bool → random 1-of-5 추가 트리거"와 정확히 같은
변수). **같은 입구의 보너스이지 두 번째 입구가 아니다 — 이중 캐스팅 위험
없음.**
