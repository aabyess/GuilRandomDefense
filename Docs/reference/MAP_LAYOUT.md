# 맵 구조 (사용자 제공, 2026-08-29)

> 원본 미니맵: `Docs/reference/map/00_minimap.png`
> 상세 이미지는 추후 추가 예정.

## 전체 배치

```
┌───────────────────────────────────────────────┐
│  ┌────────┬────────┐        ┌──┬──┐           │
│  │ 레인 1  │ 레인 2  │        │창1│창2│  ← 플레이어별 창고
│  ├────────┼────────┤        ├──┼──┤           │
│  │ 레인 3  │ 레인 4  │        │창3│창4│           │
│  └────────┴────────┘                          │
│      메인 방어 필드            ● 펑크해저드      │
│      (4분할 = 4인)             ● 불멸 전시      │
│                                ● 초월 전시      │
│                                               │
│  ▪ 스토리     ▮ 유닛뽑기    ▮▮▮▮ 조합식 표      │
│  ▫▫▫▫ 물범섬                                   │
└───────────────────────────────────────────────┘
```

## 구역별 상세

### 1. 메인 방어 필드 (좌상단)
- **4분할 = 레인 4개 = 플레이어 4명**
- ✅ 이걸로 "4레인 = 4인" 구조가 확정됨
  (나무위키 조사에선 근거 문장을 못 찾아 미확정이었음 — `ORIGINAL_GAME_RESEARCH.md` 8장)

### 2. 창고 (우상단, 4개 섬)
- **플레이어별 개인 창고**. 4개 = 4인분
- 유닛이 많아지면 **`C`키**를 눌러 해당 섬으로 유닛을 보냄
- → 인벤토리 외에 **필드 밖 보관 공간**이 별도로 필요하다는 뜻

### 3. 펑크해저드 (우측, 초록/빨강)
- **문을 부수는 이벤트 섬**
- 상시 콘텐츠가 아니라 이벤트성

### 4. 불멸 전시 (펑크해저드 아래)
- **조합식 표가 아님** — 불멸 캐릭터 **스킨 전시**
- 가운데 불이 있고 캐릭터들이 **원형으로 둘러싼** 배치

### 5. 초월 전시 (그 아래)
- 역시 전시용. 캐릭터 스킨이 **일렬로 서 있는** 배치

> ⚠️ **초월·불멸은 맵에 조합식 표를 두지 않는다.** 전시(스킨)만 배치.
>   → 조합 자체는 존재하지만(레시피 78개에 포함됨) 맵 위 표가 아닌 다른 방식으로 수행.

### 6. 스토리 (좌하단)
- 스토리 진행 구역

### 7. 물범 섬 (스토리 아래, 작은 섬 4개)
- 물범이 있는 작은 섬 4개

### 8. 유닛 뽑기 섬 (하단 중앙, 스토리 옆)
- 유닛 뽑기(가챠) 수행 구역
- **다른세계 / 랜덤유닛 스킨을 여기 전시** (조합식 표 없음)
- 상세 구조는 추후 사용자 설명 예정

### 9. 조합식 표 (하단 우측, 가장 큼)
- **표시 대상 등급**: 흔함 / 안흔함 / 특별함 / 희귀함 / 전설적인 / 제한됨
- 미니맵상 세로줄이 여러 개 = 조합표 칸

## 등급별 맵 표시 정리 (확정)

| 등급 | 맵에서의 취급 |
|---|---|
| 흔함 · 안흔함 · 특별함 · 희귀함 · 전설적인 · 제한됨 | **조합식 표에 표시** (하단 우측 큰 섬) |
| 초월 | 전시만 — 스킨 일렬 배치 |
| 불멸 | 전시만 — 가운데 불, 원형 배치 |
| 다른세계 · 랜덤유닛 | 전시만 — **유닛 생성 섬**에 스킨 |
| 영원함 · 히든 | **맵에 표시하지 않음** |

> 조합 자체는 모든 등급에 존재한다(레시피 78개). 위 표는 **맵에 조합식 표를 그리는지** 여부일 뿐이다.
> 표에 없는 등급은 다른 방식(명령어/UI)으로 조합하게 된다.

## 미확인 (사용자 확인 필요)

- 조합식 표에 없는 등급(히든·영원·초월·불멸·다른세계)의 **실제 조합 조작 방식**
- 창고에 보관 가능한 유닛 수 제한
- 물범 섬의 역할
- 펑크해저드 이벤트 발동 조건·보상

## 구현 관점 메모

- **원작이 WC3 유즈맵이라 UI를 맵 공간으로 대체**한 구조.
  Unity에서는 조합식 표·뽑기·창고를 **UI 패널로 만드는 게 조작이 훨씬 빠름**.
  다만 원작 감성을 살리려면 맵 배치를 유지하는 선택도 가능 — 기획 판단 필요.
- 창고는 `UnitInventory`와 별개 저장소가 필요. 현재 코드에 없음.

# 협동 규칙 · 보상 (2026-08-29 사용자 확정)

## 적 유닛에는 소유권이 없다

- 물범 섬은 4개(플레이어 4인분)지만, **모든 적 유닛은 어느 플레이어든 공격할 수 있다.**
- 협동 게임이므로 남의 레인·남의 물범도 도와줄 수 있다.
- → **아군 유닛에는 소유권(OwnedByPlayer)이 있지만, 적에는 없다.**
  현재 `EnemyDummy`에 소유권 개념이 없는 게 맞는 설계.

## 보상 분배

| 대상 | 보상 | 범위 |
|---|---|---|
| **물범** | **목재 1개** | **전체 플레이어에게 각각 1개** (공유 보상) |
| 일반 라인 몹 | 골드 (`EnemyData.goldReward`) | 미확정 — 처치자만? 전체? |

> ⚠️ 물범 보상은 "총 1개를 나눠 갖는" 게 아니라 **플레이어마다 1개씩** 지급.

## ⚠️ 현재 코드 상태

- `EnemyData.goldReward` 필드는 있으나 **어디에서도 사용되지 않는다.**
  적을 죽여도 골드가 들어오지 않는 상태.
- `EnemyDummy`는 죽을 때 그냥 `Destroy`만 한다 — 보상 지급 로직 자체가 없음.
- 물범(Seal)이라는 적 종류 구분도 아직 없음.

## 멀티플레이 관점

보상 지급은 **서버 권위**여야 한다. 클라이언트가 각자 지급하면 목재가 4배로 들어온다.
`MULTIPLAYER_MIGRATION.md`의 "공유 게임 상태" 항목에 보상 분배도 포함할 것.
