## 실행 방식 — 왜 생성기를 다시 돌리면 안 되나

조합식은 두 단계로 만들어졌다:
1. `Tools/generate_recipe_assets.py` — 이름만 보고 `기본_*` 임시 유닛을 참조하는 에셋을 찍어낸다
2. `Tools/repoint_upper_recipes.py` — 그 참조를 실제 등급 유닛으로 갈아끼운다

**생성기를 다시 돌리면 안 된다.** `generate_recipe_assets.py`는 매번 `new_guid()`로 GUID를 새로 뽑아서,
재실행하면 로스터·조합식의 모든 GUID가 바뀌고 `MainGachaTable`·씬 참조가 전부 깨진다.

→ **`.asset` 파일을 직접 고치고, `Tools/recipes_data.py`는 기록을 맞추기 위해 같이 고친다.**
   (`recipes_data.py`만 고치면 아무 효과가 없다. 반대로 `.asset`만 고치면 나중에 누가 전사를 다시 볼 때 되돌아간다.)

`.asset`의 재료 한 칸은 이 다섯 줄이다:
```yaml
  - kind: 0
    unit: {fileID: 11400000, guid: <유닛 GUID>, type: 2}
    item: {fileID: 0}
    wildcardGrade: 0
    count: 1
```
**조합식 표가 재료를 적힌 순서대로 그리므로 순서도 맞춰야 한다.**
