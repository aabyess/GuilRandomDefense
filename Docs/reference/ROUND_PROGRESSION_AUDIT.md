# 원작 라운드 진행 소급 확인 (2026-09-06, 리서치담당)

> **한 줄**: **마리 수·보스 라운드는 맞고, 스폰 간격이 66개 라운드 전부 다르다.**
> 그중 **17개 라운드는 스폰이 라운드 길이를 넘겨** 35마리가 라운드 안에 다 안 나온다.
> 정정 목록: `Docs/reference/ROUND_CORRECTIONS.csv`

## 원작 값 `[파일확인]`

`Trig_Round_10ver_Actions`(스테이지 머신)에서 직접 읽었다:

| 항목 | 원작 | 근거 |
|---|---|---|
| **라운드당 마리 수** | **35** | `Setinteger(GlobalTV,3,35)` — `integerD`가 스폰 종료 조건(`integerC==integerD`) |
| **스폰 간격** | **0.65초 고정** | 스폰 1회마다 `SleepForStage(GlobalTV,(0.65),3)` — **라운드가 올라가도 안 변한다** |
| 스폰 후 대기 | `17.90 − udg_Mode_TimerReal` | `Mode_TimerReal`은 **라운드마다 +2.00** 누적(라운드 40에서 2.00으로 리셋) |
| 보스 라운드 | **10·20·30·40·50·60** (6회) | `udg_Level<61 AND Level%10==0` |
| 신세계 사이드보스 | 62·66·71 | 별도(어려움 모드 제외) |

→ **원작은 「스폰 간격은 고정, 스폰 후 대기가 라운드마다 2초씩 줄어든다」로 후반을 빠르게 만든다.**
**우리는 반대로 「스폰 간격을 줄이는」 방식이다.** 결과가 비슷해 보여도 **화면에 동시에 존재하는 적 수가 달라진다.**

## 우리 값과 대조

| 항목 | 우리 | 판정 |
|---|---|---|
| 라운드당 마리 수 | **35** (일반 66라운드) | ✅ 일치 |
| 보스 라운드 마리 수 | 1 | ✅ |
| 보스 라운드 | 10·20·30·40·50·60 **+ 65·70·75** | ⚠ **원작 보스는 6회.** 65/70/75는 우리가 추가한 것(`ENEMY_DATA_AUDIT.md`에서 이미 확인) |
| **스폰 간격** | **1.6 → 0.69 곡선** | ❌ **66개 라운드 전부 원작(0.65)과 다르다** |
| 라운드 길이 | 40.65 / 보스 75.4 / 신세계 38.67 | ⚠ **부분 일치** — 아래 🚩 절 참고 |

## 🔴 17개 라운드에서 **스폰이 라운드 길이를 넘는다**

라운드 길이 40.65초인데 `34 × 간격`이 그보다 크다:

| 라운드 | 간격 | 스폰 소요 | 초과 |
|---|---|---|---|
| R1~R3 | 1.60 | 54.4초 | **+13.8초** |
| R4~R6 | 1.50 | 51.0초 | +10.3초 |
| R7~R9 | 1.41 | 47.9초 | +7.3초 |
| R11·R12 | 1.33 | 45.2초 | +4.6초 |
| R13~R15 | 1.26 | 42.8초 | +2.2초 |
| R16~R18 | 1.20 | 40.8초 | +0.1초 |

**→ 초반 라운드는 35마리 중 마지막 몇 마리가 라운드 종료 전에 못 나온다.**
원작 기준으로는 **34 × 0.65 = 22.1초**면 전부 나오고 18초가 남는다.

⚠️ **밸런스 측정에 직접 영향**: 같은 35마리라도 **1.6초 간격이면 동시 존재 수가 원작의 절반 이하**다.
광역 스킬 효율·유닛 처리량·죽음카운트가 전부 이 밀도에 걸린다. **구현담당2가 지금 재는 숫자가 이 영향을 받는다.**

## 판단

**원작대로면 66개 라운드의 `spawnInterval`을 전부 `0.65`로 통일**하면 된다(사장님 지시 「전부 원작대로」).
다만 그러면 **초반 라운드가 지금보다 훨씬 촘촘해진다** — 난이도 체감이 크게 바뀌므로 **PM 판단이 필요한 자리**다.
**연구 결론은 「원작은 0.65 고정」이고, 바꿀지는 결정 사항이다.**

## 조사 범위 공개

- 원작 값은 `Trig_Round_10ver_Actions` **한 트리거 안에서만** 읽었다(뿌리 ⑨ — 계열 안에서 풀기).
- **안 본 것**: 라운드 41 이후 `Mode_TimerReal` 누적이 음수가 되면 엔진이 어떻게 처리하는지 `[미확인]`.
  `17.90 − Mode_TimerReal`은 라운드 9쯤부터 음수가 되는데, 그때 대기가 0인지 즉시 진행인지는 확인 못 했다.
- 스폰 **위치**(레인 4개 분배)는 이번 범위 밖이다.

## 🚩 자체 정정 (2026-09-06) — **라운드 길이는 「일치」가 아니었다**

첫 보고에서 라운드 길이를 ✅로 적었는데, `Mode_TimerReal`을 끝까지 안 봐서 그랬다.
**대입 지점 6곳을 전수로 열어 확정했다** `[파일확인]`:

| 어디 | 무엇 |
|---|---|
| `InitGlobals` | `0` |
| `Trig_Round_boolean_Trigger` | **`elseif udg_Level==40 then … set udg_Mode_TimerReal=2.00`** — 하드 설정 |
| `Trig_Round_10ver` stage 11 / **stage 20** | `+= 2.00` 누적. **stage 20은 신세계 경로**(stage 3에서 `Level<61`이 거짓일 때) |

**라운드 길이 레지스터를 직접 읽으면:**
```
stage 0 (1라운드)      : Setreal(GlobalTV,7, 40.65)              ← 상수
stage 2 (2라운드 이후) : Setreal(GlobalTV,7, 40.67 − Mode_TimerReal)
```

| 라운드 | 원작 길이 | 우리 |
|---|---|---|
| 1 | **40.65** | 40.65 ✅ |
| 2~39 | **40.67** | 40.65 (0.02 차, 무시 가능) |
| **40~60** | **38.67** | **40.65** ❌ |
| **61+** | **라운드마다 2초씩 더 짧아짐** | 38.67 고정 ❌ |

→ **`Mode_TimerReal`은 난이도 상수가 아니라 라운드 진행값이다.**
**우리 `newWorldStartRound = 61`이 38.67을 61부터 적용하는데, 원작의 38.67은 40부터**이고 61부터는 더 줄어든다.

`[미확인]`: 신세계에서 매 라운드 +2.00이면 몇 라운드 뒤 `40.67 − MTR`이 음수가 되는데, 그때 엔진 동작은 확인 못 했다.

## 보스·신세계 스폰 간격 (PM 질의)

- **보스 라운드엔 스폰 간격이 없다.** stage 2에서 `Level%10==0`이면 **`Enemy_Boss_create` + `sleep(75.40)`**로 빠지고
  **35마리 스폰 루프(stage 3)를 아예 안 탄다.** 보스 1기뿐 → **우리 보스 라운드(마리 1·간격 0)가 맞다.**
- **신세계도 스폰 루프는 같은 stage 3**이라 **간격 0.65 동일**. 다른 것은 **스폰 후 경로**(stage 20 vs stage 2)뿐이다.
