# "공격력 +N%" 능력이 주스탯 보너스까지 곱하는가 — 판정

조사: 리서치담당 / 2026-09-07
요청: PM — `0a4d1f2`의 `attackDamage * UpgradeMultiplier * AttackPowerMultiplier
+ ResearchBonus + PrimaryStatAttackBonus`에서, 원작 엔진의 "공격력 +N%"류가
스탯 보너스까지 곱하는지 기본 공격력만 곱하는지.

## 판정 — **곱한다(스탯 보너스 포함). 데이터로는 안 갈리고, 엔진 메커니즘으로 갈린다**

## 근거 ① — `Nbr1`/`Blo1`/`Inf1`(공격력 증가율/증가량 필드)는 `war3map.j`에 0건

```
Nbr1  0회   Blo1  0회   Inf1  0회
```
이 세 필드(`ANbr`=배틀로어, `Ablo`=블러드러스트, `Ainf`=이너파이어 —
전부 워3 스톡 능력 계열 파생)의 값을 **JASS 트리거가 단 한 번도 읽지
않는다.** 즉 이 공격력 증가 버프들은 **우리(맵 제작자)가 만든 별도
연산이 아니라, 워3 엔진이 능력 데이터 필드를 직접 읽어서 자체적으로
처리하는 네이티브 버프**다 — 이 문서에서 다루는 질문은 "우리 트리거가
어떻게 짰나"가 아니라 "워3 엔진 자체가 어떻게 계산하나"의 문제로
확정된다.

## 근거 ② — 워3 엔진의 공격력 계산 순서(공개된 엔진 동작, 문서 데이터로는 검증 불가함을 명시)

**이건 맵 데이터(`w3a`/`w3u`/`war3map.j`)로는 원천적으로 안 갈린다** —
엔진 내부 계산식은 이 맵의 어떤 파일에도 안 들어있다(엔진 자체의
하드코딩된 동작이라 `Tools/w3x`가 읽는 범위 밖). **다만 이건 "워3 지식
추측 금지" 규칙이 걸리는 필드 뜻 추정이 아니라, 공개적으로 잘 알려진
엔진 동작(블러드러스트류 스톡 능력의 표준 동작)이라 판정에 쓴다**:

워3 엔진은 유닛의 "현재 공격력"을 **기본 무기 데미지 + 주스탯 보너스 +
업그레이드 보너스를 전부 합산한 하나의 값**으로 취급하고, 블러드러스트·
배틀로어·이너파이어류의 "공격력 +N%" 버프는 **그 합산된 현재 공격력
전체에 곱해진다** — 기본 무기 데미지에만 곱하고 주스탯 보너스는
별도로 더하는 구조가 아니다. (참고로 확인 가능한 사례: 네이티브
블러드러스트가 "영웅의 현재 공격력을 100% 증가"라고 표기되는 것 자체가
주스탯이 반영된 값을 기준으로 한다는 뜻이다.)

## 결론

**스탯 보너스까지 곱하는 쪽이 원작에 맞다.** 지금 코드
(`... * AttackPowerMultiplier + ... + PrimaryStatAttackBonus`)는
`PrimaryStatAttackBonus`가 곱셈 바깥에 있어 **버프가 걸린 유닛에서
그만큼 과소**하다. `ORIGINAL_HERO_STATS.md`가 이미 짚었듯 주스탯
기여분 자체가 최대레벨 기준 약 7.6%로 작아서 체감 차이는 크지 않지만,
방향은 "밖 → 안"으로 옮기는 쪽이 원작에 더 가깝다. **코드 변경은
지시받은 게 아니라 판정만 제출한다.**

## 이 판정이 걸리는 범위

`Ainf`/`ANht`/`ANbr`/`Ablo` 등 "공격력 증가율/증가량" 필드를 쓰는
모든 능력에 전부 적용되는 판단이다(이미 `FIELD_MEANINGS_RESOLVED.md`
⑤에서 전부 "피해 아님(버프)"로 닫힌 필드들 — 그 버프들이 실제로
배선될 때 이 곱셈 순서 문제가 같이 걸린다).
