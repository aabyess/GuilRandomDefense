## ④ 🔴 조사 중 발견 — 내 표의 등급 축이 둘 섞여 있었다

`ORIGINAL_UNLISTED_SKILL_EFFECTS.csv`의 `등급` 컬럼과 **원작 유닛 이름의 등급 라벨이 서로 다른 축**이었다.

```
CSV 등급별 고유 유닛의 ID 첫 글자
  초월함  24종 → 전부 H*     ← 대문자
  그 외   전부 h*            ← 소문자
```

**`H*`는 「영웅」 계열**이고 **이름에 등급 라벨이 없다**(`H07S 흔함영웅` · `H05N 해군의 홍일점` · `H08W CP.Zero`).
`H*` 68종의 DPS는 **38(흔함영웅)에서 403,229(밀짚모자 해적단 의사)까지** 넓게 퍼져 있다 — **등급이 아니라 별개 축**이다.

→ 그래서 **「원작 등급별 스킬 보유율」은 분모를 못 정한다** `[미확인]`.
이름 라벨로 세면 `H*` 68종이 통째로 빠지고, CSV 등급으로 세면 「초월함=H\*전부」라는 다른 정의가 된다.
**이 문서의 ①②는 우리 로스터 기준이고, 원작 쪽은 「가진 유닛의 피해 중앙값」만 비교했다.**

⚠️ **어제 쓴 `ORIGINAL_GRADE_LADDER.md`의 원작 DPS 표도 이름 라벨 기준이라 `H*` 68종이 빠져 있다.**

# 추가 (2026-09-06) — `H*` 축의 정체와 원작 보유율. **`Uncommon`은 채우면 안 된다**

## ① 🔴 `H*`는 영웅이고, **등급이 `unam`이 아니라 `upro`에 있다**

`H*`가 워크래프트3 「영웅」이라는 것은 필드 보유율로 확정된다:

| 필드 | `H*` 보유 | `h*` 보유 |
|---|---|---|
| `upro`(고유 이름) | **70** | **0** |
| `ustr`·`uagi`·`uint`(영웅 스탯) | 27 | 0 |
| `ustp`·`uagp`·`uinp`(레벨당 증가) | 63 | 0 |
| `uhab`(영웅 능력) | 30 | 0 |

base도 갈린다 — `H*`는 `Hvwd`(27)·`Hpal`(1) 같은 **영웅 베이스**를 쓰고 `h*`는 `hrif`·`hfoo` 일반 베이스다.

**그리고 영웅은 워크3에서 `upro`가 「이름」, `unam`이 「칭호」로 표시된다.** 그래서 등급이 `upro`에 있다:

```
H05N  unam = 해군의 홍일점            ← 칭호
      upro = 대령 타시기 - 초월함      ← 이름 + 등급  ★
H08X  unam = 해군 대장 '성난 보라호랑이'
      upro = 후지토라 - 초월함
H0BD  unam = 오니히메                upro = 야마토 - 초월함
```

**CSV의 `등급` 컬럼은 틀리지 않았다** — 이전 세션의 내가 `upro`를 보고 맞게 붙인 것이다.
**틀린 건 어제 `unam`만 본 내 사다리 집계였다.**
