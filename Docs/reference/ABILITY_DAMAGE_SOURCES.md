# 수치 0인 능력 938행의 피해는 어디 있나 (2026-09-05, 리서치담당)

> **결론 세 줄**
> 1. **938행 중 399행(42.5%)은 스킬이 아니라 시스템 버튼**이다(`[조합]`·창고 이동·판매·유닛 모으기). 물어볼 대상이 아니다.
> 2. 남은 **539행(스킬 후보, 능력 444종 / 유닛 196종)** 중 **92종(46.9%)에서 수치가 실제로 회수된다.**
> 3. **회수 경로가 능력ID가 아니다.** 원작은 `udg_HashAttack[유닛ID] → 트리거` 해시테이블 하나로 디스패치한다 —
>    **능력ID로 트리거를 찾으면 11.5%밖에 안 걸리고, 유닛ID로 찾으면 53.8%가 걸린다.** 대조 키를 바꾸는 게 이 조사의 전부였다.

---

## ① 원작의 스킬 디스패치 구조 `[파일확인]`

```jass
function Trig_Main_Attack_Trigger_Manager_Actions takes nothing returns nothing
    call TriggerExecute(LoadTriggerHandle(udg_HashAttack, GetUnitTypeId(GetAttacker()), 0))
```

**평타 발동 스킬은 「유닛ID → 트리거」 해시테이블 하나로 전부 처리된다.**
등록은 `SaveTriggerHandle(udg_HashAttack,'<유닛ID>',0,gg_trg_<트리거>)` 형태로 **204건 / 유닛 203종**이다.
그래서 **유닛의 능력 목록(`uabi`)에 붙은 능력은 껍데기여도 되고**, 실제 피해는 그 유닛 전용 트리거 안에 있다.

병렬 경로는 둘 더 있다:

| 경로 | 키 | 규모 | 비고 |
|---|---|---|---|
| **평타 훅** | `udg_HashAttack[유닛ID]` | 유닛 **203종** | 대부분의 캐릭터 스킬이 여기 |
| **액티브 시전** | `GetSpellAbilityId()=='능력ID'` | 능력 **48종** | 이쪽만 능력ID가 키다 |
| **오라·엔진 처리** | 없음(스톡 능력이 엔진에서 직접) | `AHad`·`AUau`·`Aroa` 등 | 트리거 코드가 아예 없다 |

## ② 피해 수치가 사는 곳 — **세 군데**다

| 채널 | 뜻 | 유닛 수(196종 기준) |
|---|---|---|
| **A. 트리거 계산식** | `RRD(공격자, 대상, <식>, …)`이 직접 계산 | 35 (17.9%) |
| **B. 더미 유닛의 능력** | 트리거가 더미를 만들어 스톡 주문을 시키고, **피해는 그 더미가 든 능력의 `w3a` 값** | 30 (15.3%) |
| **A+B 둘 다** | | 27 (13.8%) |
| 훅 없음 | 평타 훅 미등록(액티브·순수 패시브) | 77 (39.3%) |
| 훅은 있으나 수치 없음 | 버프·이동·시각효과 | 27 (13.8%) |

**B 채널이 이번 조사의 핵심 발견이다.** 예:

```
h00A 후쿠로 → udg_HashAttack → Trig_common1
     → CreateNUnitsAtLoc(1,'e0DG')        ← "안흔함 더미1"
     → IssuePointOrderById("carrionswarm")
     → 더미의 능력 A0A2 "0장풍 cp 안흔함" 의 w3a 값: Ucs1=150 · Ucs2=70,000,000 · aare=200 · aran=1700
```

**유닛이 든 능력엔 수치가 없는 게 맞다 — 수치는 「더미 유닛이 든 다른 능력」에 있다.** 두 홉 떨어져 있어서 PM의 CSV엔 0으로 보인다.
같은 꼴이 30+27종에서 확인된다(`A0A1` 루치 특별함 `Ucs1=600`, `A0BI` 에이스 `Ucs1=850`, `A0AX` 아카이누 블리자드 `Hbz1=2·Hbz2=6000`,
`A09X` 마르코 `Efk1=1500`, `A0K2` 바제스 스턴 `Wrs1=12000` …).
⚠️ **필드 뜻은 스톡 정의라 이번 조사로 확정 못 했다** `[미확인]` — `Ucs1`이 「피해」이고 `Ucs2`가 「최대 피해 한도」로 **보이지만**
(70,000,000이 여러 능력에 같은 값으로 반복되는 건 한도로 읽는 게 자연스럽다) 스톡 정의를 확인해야 확정된다.

**훅 없는 77종의 내역**: 액티브 시전 훅이 있는 것 35종(그 중 피해식이 있는 건 **2종뿐**), 순수 오라/패시브 5종, **어느 쪽도 아닌 37종**.
→ 액티브 계열은 **껍데기 수치도 트리거 피해도 없다** — 사실상 원작에서 뽑을 게 없다.

## ③ 계산식의 모양 — 우리 `SkillEffectBasis`에 **안 담기는 형태가 넷** 있다 `[파일확인]`

`RRD(…)` 호출 **649건**의 피해량 인자를 전부 파싱했다.

| 모양 | 건수 | 우리 스키마 |
|---|---|---|
| 상수 | **346** (53%) | `Flat` ✅ |
| 대상 최대체력 비례 | 112 | `TargetMaxHpPercent` ✅ |
| 대상 현재체력 비례 | 56 | `TargetCurrentHpPercent` ✅ |
| 능력 레벨 비례(`A11S` 등) | 47 | ✅ 계수로 담김 |
| 연구 횟수 비례(`GetPlayerTechCountSimple`) | 3 | `ResearchLevel` ✅ |
| **그 외** | **119** (18%) | ⬇ 아래 |

**⚠️ 담기지 않는 형태 4종 (PM이 「제일 중요한 발견」이라 하신 것)**

1. **`GetEventDamage()` 비례 — 24건.** `(GetEventDamage()×N)+N` 꼴. **「이번 평타가 실제로 넣은 피해」의 배수**다.
   시전자 공격력 스탯이 아니라 **방어력·상성이 적용된 뒤의 실제 피해**라 우리 `CasterAttackPower`와 뜻이 다르다.
2. **시전자 자신의 체력 비례 — 다수.** `N × GetUnitStateSwap(UNIT_STATE_MAX_LIFE, udg_Hero_Gaban[…])` 꼴.
   우리 `TargetMaxHpPercent`는 **대상** 체력이다. **시전자 체력 축이 없다.**
3. **누적 스택 비례 —** 아이템 충전수(`GetItemCharges(udg_Item_Bigmom…)`), 세이브 플레이 횟수(`udg_Load_PlayCount`),
   대상이 가진 버프 개수(`UnitCountBuffsExBJ`), 캐릭터 전용 누적 변수(`udg_Yamato_Damage[플레이어]`), 대상 이동속도(`GetUnitMoveSpeed`) 6건.
4. **다단 곱 —** `(N + 앞단계값) × (N + 다른값×N)` 꼴이 40건 가까이 있다. 트리거가 앞 단계에서 계산해둔 중간값을 곱한다.
   **단일 basis 하나로는 표현이 안 된다.**

**그리고 반대 방향의 발견 하나: 원작엔 「시전자 공격력 × 배수」가 없다.** `BlzGetUnitBaseDamage`·`BlzGetUnitWeapon` **0건**이다.
우리 `SkillEffectBasis.CasterAttackPower`는 **원작에 대응이 없는 축**이다(그 자리를 `GetEventDamage()`가 대신한다).

## ④ 물리/마법 구분 — **뽑힌다** `[파일확인]`

피해 호출 **715건**의 `ATTACK_TYPE_*` / `DAMAGE_TYPE_*` 분포:

| 공격타입 | 피해타입 | 건수 |
|---|---|---|
| NORMAL | UNIVERSAL | 321 |
| CHAOS | NORMAL | 102 |
| CHAOS | UNIVERSAL | 95 |
| **MAGIC** | UNIVERSAL | **62** |
| HERO | NORMAL | 59 |
| HERO | UNIVERSAL | 19 |
| MELEE | UNIVERSAL / NORMAL | 14 / 4 |
| PIERCE | UNIVERSAL / NORMAL | 13 / 8 |
| SIEGE | UNIVERSAL / NORMAL | 8 / 7 |

- **마법 스킬은 실재한다(62건).** 구현담당1이 지금 전부 물리로 넣는 건 **나중에 고칠 수 있다** — 대응표가 뽑힌다.
- **다만 대응 키가 능력ID가 아니라 유닛ID다.** 한 유닛의 트리거 안에서 여러 타입이 섞여 나오므로,
  「능력 하나 = 타입 하나」로는 안 나오고 **「유닛 하나 = 그 유닛이 쓰는 타입 집합」**으로 나온다.
  그 표를 `Docs/reference/ORIGINAL_ABILITY_DAMAGE_SOURCES.csv`(196행)로 뽑아뒀다 — 컬럼 `공격피해타입`.
- ⚠️ **`DAMAGE_TYPE_UNIVERSAL`이 압도적이다.** 워크 엔진에서 UNIVERSAL은 방어력·감쇄를 무시하는 것으로 알려져 있으나,
  **이건 맵 파일 밖 지식이라 `[미확인]`으로 둔다.** 사실이라면 **원작 스킬 피해 대부분이 적 방어력을 아예 안 탄다**는 뜻이라
  우리 방어력 설계에 직접 영향이 있다 — 확인이 필요하다.

## ⑤ 발동 조건 — 우리 `SkillTriggerType` 셋으로 담기나

| 원작 채널 | 우리 대응 |
|---|---|
| `udg_HashAttack` 평타 훅 + `GetRandomInt(1,N)==k` 확률 게이트 | `OnHitChance` ✅ (`Trig_common1`은 1/10, `Trig_Speical1`은 1/10 …) |
| 오라(`AHad`·`AUau`·`Aroa`, 엔진 처리) | `Aura` ✅ |
| 주기 타이머 등록 21건 | `CooldownAutoCast` △ (주기형이 실제로 스킬용인지는 확인 안 함 `[미확인]`) |
| **액티브 시전(`GetSpellAbilityId`, 능력 48종)** | ❌ **없다.** 플레이어가 직접 누르는 시전이라 셋 중 어디에도 안 맞는다 |
| **평타가 아닌 「피격 시」(`EVENT_UNIT_DAMAGED` 계열 81건)** | ❌ **없다.** 맞았을 때 발동하는 축 |

→ **`SkillTriggerType`에 없는 것은 「액티브 시전」과 「피격 시」 둘이다.** 다만 액티브 48종은 ②에서 봤듯 **피해식이 2종뿐**이라,
당장 값을 옮길 게 거의 없다.
