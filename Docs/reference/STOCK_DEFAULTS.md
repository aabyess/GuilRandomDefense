# 스톡(워3 기본) 기본값 조사 — `ACbh` 발동확률 · `ogru` 방어타입

조사: 리서치담당 / 2026-09-06
대상: 원작 맵이 **덮어쓰지 않은 필드**의 실제 런타임 값.
원칙: 오브젝트 파일(`w3u`/`w3a`)은 **바꾼 필드만** 저장한다. 없는 필드 = 스톡 기본값이 그대로 돈다.

## ⚠️ 먼저 — 이 문서를 쓸 때의 금지사항

**원작 맵은 `war3mapMisc.txt`의 피해 배율표를 통째로 개조했다.** 스톡 워3 표
(`classic.battle.net` 기준 Normal 100/100/150/100/70/100 등)와 **한 칸도 맞지 않는다.**

→ **스톡 배율 숫자를 우리 맵에 교차적용하지 말 것.** 배율은 반드시 원작 `war3mapMisc.txt`에서 읽는다.
스톡 자료는 **「그 필드가 무엇인지 / 기본값이 얼마인지」에만** 쓴다.

## ① 스톡 `ACbh`(Bash) 기본 발동확률 `Hbh1` = **15%**

### 근거 A — 외부 출처 2건 (일치)

### 근거 B — 원작 맵 자체가 증명한다 (이게 더 강하다)

원작 맵의 `ACbh` 파생 능력 **469개**의 `Hbh1` 값 분포:

```
0     : 291개      20    : 79개      10    : 17개      25    : 13개
100   : 9개        18    : 6개       30    : 6개       17    : 5개
14    : 4개        35    : 4개       50    : 4개       4.25  : 3개
12    : 3개        40    : 3개       13/22 : 2개씩
11 · 12.5 · 16 · 17.5 · 19.5 · 22.5 · 33 · 45 · 55 · 60 · 66 · 6.25 · 7.77 · 10.62 : 1개씩
```

**`15`가 정확히 0건이다.** 바로 옆의 14(4건)·16(1건)·17(5건)·17.5(1건)·18(6건)은 다 있는데
15만 없다. 에디터는 **기본값과 같은 값을 입력하면 파일에 쓰지 않는다.**
→ 「15를 원한 제작자는 아무것도 안 건드리면 됐다」 = **기본값이 15**.

## ② 스톡 `ogru`(오크 그런트) 방어타입 `udty` = **`large`**

### 결론 먼저 — PM의 기억(「그런트는 medium」)은 **틀렸다.** `large`가 맞다.
### 그리고 `large`는 **우리 4열 안에 이미 있다.** 근사할 필요가 없다.

### 근거

| 출처 | 원문 |
|---|---|
| [Warcraft III — Orcs → Units → Grunt (classic.battle.net, 블리자드 공식)](http://classic.battle.net/war3/orc/units/grunt.shtml) | Armor: **"Heavy"** armor type with 1 armor (7 fully upgraded) |
| [CSV of all Warcraft III units (UnitBalance.slk 덤프, gist)](https://gist.github.com/NobleUplift/3b64dc4690b7b04bf07b) | `ogru` 행의 Armor Type 열 = **Heavy** |
| [Warcraft III armor and attack types — Wowpedia](https://wowpedia.fandom.com/wiki/Warcraft_III_armor_and_attack_types) / [WoWWiki](https://wowwiki-archive.fandom.com/wiki/Warcraft_III_armor_and_attack_types) | 에디터 내부명 ↔ 게임 표시명: **Small = Light, Medium = Medium, Large = Heavy**, Fortified = Fortified, Hero = Hero, Divine = Divine, Unarmored = Unarmored |

→ 게임 표시 **Heavy** = 에디터 내부명 **`large`**. 그래서 `ogru`의 `udty` = **`large`**.

### 열 인덱스 — 0·1·6에 무엇이 있나

`war3mapMisc.txt`의 `DamageBonus*` 8개 값은 **방어타입 인덱스 순서**다:

| 인덱스 | 내부명 | 게임 표시명 | 원작 맵에서 쓰이나 |
|---|---|---|---|
| **0** | `small` | Light (경장갑) | ❌ 0기 |
| **1** | `medium` | Medium (중장갑) | ❌ 0기 |
| **2** | `large` | **Heavy** (대형/중장갑) | ✅ 22기 + 미지정 5기 |
| **3** | `fort` | Fortified (건물) | ✅ 22기 |
| **4** | `normal` | Normal | ✅ 70기 |
| **5** | `hero` | Hero (영웅) | ✅ 5기 |
| **6** | `divine` | Divine (신성) | ❌ 0기 |
| **7** | `none` | Unarmored (무장갑) | ❌ 0기 |

출처: [Armor Types — The Hive Workshop](https://www.hiveworkshop.com/threads/armor-types.214913/) (「Medium=1, Large=2, Fortified=3, Unarmored=7」, Damage Bonus Table A~H = Small/Medium/Large/Fortified/Normal/Hero/Divine/Unarmored)

**원작 맵 자체로 이 순서를 재검증했다.** `war3mapSkin.txt`의 `ARMORTIP_*`가 `war3map.wts`에서
풀리는데, 제작자가 적어둔 배율이 `war3mapMisc.txt`의 해당 인덱스와 맞는다:

- `ARMORTIP_LARGE` → 「대형 ← 관통 125% / 일반 100% / 공성 75% / 마법 85%」
  → 인덱스 2 = Pierce **1.25** · Normal **1.00** · Siege **0.75** · Spells **0.85** — **4/4 일치** ✅
- `ARMORTIP_FORT` → 「건물 ← 공성 125% / 관통 100% / 일반 75%」
  → 인덱스 3 = Siege **1.25** · Pierce **1.00** · Normal **0.75** — **3/3 일치** ✅
- `ARMORTIP_NORMAL` → 「일반 ← 일반 125% / 건물 100% / 관통 75%」
  → 인덱스 4 = Normal **1.25** · Siege **1.00** · Pierce **0.75** — **3/3 일치** ✅

> 🔴 **`ARMORTIP_MEDIUM`은 믿지 말 것.** 텍스트가 `ARMORTIP_NORMAL`과 **글자 하나까지 똑같다**
> (제작자가 복사-붙여넣기 했다). 그런데 인덱스 1(medium)의 실제 값은 **전부 1.00**이다.
> 툴팁과 실제가 다른 사고가 방어타입 쪽에도 하나 더 있었다.
> 같은 이유로 `ARMORTIP_HERO`(일반 100%라 적혀 있으나 실제 0.90)와
> `ARMORTIP_DIVINE`(일반 130%라 적혀 있으나 실제 1.00)도 **낡은 텍스트**다.

### ⚠️ 여기서 나온 부수 발견 — 사이드보스 라인의 방어타입이 갈라져 있다

`ogru` 기반 사이드보스는 레벨 64·66·67·71·72·73·76·77로 한 줄인데, 절반만 `fort`가 지정돼 있다:

| 지정됨 (`fort`) | 미지정 (→ 스톡 `large`) |
|---|---|
| 레벨 64 피카 · 67 샬롯 크래커 · 72 잭 · 77 잡몹 | 레벨 66 호미즈 · 71 바질 호킨스 · 73 퀸 · 76 잡몹 |

제작자가 `fort`를 **의도**했으나 4기를 빠뜨렸을 가능성이 크다.
그러나 **실제로 돈 값은 `large`다.** 사장님 지시(「모든 것 원작 따라간다」)는 *의도*가 아니라
*원작에서 실제로 돌아간 것*을 따르는 것이므로 → **`large`로 간다.**
(메인보스 22기는 전부 `otbk` 기반으로 명시적 `large`. 메모리 「보스=Large」와도 일치한다.)
