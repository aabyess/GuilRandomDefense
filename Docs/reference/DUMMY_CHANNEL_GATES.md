## ① 방법 — 「어느 블록이 이 더미를 소환하는가」

PM이 막힌 지점(「한 부모 밑에 게이트가 다른 자식이 여럿」)은 **부모 트리거 이름으로 찾았기 때문**이다.
**더미 유닛ID로 찾으면 소환 지점이 하나로 좁혀진다.**

```
1. 더미 유닛ID('e0BU' 등)가 든 함수에서 CreateNUnitsAtLoc / CreateUnitAtLoc 을 찾는다
2. 그 호출을 감싸는 if/elseif/else 를 최상위부터 스택으로 쌓아 전부 편다 (뿌리 ⑧)
3. 조건이 Trig_..._FuncNNNC() 꼴이면 그 함수 본문까지 펼친다 (뿌리 ⑧ 덧붙임)
   — GetBooleanAnd 래퍼·다중 return true(OR) 꼴도 재귀로 편다
```

**52/52 전부 소환 지점을 찾았다. 「불가」 0건.**

> ⚠️ 구현 중 실수 하나를 기록해둔다: 조건 문자열에서 감싸는 괄호를 `strip('() ')`로 벗겼더니
> `Trig_XXX_Func008C()`의 **끝 괄호까지 지워져** 조건 함수 치환이 조용히 안 됐다.
> 8행이 `Trig_..._Func008C`라는 이름 그대로 남아 있었고, **「안 풀린 것」이 아니라 「내 코드가 못 편 것」**이었다.
> 괄호 균형을 세어 **완전히 감싸는 쌍만** 벗기도록 고쳤다.

## ③ ⚠️ 추정 6행 — 소환 지점이 여럿이라 확정 못 함

| 더미 | 유닛 | 후보 게이트 |
|---|---|---|
| `e0EN` | 베이비 5 | `Stage==0 AND integerA==5` ‖ `Stage==5` |
| `e00E` | 바솔로뮤 쿠마 | `(무조건)` ‖ `1/10` |
| `e00J` | 레일리(부선장) | `A0ES레벨==2` ‖ `NOT(A0ES레벨==2)` ‖ `시전자마나==115` |
| `e0H5` | 카이도 | `Stage==4` ‖ `Stage<=4 AND Stage%2==0` |
| `e0BR` | 루피 기어서드 | `Stage==1` ‖ `Stage==2` |
| (1행 더) | | |

**같은 더미가 여러 자리에서 소환된다.** 어느 소환이 이 피해와 짝인지는 **더미별 능력 시전 순서까지 봐야** 갈린다.
**구현 시엔 가장 보수적인(가장 낮은 발동률) 후보를 쓰는 편이 안전하다.**

## ④ ⚠️ 「Stage == N」은 부모 게이트가 아니다

8행 중 상당수가 `Stage[GlobalTV]==N`으로 나왔다. **이건 그 트리거 내부의 단계이지 발동 조건이 아니다.**
진짜 게이트는 **그 트리거를 실행시키는 호출자**(대개 평타 트리거)에 있다 — **한 단계 더 파야 한다.**

이 8행은 표에 그대로 적어뒀다. **「Stage==N」이 보이면 그게 답이 아니라는 표시로 읽어라.**

## 조사 범위 공개

- 대상: `ORIGINAL_SKILL_DAMAGE_TABLE.csv`의 `더미채널판정 = ⭕ 피해 있음` **52행 전수**(고유 더미 50기).
- 조건 스택은 `war3map.j`를 정규식으로 토큰화해 `if`/`elseif`/`else`/`endif`를 세어 쌓았다 —
  **주석이나 문자열 안의 키워드에 속을 수 있는 방식**이다. 확정 46행도 그 한계 위에 있다 `[미확인]`.
- **안 본 것**: ④의 「Stage==N」 8행에 대한 **호출자 추적**. 시간이 없었다 — **다음 사람의 첫 작업으로 남긴다.**

# 추가 (2026-09-06, 리셋 후) — 「Stage == N」 6행 해소 + **어젯밤 표의 오염 1건 정정**

## 🔴 먼저 — 어젯밤 내 도구가 조건 하나를 오염시켰다 (뿌리 ⑲ 자가적용)

조건 스택을 쌓을 때 `if`/`then`을 **단어 경계 없이** 잘랐다.
그래서 **`SetUnitL·if·eBJ` 안의 `if`가 `if`로 잡혔다.**

```
옛(오염): 시전자체력==75.00 AND eBJ(GetAttacker(),1.00) set udg_Hero_Sengoku[0]=... 
새(정정): GetRandomInt(1,10)==6
```

원문으로 손 확인했다 — 센고쿠 `e02B` 더미는 **체력 75 블록과 무관한 별개 `if` 블록**에서 소환된다:

```jass
Trig_Sengoku_Attack_Actions:
    if 시전자체력 == 75.00 then … ConditionalTriggerExecute(gg_trg_Seongoku_Skill_4) else … endif
    if GetRandomInt(1,10)==6 then
        CreateNUnitsAtLoc(1,'e02B', …)        ← 여기다
```

**52행 전수를 다시 돌려 대조했고 바뀐 행은 이 1행뿐이다.** 나머지 51행은 그대로다.
`\bif\b`로 고쳤다. **조건 문자열에 `set `·`call `이 섞여 있으면 오염 신호**라는 자가검증도 넣었다.

## ① 「Stage == N」의 정체 — **그 트리거가 곧 평타 트리거였다**

호출자를 찾으니 **6개 중 5개가 `TriggerExecute` 호출자 0건**이었다. 뿌리 ⑫대로 「죽은 경로」로 볼 뻔했는데, **아니었다** — `InitTrig`를 보니 전부 이 꼴이다:

```jass
InitTrig_Unique34:
    set gg_trg_Unique34 = CreateTrigger()
    call s__TrigVariables_RegisterTimerPutsTriggerToSleep(gg_trg_Unique34)
    call TriggerAddAction(gg_trg_Unique34, function Trig_Unique34_Actions)
```

**이벤트 등록이 없다.** 대신 `udg_HashAttack`에 **유닛ID로 등록**돼 있다:

| 트리거 | 등록된 유닛 |
|---|---|
| `Trig_Unique34` | `h02E` 죠즈 |
| `Trig_Unique33` | `h02F` 조로 |
| `Trig_Unique29` | `h02M` 베이비 5 |
| `Trig_Unique32` | `h01X` 루피 기어서드 |
| `Trig_Legend11` | `h031` 후지토라 |
| `Trig_Kaido_Attack` | `h07M` 카이도 |

→ **이 트리거들 자체가 그 유닛의 평타 트리거**다. `TriggerExecute(LoadTriggerHandle(udg_HashAttack, GetUnitTypeId(GetAttacker()), 0))`로 **평타마다 실행**된다.
**「호출자 0건 = 죽은 경로」가 아니었다** — 호출 방식이 해시테이블이라 이름으로 안 잡혔을 뿐이다.

**따라서 진짜 게이트는 stage 0의 진입 조건과, 거기서 그 stage까지 가는 분기다.**

## ③ 여기서 배운 것 — 방법론 18

> **「호출자 0건」을 죽은 경로로 읽기 전에 「이름 말고 다른 방식으로 불리는가」를 봐라.**

# 추가 ② — 추정 5행 중 4행을 **유닛ID로 짝을 맞춰** 확정

## 방법 — 「누가 이 더미를 소환하는가」가 아니라 「이 유닛의 평타 트리거는 어느 것인가」

같은 더미가 여러 자리에서 소환되는 건, **여러 유닛이 같은 더미를 쓰기 때문**이었다.

| 더미 | 유닛 | 소환 지점 | 그중 **이 유닛의** 평타 트리거 | 진입 게이트 |
|---|---|---|---|---|
| `e00E` | `h030` 쿠마 | `Legend6` · `kuma_warp` | **`Legend6`** | **1/10** ✅ |
| `e00B` | `h031` 후지토라 | `Legend11` · `Huji01` | **`Legend11`** | **1/7** ✅ |

## 여기서 얻은 것 — 방법론 19

> **소환 지점이 여럿이면 「누가 소환하나」가 아니라 「이 행의 유닛은 누구인가」로 좁혀라.**
