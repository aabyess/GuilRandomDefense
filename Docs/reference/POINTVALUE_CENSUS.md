# `GetUnitPointValue`(`upoi`) 원작 전수 — 24건 대상조건 게이트의 실체

조사: 리서치담당 / 2026-09-06
요청: PM — 「`<200`/`==200`/`>=300` 경계가 뭘 가르는지, 199/201 경계에 뭐가 있는지,
`==200`이 실재하는지, 우리 `EnemyData`(`pointValue`, 이미 필드만 만들어짐)에
어떻게 매핑하는지」

## 결론 한 줄

**`upoi`는 등급 사다리 그 자체다.** 놀거나 임의의 숫자가 아니라 **등급 이름과
거의 1:1**이고(등급마다 고유 구간), **200이 그 사다리 위에 뚫린 진짜 빈틈**(184~199
전부 비어있다) 바로 다음에 오는 "보스 전용" 특수값이다. `EnemyData.pointValue`는
**등급별로 원작 숫자를 그대로 넣을 수 있고, 보스는 정확히 200을 넣으면 된다.**

## PM 질문 하나씩

**① 199/201에 뭐가 있는가** — **둘 다 사실상 비어 있다.** 199는 이름이 깨진(인코딩
문제) 유닛 1건뿐이라 노이즈로 본다. 201은 **0건**. 즉 `<200`이 199/201을 정교하게
가르는 게 아니라, **183(로스터 최고 등급)과 200(보스) 사이에 184~199라는 16칸짜리
빈 구간**이 있고 `<200`은 그 큰 빈 구간의 이쪽(로스터 등급 전체)을 통째로 가리키는
경계일 뿐이다. **잡몹 대 보스가 아니라 "등급 사다리 전체" 대 "보스"다** — 로스터
등급엔 흔함부터 랜덤전용까지 전부 포함된다(잡몹이라는 별도 카테고리가 없다).

**② `==200`이 실재하는가, 무엇인가** — **실재한다, 28건.** 라운드 보스(도플라밍고·
아론·크로커다일·에넬·루치·키자루·센고쿠·카이도·빅맘 등 이미 알려진 보스 로테이션)와
퀘스트 미니보스 일부가 정확히 200을 갖는다. **`==200`은 확률이 아니라 "너 지금
보스 치는 거 맞아?"라는 이산 판정이다.**

**③ `>=300`이 뭘 가르는가** — **하나가 아니라 둘로 갈린다(구현측이 기존에 "200~301
전부 보스 취급"으로 뭉쳐 넣은 걸 정정해야 한다)**:
- **300 = 스토리/구역 표시 유닛**(챕터 이름이 그대로 유닛명이다 — "1.로그타운" 등).
  전투에서 실제로 맞을 일이 없는 장식용으로 보인다 — **`>=300` 분기가 걸리는 두
  트리거(`Gaban_Skill_mana`,`Legend13_2`)에서 이 갈래는 사실상 죽은 코드일 가능성이
  높다.**
- **301 = 신세계 사이드보스**(`[신세계]` 접두 4종 + 해적함대) — **이건 진짜 전투
  대상**이다. 우리 쪽 "사이드보스 광폭화 소환체"(`ORIGINAL_BOSS_COMBAT_SPEC.md` §⑦,
  이미 알려진 카테고리)와 정확히 일치하는 것으로 보인다.

**④ 우리 `EnemyData` 대응** — `EnemyData.pointValue`(방금 구현측이 필드만 만들어둔
그 자리)에 **원작 숫자를 등급별로 그대로 넣으면 된다**, 값으로 대조해 확인했다:

| 우리 등급 | 넣을 `pointValue` |
|---|---:|
| 흔함 | 1~9 중 하나(개별 유닛 인덱스, 큰 의미 없음 — 통일하려면 아무 한 자리 수) |
| 안흔함 | 70 |
| 특별함 | 80 |
| 희귀함 | 90 |
| 전설적인 | 101(표준) — 상위 변형(로우 등)은 111~119 개별값, 우리가 그 변형을 갖고 있으면 순위별로 달리 줘도 원작과 어긋나지 않는다 |
| 특수함 | 102 |
| 변화됨 | 103 |
| 제한됨 | 108~110(서브티어 있음, 기본은 110 권장) |
| 초월함 | 131 |
| 불멸의 | 151 |
| 영원한 | 161 |
| 랜덤전용 | 180(`[제한됨]` 서브태그 붙은 것은 181) |
| 히든 | 대부분 101과 겹쳐 나온다(등급표만으론 히든 전용값이 안 깨끗하다) — `[미확인]`, 필요하면 히든 유닛만 추려 재조사 가능 |
| **보스**(`isBoss=true`, 라운드보스) | **정확히 200** |
| **신세계 사이드보스** | **301** |
| (스토리 마커, 전투 무대응) | 300 — 우리 쪽엔 대응 유닛 없음(장식용) |

⚠️ **"모양이 같다고 대응은 아니다" 재확인**: 구현측이 이미 넣어둔 `takesPercentDamage`
(bool, `<200`을 미리 등급-무관 "보스냐 아니냐"로 뭉쳐놓은 필드)는 **①②까지는 맞는
근사**이지만(로스터 전체 vs 라운드보스), **③(300 vs 301)은 놓치고 있다** — 지금
`takesPercentDamage`는 신세계 사이드보스도 "보스"로 묶어 `false`(200 취급)를 줬을
가능성이 있는데, 원작에선 신세계 사이드보스가 **301**(보스 200과 다른 값)이라
`Gaban_Skill_mana`/`Legend13_2`의 3단 분기(`<200`/`==200`/`>=300`)에서 **"보스"와
"신세계 사이드보스"를 같은 값으로 취급하면 그 두 트리거만 원작과 달라진다.** 지금
당장 `SkillEffect.targetCondition`을 쓰는 게 0건이라 회귀는 없지만, 나중에 이 둘을
배선할 때 **200과 301을 구분해서 넣어야 한다**는 걸 남긴다.

## 방법

`war3map.w3u`에서 `upoi` 필드(타입=int, 태그 직후 4바이트 type + 4바이트 값 —
level/dataId 없는 짧은 헤더라 다른 필드와 바이트 레이아웃이 다르다는 걸 처음에
놓쳐 재조회했다)를 가진 유닛 459개 전수(값 0인 86개는 논전투/미사용으로 제외)를
`unam`으로 이름을 붙이고 등급 텍스트와 대조했다.
