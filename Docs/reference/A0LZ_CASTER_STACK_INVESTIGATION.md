# `A0LZ` 캐스터 자신 강화스택 — 조사 결과

조사: 리서치담당 / 2026-09-06
요청: PM — 「`vivi_Skill_4_Mana`에서 발견된 `A0LZ` 결측, 규모부터 재라 — 정체·상승법·
사용유닛수·기존대응·유사축 전수」

## 결론 요약

- **`A0LZ`는 비비(문필환) 1명 전용이다.** 다른 캐릭터가 안 쓴다 — 작은 문제다.
- **레벨 자체(0~10)가 진짜 스탯이고, 능력 고유 필드(`Hbh1`/`Hbh2`)는 상수라 의미
  없다** — `A11S`와 같은 "카운터 전용" 부류다.
- **올리는 법이 확인됐다** — 자가 시전 강화 버튼, 실패해도 자원이 나간다, 성공률이
  레벨마다 9%씩 깎여 레벨10에서 정확히 0%(그 이상 못 감). 자원은 **랜덤위습**(흔한
  자원, 라운드당 2개 공급) + 목재 소량이라 등급조합용 희소 위습과는 무관하다 —
  **원작에서 실제로 레벨10까지 도달 가능하다**(기대 시도 32.5회, 랜덤위습
  약 98개·목재 65 — 75라운드 안에서 충분히 벌 수 있는 양).
- **우리 엔진에 이 정확한 축(캐스터 소유·0~N·성공확률로 오르는 영구 강화)은 없다**
  — `CasterSkillLevel`(능력레벨 1/2 전용, 파일 설명문이 이미 "구조상 안 맞다"고
  검토·기각함)·`CasterStrength/Agility/Intelligence`(영웅스탯)·
  `casterBuffCountFactor`(현재 버프 개수, 영구 아님) 셋 다 확인했고 셋 다 다르다.
  **새 축이 필요하다는 결론이 맞다.**
- **비슷한 패턴이 더 있는지 전수해봤다** — `IncUnitAbilityLevelSwapped` 전체 26건
  중 `A0LZ`형(자가 시전 강화 버튼 + 실패시도 자원소모)은 **추가로 확인 안 됨**.
  25건 중 상당수는 다른 부류(전투 중 평타/스킬로 쌓이는 콤보 스택 — `A0QW`/레베카
  등, `Aegr`/`AIsr`와 같은 "전투 스택" 계열)라 **A0LZ와 같은 시스템으로 묶으면
  안 된다.** 전부 개별 확인은 못 했다 — 아래 "남은 것" 참고.

## ① `A0LZ` 레벨별 값 — 플래토 확인

`base=ACbh`(오브형 패시브, `Hbh1`=명중시추가피해 확률류, `Hbh2`=배수류 필드).
**레벨 1~10 전부 덤프했다 — `Hbh1`=10.0, `Hbh2`=5.0로 10레벨 내내 완전히 고정.**
`Aegr`류처럼 레벨에 따라 값이 등차로 오르다 꺾이는 배열이 **아예 없다** — 애초부터
상수다. 즉 **능력 자신의 필드값은 장식이고, 밖에서 `GetUnitAbilityLevelSwapped
('A0LZ',캐스터)`로 읽는 레벨 정수 그 자체가 진짜 스탯**이다(`A11S`와 동일 부류).
읽는 곳(5곳, `vivi_skill_2/3/4/5`)이 실제로 쓰는 공식: `(300,000+대상최대체력×
0.10)×(1+레벨×0.05)` 류 — 레벨이 오를수록 최종 배율이 1.00(레벨0)→1.50(레벨10)까지
선형으로 오른다(파일 설명문의 "배율 1.00~1.50"과 정확히 일치).

## ② 올리는 법 — 전부 원문으로 확인

- **트리거**: `Trig_vivi_upgrade`(조건: `GetSpellAbilityId()=='A0M0'` — 비비 자신에게
  거는 자가시전 스킬).
- **입장 조건**(`Func001C`): 플레이어 목재 ≥2 **AND** 맵 전체에 `e0IX`(랜덤위습)
  소유 유닛이 3기 이상 있어야 시전 자체가 가능(부족하면 "랜덤위습의 개수나 목재가
  부족합니다" 메시지, 오더 취소).
- **소모**(성공·실패 무관, 매 시도): **목재 2 + 랜덤위습(`e0IX`) 3기**(맵에서 무작위
  로 3기를 집어 제거).
- **성공률**(`Func001Func003C`): `(90 − 레벨×9) >= GetRandomInt(1,100)` → **레벨 L
  에서 성공확률 = (90−9L)%**. 레벨0=90%, 레벨5=45%, 레벨9=9%, **레벨10 이상은
  0%**(수식이 자연스럽게 상한을 만든다 — `alev=10`과 정확히 맞물린다).
- **성공 시**: `A0LZ` 레벨+1 외에 **부가 효과 3종**도 조건부로 같이 오른다
  (`A0M1`+1레벨, `A122` 능력 추가+버프트리거 등록, `A0M2`+1레벨, 그리고 특정 조건에서
  `A0M0`(강화 버튼) 자체를 비활성화) — **비비 전용 복합 강화 패키지**이지 `A0LZ`
  단독이 아니다. `A0M1`/`A0M2`/`A122`가 뭘 하는지는 이번 조사 범위 밖(요청은
  `A0LZ`만)이라 안 팠다.
- **자원 성격**: `e0IX`(랜덤위습)는 **등급 조합용 희소 위습과 다른 자원**이다
  (`ACQUISITION_RESEARCH.md`/`BALANCE_RESEARCH.md` 기존 조사 재확인) — 시작 4기 +
  **라운드마다 2기**(페널티 없으면) 지급, 획득 경로 추가多(도박 보너스 등). **흔한
  자원**이라 `WISP_BUDGET_TIER_CEILING` 문서가 다루는 "등급 사다리용 위습 극희소"
  문제와는 무관하다.

### 도달 가능성 — 레벨10까지 기대 비용

레벨 L→L+1 성공확률 $p_L=(90-9L)\%$이므로 기대 시도 횟수 = $\sum 1/p_L$:

```
레벨0→1: 1/0.90=1.11   레벨1→2: 1/0.81=1.23   레벨2→3: 1/0.72=1.39
레벨3→4: 1/0.63=1.59   레벨4→5: 1/0.54=1.85   레벨5→6: 1/0.45=2.22
레벨6→7: 1/0.36=2.78   레벨7→8: 1/0.27=3.70   레벨8→9: 1/0.18=5.56
레벨9→10: 1/0.09=11.11
합계 ≈ 32.5회 시도
```

시도당 랜덤위습3+목재2 소모 → **레벨10 도달까지 기대 랜덤위습 ≈ 98개, 목재 ≈ 65**.
공급(라운드당 2개+시작4)만으로 약 47라운드째 누적 98개 — **75라운드 게임에서
현실적으로 레벨10 완주가 가능하다.** (다른 데 안 쓰고 전부 저금한다는 가정 — 실제로는
랜덤위습을 흔함 조합에도 쓰므로 경쟁이 있을 수 있다, `[근사]`.)

## ③ 사용 유닛 수 — **1명(비비)뿐**

`GetUnitAbilityLevelSwapped('A0LZ',...)` 읽는 곳 5곳 전부 `Trig_vivi_skill_2/3/4/5`
안이고, 올리는 곳(`IncUnitAbilityLevelSwapped`) 1곳(`Trig_vivi_upgrade`)도 비비
전용이다. **다른 유닛이 `A0LZ`를 쓰는 증거 없음.** 작은 문제 맞다.

## ④ 우리 엔진에 이미 있는가 — **없다, 셋 다 확인하고 다 다름**

| 후보 | 뜻 | `A0LZ`와 다른 점 |
|---|---|---|
| `SkillEffectBasis.CasterSkillLevel` | 능력 레벨 1/2, `levels[0]/[1]` 1:1 대응 | `A0LZ`는 0~10(11단), 이미 파일 설명문이 "구조상 안 맞다"고 검토·기각(비비 파일 자체 근거) |
| `CasterStrength/Agility/Intelligence` | 영웅 스탯(STR/AGI/INT) | 완전히 다른 축, 아직 값 자체가 0(01번 대기) |
| `casterBuffCountFactor`(`CountCasterBuffs()`) | **현재** 걸린 버프 개수 | 일시적(버프 사라지면 0으로 리셋) — `A0LZ`는 **영구** 누적(리셋 없음) |

**세 후보 다 확인했고 다 아니다 — 새 축이 필요하다는 결론이 맞다.** 이름 제안은
안 한다(설계는 구현 몫) — 다만 "유닛(비비) 하나가 소유하는 0~N 정수, 성공확률
게이트로만 오르고 리셋 없음"이라는 요구사항만 남긴다.

## ⑤ 비슷한 "캐스터 자신 스택" 축이 더 있는가 — **부분 조사, 완전 전수 아님**

`IncUnitAbilityLevelSwapped`(자기증분 패턴) 전체 **26건**을 훑었다:

- **`A0LZ`(비비)만 "자가시전 강화버튼 + 실패해도 자원소모 + 성공확률 체감"
  패턴이 확인됐다.**
- **`A0QW`(레베카, `Trig_RebecaAttack`에서 증분)** 같은 것들은 **평타/전투 중에
  쌓이는 콤보성 스택**으로 보인다(`Aegr`/`AIsr`처럼 전투 중 축적, `A0LZ`처럼
  자원 소모형 영구 강화가 아니다) — **다른 시스템으로 분류해야 한다, `A0LZ`와
  안 섞는다.**
- 나머지 24건은 읽는 곳(`GetUnitAbilityLevelSwapped`)이 0~2회뿐이라 개별 확인을
  다 못했다 — **`[미확인]`으로 남긴다.** 필요하면 26건 전부 증분 트리거의 원문을
  펼쳐 "자가시전+자원소모+확률체감" 패턴인지 개별 판정하겠다(시간이 걸린다,
  A0LZ 하나에 든 시간의 몇 배 수준으로 추정).

## 남은 것

- `A0M1`/`A0M2`/`A122`(비비 강화 성공 시 같이 오르는 부가 효과 3종)는 이번 조사
  범위 밖 — 필요하면 별도 요청.
- 26건 중 22건(A0LZ·A0QW 제외)의 개별 원문 판정 — 필요 시 이어서.
