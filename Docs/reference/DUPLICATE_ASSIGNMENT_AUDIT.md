## 결론 먼저

**설계(원작<로스터라 남는 슬롯을 채우려 재사용)가 아니라 버그다.**
`generate_unit_skill_damage_effects.py`가 `ORIGINAL_SKILL_DAMAGE_TABLE.csv`를 **원작 유닛ID로
묶지 않고 행(row) 단위로** 등급 안 순위 매칭한다(`load_csv()`가 `by_grade[등급].append(r)`만
하고 uid로 `groupby`하지 않음). 원작 캐릭터 하나의 능력이 **같은 트리거 아래 계산식이
여러 줄**(예: 한 방은 Flat, 다른 한 방은 %현재체력)이면 그 행 개수만큼 **서로 다른
로스터 유닛에 쪼개져 배정된다** — 슬롯이 남아서가 아니라, 애초에 "이 여러 행이 같은
능력"이라는 걸 이 스크립트가 모른다.

### 실측 사례 (직접 파일 확인, 둘 다 살아있는 로스터 참조)

```
h01S 벤 베크만(Trig_Unique21) — 계산식 2줄(Flat 10,000 / 대상현재체력×0.01+20,000)
  → 희귀함_임채민(Flat 10,000)  +  희귀함_양재모(대상현재체력×0.01+20,000)
  두 유닛이 "벤 베크만의 같은 트리거"를 나눠 맞고 있다 — 원작은 한 캐릭터의 한 능력.

h02M 베이비5(Trig_Unique29) — 계산식 3줄
  → 희귀함_이용민(1줄) + 희귀함_두유찬(1줄) + (3번째 행은 순위 밖으로 드롭 가능성, 미확인)
```

### 등급별 「원작 행수 vs 가용 로스터」 관계로 본 판단 근거

- **희귀함(41행/43슬롯)·전설적인(60행/33슬롯, 원작이 더 많음에도 발생)·영원한(24행/7슬롯,
  원작이 훨씬 많음)** — 어느 쪽도 "로스터가 남아서" 상황이 아니다. 특히 전설적인·영원한은
  **원작 행수가 가용 로스터보다 훨씬 많은데도** 중복이 난다 — "남는 자리 채우기"라면
  원작이 로스터보다 적은 등급에서만 나야 하는데 그 반대 등급에서도 똑같이 난다.
  → **행 단위 매칭이라는 구조적 원인 하나로 전 등급에서 일관되게 재현된다.**
- 불멸의(20행/4슬롯)처럼 원작이 로스터보다 압도적으로 많은 등급에서도 중복이 1건
  나는데, 이건 "자리가 남아 재사용"이 아니라 **상위 4순위 안에 우연히 같은 uid의
  행 2개가 둘 다 들어간 것**이다(그 uid의 다른 행들은 오히려 순위 밖으로 밀려
  드롭됐을 수 있다 — 별도 확인 필요, 이번 조사 범위 밖).

## 조사 방법
`Tools/generate_unit_skill_damage_effects.py`의 `load_csv()`/`load_roster()`/`GRADE_ENUM`을
그대로 불러와(import) 각 등급의 `ability_rows`(정렬된 원작 행 리스트)와 `eligible`
(가용 로스터 리스트)를 재현하고, `n=min(len(ability_rows), len(eligible))`으로 실제
잘리는 지점까지의 상위 n행 안에서 유닛ID가 2번 이상 나오는 경우를 셌다. 파일 수정 없음.
