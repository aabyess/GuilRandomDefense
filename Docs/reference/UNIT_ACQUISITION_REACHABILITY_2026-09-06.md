# 유닛 획득 경로 전수 · 조합식 의존 그래프 도달성 — 2026-09-06

작성: 구현담당2. PM 지시 — "조합식 207개의 재료 의존 그래프"를 확률 가정 없이 순수
데이터로 만들고, 잎(leaf) 재료가 실제로 가챠(또는 그 밖의 실배선 경로)로 나오는

## 🔴 ① 첫 시도가 틀린 기준으로 돌아갔다 — `GachaTable.weight`는 죽은 필드

**처음에는 "가챠로 나오는 등급 = `MainGachaTable`에서 `weight>0`인 등급(0~3)"으로
잡고 로스터 240종을 검사했더니 60종(초월함 전체 포함)이 "도달 불가능"으로 나왔다.**

**이 기준 자체가 틀렸다.** `GachaTable.cs`에 이미 이렇게 적혀 있다(2026-09-05 감사,
기존 주석 — 내가 새로 쓴 게 아니다):

> "`Roll()`(weight 기반 등급 선택)을 부르는 곳이 코드에 0건이다 — 실제 지급 경로
> (`UnitPortal.RollReward`)는 `RollFromGrade`로 등급을 **직접 지정**해서 weight를
> 아예 안 본다."

즉 **`weight` 컬럼은 죽은 값**이고, 실제로는 각 포탈이 `RollFromGrade(그 등급)`을
직접 호출해 그 등급 `pool`에서 균등 랜덤으로 뽑는다. weight=0인 히든(grade4)도
`pool`엔 22종이 채워져 있다 — **포탈만 실제로 그 등급을 부르면 얼마든지 나온다.**

**`BALANCE_SIMULATION_2026-09-05.md` §10-5의 "GachaTable grade4+ weight=0이라
결측" 지목 자체가 죽은 필드를 근거로 삼은 오판이었다 — 해당 문서에 취소선+정정을
달았다.**

⚠️ **`GachaTable.weight` 필드 자체는 여전히 죽어 있다** — 있는데 아무 영향이 없는
상태라 같은 오판이 반복될 수 있다. 쓰거나 지우거나 해야 하는 채무로 남겨둔다
(판단은 나중, 지금은 목록에만 올림).

## 🔴 ③ 히든(4) 포탈 미배선 — 버그가 아니라 설계였다

`MapGenerator.cs`의 뽑기 밴드 목록:
```csharp
GachaBand.Random("전설·히든", UnitGrade.Legendary),  // 라벨은 둘, 인자는 하나
```
**라벨은 "전설·히든"인데 실제 인자는 `UnitGrade.Legendary` 하나뿐** — 처음엔 "오늘
여러 번 나온 라벨-배선 불일치 패턴"으로 의심했다. **그런데 `HiddenCombineManager.cs`
자체 주석에 이미 답이 있었다:**

> "PM 지시(2026-09-05): CombineSystem(우리 UI 클릭 조합)에 합치지 않는다 — 원작은
> 입력 경로 자체가 다르다(유닛을 겹쳐두는 게 아니라 채팅으로 확인한다)."

**히든은 원래부터 뽑기 포탈 소관이 아니었다** — "전설·히든" 라벨은 그냥 부정확한
이름이었을 뿐(수정하면 되는 사소한 문제), 실제 획득 경로는 `HiddenCombineManager`
쪽에 이미 따로 구현돼 있다. **버그 vs 설계 질문의 답은 "설계"다.**

**다만 지금 당장은 히든 23종 전부 재료 데이터가 비어 있어 조합이 항상 실패한다** —
이것도 이미 코드에 명시된 의도된 상태다:

> "재료 슬롯마다 unit이 비어 있으면(사장님 배정 전) 그 슬롯은 영원히 못 채운다...
> 지금은 23개 전부 재료가 비어 있어 조합이 항상 실패한다(의도된 상태, 값이 채워지면
> 자동으로 살아난다)."

**즉 히든은 "배선 버그"가 아니라 "콘텐츠 대기"다.** 사장님이 23종의 재료를
배정하면 자동으로 풀린다.

## ④ 조합식 207개 의존 그래프 — 최종 도달성 (확률 무관, 순수 데이터)

leaf 등급을 위 ②의 실배선 기준(0·1·2·3·5·7·8·9·10·11·12 + 특수지급 3종 + 스토리
보상 1종)으로 다시 잡고 207개 조합식(재료 1~8개, 중앙값 3개, 재귀 포함)을 전부
해석했다.

```
사이클: 0건
남은 도달 불가: 8건 → 실제로는 6건(아래 참고)
  히든(4)      5건 — 맥주만땅·감탄떡볶이·이삭토스트·이요한·미소야 (③의 콘텐츠 대기 그대로)
  초월위습(13) 2건 — 박은석 초월위습·해적선 → 둘 다 특수지급/스토리보상으로 실제로는 해결됨
                     (내 조합식 파서가 이 두 경로를 몰라서 "도달불가"로 잘못 표시한 것일 뿐)
  제한됨(6)    1건 — 강보명
```

**강보명(제한됨)을 직접 열어봤다** — `Assets/Data/Recipes/제한_강보명.asset`:
```
재료: 전설적인_임채현(호모사피엔스, 도달✅) + 히든_이요한(도달❌, 콘텐츠 대기) + 희귀함_고어진(도달✅)
비용: 5000엔 + 목재5, R40 이전만
```
**제한됨(강보명)이 막힌 이유는 별개 버그가 아니라 히든 콘텐츠 대기가 그대로
전파된 것이다** — 재료 셋 중 하나가 히든이라, 히든이 풀리면 강보명도 자동으로
풀린다. **진짜 새로 발견된 결손은 0건이다** — 전부 이미 알려진 히든 콘텐츠 대기
하나로 수렴한다.

### 조합 깊이 분포 (leaf에서 몇 단계 만에 도달하는가)

조합으로만 도달하는 유닛 약 80종 중: 깊이1=54종, 깊이2=21종, 깊이3=5종. **깊이가
얕다(최대 3단)** — PM이 예상한 대로 "손으로도 셀 수 있는" 수준이라, **몬테카를로
없이도 이 그래프 자체로 "무엇이 무엇에 의존하는가"는 이미 답이 나온다.**

## ⑤ 결론 — 몬테카를로가 필요한가

**필요 없어 보인다, 지금 질문에는.** "조합식이 구조적으로 완성 가능한가"(도달성)는
확률과 무관하게 이 그래프만으로 이미 100% 가깝게 풀렸다(강보명 1건 빼고 전부 해결,
그 1건도 히든 콘텐츠 대기로 수렴). **몬테카를로가 필요해지는 지점은 "도달 가능한가"가
아니라 "라운드 R까지 실제로 도달할 확률이 얼마인가"(속도) 질문으로 넘어갈 때다** —
그건 여전히 위습 지급 스케줄·가챠 풀 크기·조합 순서 선택이 얽힌 별도 작업이고,
지금 이 문서의 범위 밖이다.

**`tier_for_round`(§`TIER_SCHEDULE_CONFIDENCE_2026-09-06.md`)의 신뢰구간을 좁히는
작업으로 이어가려면**, 이 도달성 그래프에 "라운드별 위습 지급량"과 "가챠 풀 크기당
평균 시도 횟수"(쿠폰 수집가 문제)를 얹어야 하는데, 이건 규모가 있는 별도 작업이다
— 착수 여부는 판단을 구한다.
