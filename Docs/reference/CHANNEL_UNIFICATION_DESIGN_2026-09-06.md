## 배경

`check_assignment_invariants.py`(구현담당3)가 원작 유닛 키(description에서 추출) 기준으로
같은 원작 캐릭터의 스킬이 **로스터 두 곳 이상**에 걸친 사례를 찾는다. 06번① 구형 14개
description을 파싱 가능하게 고친 뒤(`77e8d49`) **35건 → 39건**으로 늘었다(예고된 대로).

## 🔴 뿌리 ⑮의 세 번째 얼굴 — 1채널도 행 단위 매칭 버그가 있다

39건의 tie-break를 설계하다가, 원작 하나(uid)에 능력이 여러 개면 **1채널
(`generate_unit_ability_skills.py`)도 그 능력 개수만큼 서로 다른 로스터 유닛에
쪼개고 있다**는 걸 발견했다 — `by_gate`(넘치는 원작을 조용히 드롭)·2채널(행 단위
매칭)에 이은 **같은 실수의 세 번째 얼굴**이다.

```
by_gate            원작 > 로스터 → 넘치는 것을 조용히 드롭        13유닛 19행 (회수 완료, 6505647)
skill_damage(2채널) 행 단위 매칭 → 한 원작이 여러 로스터로 분산   32유닛 → 77슬롯 (재배정 완료, ca753e0)
ability(1채널)      행 단위 매칭 → 같은 버그, 미수정              104 uid 중 22개가 능력 2개 이상
```

실측(`generate_unit_ability_skills.py` 재시뮬레이션, 파일 안 건드림):

| | 현재(행 단위) | uid 단위 재배정 후 |
|---|---:|---:|
| 로스터 유닛(=SkillData 파일) 수 | 102 | **94**(−8) |
| 실제 배치된 고유 원작 uid 수 | 90 | **94**(+4) |

2채널이 122→92슬롯으로 정리됐던 것과 같은 모양의 개선이다 — 중복이 사라지고
빈 슬롯만큼 새 원작 캐릭터가 더 들어간다.

**세 생성기가 독립적으로 같은 실수를 세 번 냈다는 것 자체가 신호다.** ⑤-0을 만들
때 "uid로 묶어 등급 안 순위매칭" 로직을 **한 곳(공용 헬퍼)에 두고 세 생성기가 같이
쓰게** 한다 — 지금처럼 스크립트마다 따로 구현하면 네 번째 얼굴이 또 나온다.

## 확정된 실행 순서

```
⑤-0  1채널 uid 단위 재배정        ← 새로 추가, 2채널 regroup(ca753e0)과 같은 패턴
       + uid-단위-순위매칭 공용 헬퍼를 만들어 by_gate·2채널·1채널이 같이 쓰게 정리
⑤-1  채널 태깅을 정확히 다시      ← ⑤-0 결과 위에서, "문자열 포함"이 아니라
       "검사기가 실제로 집은 키가 어느 채널 문구에서 나왔는지" 기준으로
⑤-2  ①②④ 적용 — 재순위매칭 tie-break · 히든 3자 순환 별도처리 · 게이지 충돌 검사
```

### ⑤-0이 필요한 이유(실측) — 채널 태깅 오류의 원인이기도 했다

"동순위(같은 채널끼리 충돌)" 사례를 검증하다가, 미호크 건(`세계 최강의 대검호
쥬라클 미호크 - 영원한`)이 **1채널 안에서 같은 uid의 능력 2개(A0HV·A0G3)가 애초에
서로 다른 로스터(영원_문필환/영원_김영원)로 쪼개진 것**임을 확인했다. 이 파일들에
2채널 내용도 나중에 얹혀 있어서(`append_to_existing`), "2차 배정 문자열이 있으면
2채널" 기준으로 태깅한 어제 보고의 **"2채널 vs 2채널 11건"은 부정확할 수 있다**
(실제로는 1채널 내부 충돌인데 2채널로 잘못 표시된 사례 포함) — ⑤-1에서 바로잡는다.

### ⑤-0 적용 후 위반 건수 예측(시뮬레이션, 파일 미변경)

1채널 기여분(설명에 "원작 능력표(ORIGINAL_UNIT_ABILITIES.csv)" 마커가 있는 파일
100개)을 현재 집계에서 빼고, uid 단위로 재계산한 1채널 결과로 교체해 재검산:

**39건 → 33건**(−6). 단, **구성이 그대로 줄어드는 게 아니라 바뀐다** — 1채널
자체 충돌 일부(미호크·비비 등)는 사라지지만, uid 재배정으로 로스터 유닛이 새
원작을 받으면서 06번①/게이트/2채널과 **새로 부딪히는 사례도 생긴다**(예: "제트
해군 스승 Z", "몽키.D.거프", "실버즈 레일리"가 예측 목록에 새로 등장 — 이 셋은
이미 A그룹 특성 승자가 있는 키라 ⑤-2에서 원칙 1로 바로 정리될 가능성이 높다).

**→ 결론: 지금 갖고 있던 "동순위 14건" 표는 ⑤-0 이후 다시 계산해야 한다.**
이 문서에 있던 구버전 A/B/동순위 상세 표는 폐기하고, ⑤-0 적용 뒤 ⑤-1(정확한
채널 재태깅) → ⑤-2(재순위매칭 tie-break)를 그 결과 위에서 새로 돌릴 것.

## ⑤-2에서 쓸 확정 원칙 (PM 지시, 순서 안 바뀜)

1. **특성(06번①) 우선** — 사장님 확정 26명 배정이 항상 승자.
2. 나머지는 **채널 우선순위**: 06번① > 게이트/회수·절대쿨 > 1채널(⑤-0 이후) > 2채널.
3. **동순위(같은 채널끼리) tie-break = 재순위매칭이다, 임의 기준(알파벳 등) 금지.**
   원작 쪽 점수가 높은 쪽이 로스터 쪽 DPS가 높은 자리를 갖고, 진 쪽은 그 등급의
   다음 빈 자리로 재배치한다.
4. **히든 3자 순환**(반더데켄·아카이누·코알라, ⑤-0 이후에도 재현되면 — 위 예측
   목록에 셋 다 그대로 있다) — 채널우선순위를 기계적으로 적용하면 승자가 계속
   바뀌는 순환이 생긴다. 게이트 몫은 그대로 두고, **1채널 몫만 따로 떼어 히든
   등급 안에서 재순위매칭**한다.
5. **게이지 재검토 필수** — 이관 후 한 로스터 유닛이 여러 채널의 게이지 스킬을
   동시에 가지면(마나 125+마나 85처럼 종류는 같고 임계값이 다르면 먼저 찬 쪽이
   리셋해 나머지가 영영 안 닿는다), 그 이관은 **보류**하고 목록에 남긴다(오늘 밤
   시키 배정 때와 같은 판단 기준).
6. **적용은 "전체 계산 → 한 번에 적용"** — 순차 적용 금지(불멸_정윤식·불멸_고도현처럼
   한 유닛이 여러 이관에 동시에 걸리는 사례가 있어, 중간 상태로 저장하면 꼬인다).
7. **파일명은 리네임한다**(참조만 옮기는 방식 금지 — 파일명이 옛 로스터를 가리키면
   반드시 누군가 나중에 밟는다, 오늘 밤 검사기 버그가 그 예). **내용 변경과
   리네임은 별도 커밋으로 나눈다**(diff 리뷰 가능하게).
