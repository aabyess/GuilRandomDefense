# 꼬리표 전수 재집계 — 클라우드 세션 결과 로컬 재현(커밋 유실분 복구)

조사: 리서치담당 / 2026-09-07. 어젯밤 예약된 클라우드 세션이 이 조사를
끝냈으나 GitHub push가 403으로 막혀 저장소에 결과가 없었다(사장님
대화창에 파일로만 전달됨) — PM 지시로 **같은 조사를 로컬에서 재현**했다.
처음부터 다시 짠 게 아니라 클라우드가 낸 결론을 검증하는 것이 목적이다.

## 방법

`Assets/Data/UnitSkills/*.asset`의 `description` 필드 전체(384개 파일,
정규식으로 `description:` 줄 추출)를 파이썬으로 훑어, 클라우드가 보고한
15개 유형별로 특징적 문구를 정규식으로 찾아 **파일 단위 집합**(한 파일에
같은 유형 문구가 여러 번 나와도 그 파일은 1건으로만 센다)을 만들고,
유형 간 합집합으로 "근사 꼬리표 하나 이상 걸린 파일 수"를 냈다. 클라우드가
쓴 정확한 정규식은 알 수 없으므로 **각 유형의 실제 문구 표본을 먼저 읽고
그 표본에서 정규식을 역산**했다(추측 아니라 원문에서 뽑음).

## 🔴 먼저 — 파일 수가 384개다, 클라우드의 385개와 다르다

이유는 확인 못했다(그 사이 파일이 하나 늘거나 줄었을 수 있다 — 이
세션에서 `Assets/Data/UnitSkills/`를 건드린 적은 없다). **비율 계산엔
내가 실제로 센 384를 분모로 썼다**(클라우드의 385 대비 결과와 각주로
같이 적는다).

## 합계

```
15개 유형 합(중복 포함)     내 재현: 473   (클라우드: 474, 거의 일치)
근사 꼬리표 하나 이상 걸린 파일(합집합)  내 재현: 284개 / 384개 (73.96%)
                                        (클라우드: 288개 / 385개, 74.8%)
```
**클라우드 결론과 큰 틀에서 일치한다** — 대략 74%의 스킬 자산 파일에
근사·미확인류 꼬리표가 걸려 있다. 284 vs 288(4건 차이), 73.96% vs
74.8%(0.84%p 차이)는 위 표의 "값겹침모호/유예"(−3건)와 파일 수
자체의 384 vs 385(−1건) 차이로 대부분 설명된다.

## 옛 3패턴(§0) 재확인 — 클라우드 주장과 정확히 일치

```
옛 방법(정규식 3패턴: [게이트 미확인]·[미확인]·축밖 계열)을
지금 384개에 적용 → 121건 (31.4%)
```
**클라우드가 "옛 3패턴을 지금 385개에 적용해도 121건뿐"이라고 한
숫자와 정확히 같다(121).** `APPROXIMATION_LEDGER.md` §0의 "116개
(31.8%)"는 그때 기준 파일 수(365개 무렵)로 잰 것이고, **근사가 실제로
늘어난 게 아니라 파일이 늘고(365→384) 세는 방법(정규식 패턴 15종
vs 3종)이 넓어진 것**이라는 클라우드 결론이 원문 재확인으로 검증됐다.
