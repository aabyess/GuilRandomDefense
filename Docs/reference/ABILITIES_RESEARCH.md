# 원작 능력(w3a) 조사 (2026-09-04, 구현담당1)

> 조사 방법: `Tools/w3x/w3a.py`(신규)로 `war3map.w3a`(1,628개 능력, 115종 기반 템플릿에서 파생)를
> 직접 파싱, `war3map.wts`로 이름 문자열 해석. `ordsearch.net` 등 웹 조사가 아니라 **원작 데이터
> 파일을 직접 읽은 것**이라 이 문서 안의 수치·문구는 전부 [원작 데이터 확정]이다 — 추정이 섞인
> 곳만 별도 표기했다.
>
> PM 지시대로 **③(방무뎀·보잡·전체체력)과 ④(중첩·지속시간)를 먼저** 다룬다.

## 요약

| 질문 | 답 | 확신도 |
|---|---|---|
| 방무뎀 30%가 맞는가 | **아니다 — 유닛마다 다르다.** 30%는 여러 값 중 하나(예시 하나)였을 뿐, 고정 상수가 아니다 | 높음(원작 데이터 직접 확인) |
| 보잡(전체체력5%) 기준 | **대상(target)의 전체체력**, 그리고 **대상 종류별로 % 자체가 다르다**(일반/보스/스토리) | 높음 |

| 방깎은 중첩되는가 | **된다. 원작 전역에서 일반적인 패턴이다.** 다만 **무한 중첩이 아니라 능력마다 다른 상한**이 있다 | 높음 |

## ③ 방무뎀 · 보잡 · 전체체력

### 방무뎀(방어무시 데미지) — 고정 30%가 아니라 유닛마다 다른 값이다

`ACce` 기반 능력(이름에 "방무뎀"이 들어간 것) 5종을 전수 확인했다:

| 능력 | 수치(`nca1` 필드) | 툴팁 원문 |
|---|---|---|
| !방무뎀1 | **45%** | "350범위의 적들에게 현재 공격력의 45% 방어무시 데미지" |
| !시노부분신평타방무뎀 | **50%** | "350범위의 적들에게 현재 공격력의 50% 방어무시 데미지" |
| !노래노래열매-방무뎀 | **30%** | (스턴형이라 %는 다른 능력에, 이 이름의 인스턴스만 30%) |

**결론**: `nca1`이라는 능력 필드에 소수(0.3/0.45/0.5 등)로 직접 박혀 있고, 툴팁 문구가 그 값을
그대로 설명한다 — **"공격력의 N% 만큼 방어를 무시하는 추가 피해"**가 방무뎀의 정확한 정의다.
N은 30~50% 사이에서 능력마다 다르다. **사장님/구현담당3이 말한 "30%"는 실존하는 값(노래노래열매)
이지만 전체를 대표하는 고정 상수는 아니다** — 유닛별 개성 수치 중 하나다.

### 보잡 — 우리 팀 용어, 원작 개념은 "대상 종류별로 %가 다른 고정 피해"

"보잡"은 원작 게임 텍스트에 그대로 나오는 단어가 아니다(전수 검색 0건) — `UNIT_STATS_RESEARCH.md`가
조합표 약어를 풀며 붙인 우리 팀 용어("보스 잡기"의 줄임)다. 그런데 **그 개념 자체는 원작에 실제로
있다.** 예: `!급소베기-가반`(45번 공격마다 발동):

```
◎일반유닛 전체체력의 50% 고정 데미지
◎보스급유닛 전체체력의 10% 고정 데미지
◎스토리유닛 전체체력의 5% 고정 데미지
```

**핵심 발견**: 이런 "전체체력 비례 고정 데미지" 능력은 전부 **대상 종류(일반/보스/스토리)별로
다른 %를 쓰고, 언제나 보스·스토리가 더 낮다** — 큰 체력 풀에 그대로 %를 먹이면 보스 한 방에
녹기 때문으로 보인다. `UNIT_STATS_RESEARCH.md`가 "보잡(전체체력5%)"로 적은 김용태(우리 게임
개명 캐릭터)를 원작 캐릭터명으로 못 찾아서 그 정확한 인스턴스는 대조 못 했지만(이름 매핑 필요),
**"5%"가 이 패턴의 "보스급" 또는 "스토리" 구간 수치로 봐도 구조적으로 이상하지 않다.**

### 전체체력 vs 최대체력 — 같은 것이다

전수 검색 결과 "전체체력" 43회, "최대체력" 3회 — 두 표현이 **완전히 같은 문형**(`N%의 추가
물리데미지`)으로 쓰인다:

```
최대체력의 30%의 추가 물리데미지(보스/스토리 3%)      ← "최대체력" 사례
전체체력 30%의 추가 물리데미지(보스/스토리 20만)      ← "전체체력" 사례(같은 문형)
```

**결론: 둘은 동의어다.** "전체체력"이 압도적 표준 표기이고 "최대체력"은 같은 작성자가 드물게
섞어 쓴 이표기로 보인다 — 별도 스탯이 아니다.

## ④ 중첩 · 지속시간 — 방깎(아머 브레이크)은 광범위하게 중첩된다

"중첩"이 들어간 원문 24건을 전수 확인했다. **결론부터: 방깎은 원작 전역에서 흔하게 중첩되는
패턴이고, "유닛당 한 번만"은 원작 근거가 없다 — 구현담당3이 이미 스스로 "근거 없는 판단"이라고
밝힌 그대로다.**

### 방깎 중첩 사례 (일부)

| 능력 | 1회당 감소량 | 중첩 상한 |
|---|---|---|
| (여러 종) | 방어력 3/5/7 | **방어력 75 감소**까지 |
| (2종) | 방어력 10/11 | **방어력 80 감소**까지 |
| (1종) | 방어력 10 | **7중첩**까지(횟수 기준) |
| (1종) | 방어력 60, 이후 1중첩마다 6 | **10중첩**까지 |
| (1종) | 방어력 2 | **9중첩**까지 |

**상한이 능력마다 다르다** — 어떤 건 "감소량 총합"으로 상한을 걸고(75/80), 어떤 건 "중첩 횟수"로
건다(7/9/10회). 우리 `TraitEffectKind.ArmorShred`/`EnemyDummy.AddArmorShred`가 지금은 유닛
1기당 1회만 걸도록 막혀 있는데(구현담당3), **원작은 이 제한이 없다** — 여러 유닛이 같은 대상을
때리면 각자 중첩되고, 대신 총 감소량(또는 횟수)에 상한이 있다.

**부가 발견**: "아머 브레이크 중첩1마다 피해량 1.25% 증가"라는 2차 효과도 있다 — 방깎이 방어만
깎는 게 아니라, **쌓인 중첩 수 자체가 별도로 데미지 증폭 계수로도 쓰이는** 능력이 최소 2종 있다.

### 지속시간 — 서술 자체가 없다(=영구 누적형으로 보인다)

"중첩" 24건 전수를 다시 훑었지만 **"N초간"·"지속시간"류 표현이 단 하나도 없다.** 전부 "최대
N까지 감소/중첩"이라는 **상한**만 말하고, 시간이 지나면 풀리는지는 언급이 없다. 능력 파일
쪽(`adur`/`ahdu` 필드, 지속시간)도 이 계열 트리거 능력들은 전부 `0.0`이다.

**다만 완전히 확정은 아니다** — WC3 구조상 디버프의 실제 지속시간은 능력 파일(`w3a`)이 아니라
**버프 파일(`war3map.w3h`)에 별도로 있을 수 있다.** 이번 조사는 PM이 지정한 `w3a`만 팠고
`w3h`는 안 열어봤다 — `abuf` 필드(예: `B050`)가 그 버프 파일의 참조 ID다. **완전히 확정하려면
`war3map.w3h`도 파싱해야 한다**(다음 사람에게 넘김, `Tools/w3x/w3a.py`와 거의 같은 구조일 것으로
예상됨 — README의 파일 목록에 "64 KB"로 이미 잡혀 있다).

**우리 설계 시사점**: "영구 누적 + 상한" 쪽이 원작에 훨씬 가깝다. 지금 `EnemyDummy.AddArmorShred`가
시간 감쇠 없이 계속 쌓이기만 하는 구조라면 그 자체는 원작과 맞다 — **고칠 건 "유닛당 1회" 제한을
푸는 것과 상한을 추가하는 것** 둘이다.

## ① 능력 전체 개요 — 1,628개, 115개 기반 템플릿

전수 나열은 안 했다(1,628개는 문서 하나로 감당할 분량이 아니고, 우리 로스터 239종과 원작 캐릭터명이
전부 개명되어 있어 1:1 매핑 없이는 "이 능력이 우리 유닛 누구 것"인지 알 수 없다 — 이름 매핑은
별도 작업이 필요하다). 대신 구조를 정리한다.

- **115개의 "기반 능력"**(WC3 오브젝트 에디터에서 원본으로 복제해 쓰는 엔진)에서 1,628개의
  커스텀 능력이 파생됐다 — 평균 능력당 ~14개 변형.
- 가장 많이 재사용된 기반: `ACbh`(469개 파생, 예: "!시구레"·"!급소베기-가반") — 즉발형 단일/범위
  피해 계열로 보인다(파생 예시들이 전부 "발동시 즉시 피해" 툴팁).
- 능력이 전투 스킬만은 아니다 — `AHwe`(110개)·`Aroa`(52개)·`AHtc`(34개) 등 다수는 예시 이름이
  `[조합]`이다. **원작은 조합(콤보) 시스템 자체도 능력 오브젝트로 구현했다** — 우리 `CombineSystem`이
  전혀 다른 방식(별도 레시피 에셋)으로 이미 만들어져 있어 이건 참고만 하면 된다.
- 이름에 등장하는 어휘 22종(구현담당3 조사분: 단일·범퍼·보잡·방무뎀·방깍·마방깍·도킹·이감·공증·
  공속·마젠·체젠 등) 중 이번에 실물 데이터로 직접 대조한 건 **방무뎀·방깎(위 ③④)뿐**이다. 나머지
  (도킹·마방깍·마젠·체젠 등)는 이름으로 검색은 해봤으나 이번 조사 시간 안에 깊이 못 들어갔다 —
  아래 "확인 못한 것" 참고.

### 필드 어휘(관찰만, 확정 아님)

능력 데이터에서 자주 나오는 필드 코드와 관찰된 의미(WC3 표준 필드 배치 지식 + 이번 데이터
관찰을 섞은 것 — **모두 [추정], 블리자드 원본 필드 정의표와 대조는 안 했다**):

| 필드 | 관찰된 역할 |
|---|---|
| `anam` | 능력 이름(우리가 방금 검색에 쓴 것) |
| `atp1` | 툴팁 제목 |
| `aub1` | 툴팁 본문(수치·조건이 전부 여기 텍스트로 있다) |
| `adur` / `ahdu` | 지속시간(일반/영웅) — 방깎류는 전부 0 |
| `aare` | 효과 범위(반경) |
| `nca1` | 방무뎀류 능력의 %값(0.3/0.45/0.5 등) — 이번에 새로 특정함 |
| `abuf` | 연결된 버프 ID(`war3map.w3h` 참조) |
| `alev` | 레벨 수 |
| `arac` | 종족 분류(게임플레이 무관, 오브젝트 에디터 분류용으로 보임) |

## 확인 못한 것

- 도킹·마방깍·마젠·체젠 등 나머지 어휘의 실제 능력 데이터 대조 — 이번엔 시간상 방무뎀·방깎만 팠다.
- 방깎류 디버프의 정확한 지속시간(있다면) — `war3map.w3h` 미파싱.
- "보잡(전체체력5%)" 김용태의 원작 캐릭터명 매핑 — 우리 로스터 개명 때문에 직접 대조 불가.
- 능력 필드 코드의 확정 의미 — 블리자드 원본 필드표 없이 툴팁 텍스트로 역추론한 것이라 일부
  틀릴 수 있다(특히 `Hbh1`/`Hbh2`/`Hbh3`처럼 기반 능력 고유 필드는 뜻을 전혀 못 밝혔다).

## 도구

`Tools/w3x/w3a.py`(신규, w3q.py와 동일 포맷) + `Tools/w3x/wts.py`(신규, 문자열 테이블 해석).
사용법은 `Tools/w3x/README.md`의 기존 예시에 `import w3a, wts`만 추가하면 된다.
