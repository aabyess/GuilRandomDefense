## ① 위습 예산 곡선 (`WaveData.wispRewards`, 고정 스케줄)

위습은 등급별로 갈린다(`WispData.targetGrade`, 포탈은 `acceptedGrades`로 그 등급만
받는다 — 흔함 위습으로 희귀함을 못 뽑는다). 실제 75라운드 스케줄을 그대로 합산:

| 등급 | 첫 지급 라운드 | 75라운드 누적 |
|---|---:|---:|
| 흔함 | R1 | 205개 |
| 안흔함 | **R10** | **2개** |
| 특별함 | **R30** | **2개** |
| 희귀함 | **R50** | **2개** |
| 전설적인(전설·히든 위습, 실제로는 전설만) | **R65** | **3개** |
| 히든 | — | **0개**(위습 자체가 없다 — `UNIT_ACQUISITION_REACHABILITY` §① 참고) |
| 랜덤유닛·다른세계·특수함 | — | 0개(다른 채널: 위습교환/도박, 아래 참고) |

🔴 **흔함 이후로는 극도로 희소하다.** 안흔함·특별함·희귀함이 각각 게임 전체에서
딱 2개, 전설적인은 3개뿐이다. "위습을 많이 벌어서 빨리 조합한다"는 그림 자체가
안흔함 이상부터는 성립하지 않는다 — **개수가 아니라 언제 처음 나오느냐가 병목이다.**

## ② 조합 하나당 위습 하한 (`UNIT_ACQUISITION_REACHABILITY` 의존 그래프 재사용)

각 등급의 **가장 싼** 조합 경로(순수 위습 유닛만으로 만들 수 있는 경우)를 재귀로
찾았다. "완벽한 운"(뽑을 때마다 정확히 필요한 특정 유닛이 나온다) 가정이라 **하한**이다.

| 등급 | 최소 위습 요구 | 비고 |
|---|---|---|
| 안흔함 | 위습 1개(안흔함) | 리프 |
| 특별함 | 위습 1개(특별함) | 리프 |
| 희귀함 | 위습 1개(희귀함) | 리프 |
| 전설적인 | 위습 1개(전설적인) | 리프 |
| 불멸 | 전설적인 3개 | 8/8 유닛이 순수 위습 경로 있음 |

| 영원함 | 전설적인 2개 + 희귀함 3개 + 안흔함 2개 | 8개 중 2개만 순수 위습 경로 |
| 히든 | 불가능(∞) | 원작 채팅-조합 재료 23/23 전부 미배정(콘텐츠 대기) |
| **초월함** | **불가능(순수 위습 경로 없음)** | **25개 전부** — 조합식이 존재해도 재료 사슬이 결국 아래 ③의 채팅언락 없이는 안 닫힌다 |

## ③ 겹치기 — "가장 빨라도 이 라운드 전엔 불가능"

①(공급)과 ②(요구)를 겹쳐 **완벽한 운을 가정해도 도달 못 하는 최초 라운드**를 냈다.

| 등급 | 필요 위습 | 가장 빠른 가능 라운드 |
|---|---|---|
| 안흔함 | {안흔함×1} | R10 |
| 특별함 | {특별함×1} | R30 |
| 희귀함 | {희귀함×1} | R50 |
| 전설적인 | {전설×1} | R65 |
| 불멸(최소조합) | {전설×3} | **R75 (게임 마지막 라운드)** |
| 제한됨(최소조합) | {전설×2, 희귀×1} | R70 |
| **영원함(최소조합)** | {전설×2, 희귀×3, 안흔×2} | **75라운드 안에 불가능 — 완벽한 운이어도 못 만든다** |
| 초월함 | — | 순수 위습 경로 자체가 없다(②) |

🔴 **불멸은 완벽한 운이어도 R75(마지막 라운드)에야 첫 한 기가 나온다.** 영원함은
그마저도 안 된다. 초월함은 순수 위습 경로 자체가 없다. **즉 위습 조합만으로는
이 세 등급이 실질적으로 "게임 중에는 없는 등급"이다.**

**결론**: 초월함·불멸·영원함은 원작 설계상으로도 **플레이어당 딱 1기**(위 47종

얻는 경로는 통계적으로 사실상 없다(불멸조차 마지막 라운드에야 겨우 가능, 영원함은
불가능). **이 세 등급을 "여러 기 보유"로 취급하는 어떤 붕괴 모델도 원작과 크게
어긋난다.**

## 결론 — 몬테카를로가 필요한가

**아니다, 결정론만으로 이미 크게 좁혀졌다.**

```
붕괴 라운드 범위(TIER_SCHEDULE_CONFIDENCE §③, 어제)     R8 ~ R71 (63라운드 폭)
```

이 폭이 넓었던 가장 큰 이유는 tier_for_round가 **초월함·불멸·영원함까지 "여러
기 보유 가능한 등급"으로 취급**하고 라운드 스케줄에 여러 칸을 내줬기 때문이다.
**결정론적 분석은 그 전제 자체가 틀렸다는 걸 확률 없이 보여준다** — 이 세 등급은
"여러 기"가 아니라 "플레이어당 최대 1기"가 원작 상한이다. §⑤ 스윕(A안)이 이걸
실제로 tier_for_round에 반영했을 때 붕괴 라운드 범위가 얼마나 좁아지는지 잰다.

**몬테카를로가 필요한 지점은 남아 있다** — 흔함·안흔함·특별함·희귀함·전설적인
"사이" 구간에서 정확히 몇 라운드에 조합이 완성되는지(운에 따라 R10~R70대까지
분산)는 확률 없이는 못 좁힌다. 다만 그건 **위 세 최상위 등급을 뺀, 훨씬 좁은
범위** 안에서의 질문이라 규모가 확 줄어든다.

## ④ `Tech_Onedill` 확정 — "제한"이다, `war3map.j` 원문 근거 (리서치담당)

처음엔 `BOOLEAN_FLAG_CHANNEL.md`가 이 플래그를 "등급 해금 플래그"라고 불러서
내가 읽은 "플레이어당 1기 제한"과 정반대로 보일 수 있었다. 내가 낸 코드·문서
근거(리셋 없음·조건 극성·46=46)는 방향은 맞았지만 **우리 C# 포트 코드를 원작
증거로 댄 순환**이 하나 섞여 있었다(`.claude/TEAM_RULES.md` 뿌리 ㊱로 기록됨,
커밋 `e810877`) — **리서치담당이 `war3map.j` 원문을 직접 확인해 완전히 닫았다.**

**원문 3줄:**
```jass
// ① 리셋: InitGlobals(맵 로드 1회)에만 존재, 게임 중 되돌리는 곳 8,156개 함수 중 0곳
// ② 극성: 46개 트리거 Conditions가 토씨 하나 안 틀리고
if(not(udg_Tech_Onedill[GetConvertedPlayerId(GetTriggerPlayer())]==false))then
return false
endif
// → not(flag==false) = flag==true일 때 발동 거부. false만 통과.
// ③ 성공 분기 Actions가 46개 전부 동일하게 플래그를 true로 세움
```

**결론: "제한"이 맞다.** 46개가 서로를 잠그는 구조이고, **플래그가
`[GetConvertedPlayerId(...)]`로 플레이어별 배열**이라 정확히는 "플레이어당
초월·불멸·영원 채팅해금 평생 1회"다(4인 게임이면 팀 전체론 최대 4기, 각자 1기씩).

⚠️ **곁가지 — 헷갈리지 말 것**: `udg_Tech_Onedill_int`라는 별도 정수 배열이
있는데, 이건 "보물상자 특수효과 한 번만 보여주기" 부수 연출 게이트라 이 질문과
완전히 무관하다. 이름이 비슷하니 나중에 다시 찾을 때 헷갈리지 않게 여기 남긴다.

**`BOOLEAN_FLAG_CHANNEL.md`의 "등급 해금 플래그"라는 이름표는 부정확한 요약이었다**
— 같은 조사 안에서도 요약 라벨과 상세 트리거 분석(`BALANCE_RESEARCH.md`)이 갈린,
오늘 반복된 그 패턴(라벨이 실제 동작과 다르게 읽힐 수 있다)의 사례로 남는다.

## 🔴 ⑤ A안(제한) 붕괴 스윕 — 범위는 좁아지지 않았다

`Tools/simulate_balance.py` §⑤. `MODELS_DT_CAPPED` — 영원함(T6)·초월함(T9)·
불멸(T11)에 도달하는 순간을 "플레이어당 공유 슬롯 1개"로 캡을 씌운 4모델
변형을 만들어 `TIER_SCHEDULE_CONFIDENCE_2026-09-06.md`와 같은 12개 조합
(칸수 8·10·12·14 × 모양 뒤가넓음·균등·앞이넓음)으로 다시 스윕했다.

```
모델            A안 범위(캡 적용)         B안 범위(§15, 폐기됨— 참고용)
고정 10기/레인    R8~R69 (0/24 완주)      R8~R71 (3/24 완주)
안 조합          R12~R73 (9/24 완주)     R12~R14 (14/24 완주)
최대 조합(그리디)  R55~R74 (13/24 완주)    R47~R68 (11/24 완주)
국소최적 조합     R55~R73 (20/24 완주)    R68~R71 (22/24 완주)
```

**「범위가 안 좁아졌다」가 정직한 답이다.** 좁아지긴커녕 **"안 조합"·"국소최적
조합" 둘은 오히려 훨씬 넓어졌다**(안 조합: 폭2→폭61, 국소최적: 폭3→폭18).
**좁아졌다고 말하고 싶어서 좁히지 않는다** — 이건 오늘 만든 밸런스 지표 중
가장 반직관적인 결과라 원인을 짚는다.

**원인**: "안 조합"·"국소최적 조합"은 시간이 지날수록 유닛을 계속 쌓는 모델이다.
**B안(캡 없음)에서는 스케줄이 영원함·초월함·불멸에 닿기만 하면 그 등급의
압도적 화력을 무제한으로 쌓을 수 있어서, 어떤 칸수·모양 조합이든 "일단 그
등급에 닿으면 이긴다"는 사실상 같은 결과로 수렴했다** — 그래서 B안의 좁은
범위(안 조합 R12~R14)는 **진짜 안정성 신호가 아니라 "무제한 최상위 등급
스택"이라는 틀린 가정이 모든 조합을 같은 방향으로 밀어붙인 인공물**이었다.
**캡을 씌우자 그 가짜 수렴이 사라지고, 모델의 운명이 이제 "영원함·초월함·
불멸이 아닌 나머지 등급의 스케줄 타이밍"(정확히 `tier_for_round`의 "75라운드
균등분할" 가정)에 훨씬 더 민감해졌다** — 원인은 PM이 처음 짚은 그대로,
**여전히 "75라운드 균등분할" 가정 자체다.** A안은 캡이 정확했을수록(원작에
더 가까울수록) 오히려 이 잔여 가정의 취약성을 더 선명하게 드러냈다.

**"고정 10기/레인"은 거의 안 움직였다**(R8~R71 → R8~R69) — §③(어제)에서 이미
확인했듯 이 모델의 붕괴는 다른세계(T8, 연구소 자체가 없는 등급) 구간에서
나서 애초에 영원함·초월함·불멸 캡과 무관했기 때문이다.

**"최대 조합(그리디)"는 A안에서 오히려 붕괴가 늦어졌다**(R47~R68 → R55~R74,
완주 비율도 11→13/24) — 캡에 막혀 승급 못 한 저티어 쌍이 "사라지지 않고 그
등급에 쌓이는" 내 구현 선택(승급 대신 재료를 남겨두는 쪽, "플레이어라면
승급을 시도 안 하고 그냥 들고 있는다") 때문일 가능성이 크다 — 이건 모델의
구현 선택이 결과에 미치는 영향이라 별도로 표시해둔다(더 정밀하게 재려면
"막힌 재료를 다른 방향으로 승급 시도한다"는 재분배 로직이 필요한데, 그건
또 다른 창작이라 이번엔 안 넣었다).

**결론**: A안이 "확정된 사실"(플레이어당 1기)을 반영했는데도 붕괴 라운드
범위는 좁아지지 않았다 — 오히려 두 모델에서 넓어졌다. **`tier_for_round`의
"75라운드 균등분할" 가정이 여전히 근본 원인이고, 위습·조합 경제(챗언락 캡
제외)의 나머지 부분(안흔함~전설적인 구간이 정확히 언제 완성되는가)이 안
풀리는 한 이 폭은 안 닫힌다.**
