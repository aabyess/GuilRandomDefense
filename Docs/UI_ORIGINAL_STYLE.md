### 1-3. 개편안
- 점수판을 **진짜 표**로: 제목(1줄) + 2열(이름 | 적 수) × 머리줄+4행, 신세계에선 3열(풀카운트) 추가·글자 약간 축소(원작 0.11→0.09 = 약 −18%).
- 머리줄 둘: 「난이도 : 보통모드」(청록), 「남은 라운드 유닛 수」(초록).
- 이름 칸: `[플레이어 색 칩] [칭호 색 접두어] 닉네임`(내 줄은 굵게 — 우리 쪽 유지 아이디어). 색은 원작 4색 그대로.
- 골드·목재 열은 **선택 사항 3안**: (가) 뺀다(원작 그대로 — 상단 바엔 내 것만 있어 팀 것은 안 보임) (나) 점수판 맨 오른쪽 작은 열로 유지(권장) (다) Tab 누르면 상세. → **사장님 선택 필요**.
- 데스카운트 경고: 이미 알림이 있으면 그대로(원작도 본인에게만 3초).
- 구현 난이도: 중. 건드릴 파일: `UI/GameHud.cs`(BuildTeamPanel·RefreshTeamPanel 교체, TMP 한 덩어리 → 열별 TMP 또는 `TMP <cspace>`/`<pos>` 태그로 정렬), `UI/PlayerDisplayName.cs`(칭호는 이미 접두어로 만들어 둠 — 색 태그 포함 문자열을 그대로 재사용).
- 멀티 영향: **새 [Networked] 필요 없음**. 적 수·골드·목재는 클라가 이미 읽고 있고(PlayerContext 복제), 풀카운트는 10-03에 `NetGameState.FullCounts`로 복제 완료. 닉네임은 `NetPlayer.Nickname`(이미 [Networked]). 칭호는 호스트 PersistentSave에서만 알므로 **칭호를 점수판에 보이려면** 클리어 횟수를 슬롯별로 복제해야 함(작은 [Networked] 1개: `NetPlayer`의 클리어횟수 int).

### 2-4. 개편안 (우선순위)
1. **초상화 아래 체력 바(실시간)** — 가장 눈에 띄는 차이. 선행: 현재 체력 노출.
2. **영웅 레벨 옆 경험치 바 + (원하면) 힘/민/지 줄** — 원작 `Hero` 표시와 같은 자리.
3. **인벤토리를 아이콘 슬롯으로**(6칸 vs 8칸 결정 필요) + 단축키 표기.
4. 상단 좌측 메뉴 단추 이동·타이머 서식(저비용).
5. 버프 아이콘 줄(큰 작업 — 별도 승인).
- 파일: `UI/GameHud.cs`(주), 체력 노출은 `Units/UnitAttacker.cs`·`Net/NetEntity.cs`. 멀티: 체력·XP를 클라 겉모습에 보이려면 `NetEntity`에 [Networked] 필드(체력 비율 1개, 경험치 1개) 추가 — 네트워크 구조 변경이라 호스트·클라 같은 빌드. 단일 유닛 선택 화면에서만 필요하므로 대역폭은 작다.

## ③ 방 만들기 · 시작 전 (NetBoot · NetLobbyUi)

### 3-1. 원작 시작 단계 (j에서 직접)
- 로비(워크3 커스텀 게임 설정 화면)는 **맵 설정이 정한다** [j 116030~116111, `config` 함수]: 플레이어 1~4 = 사람(`MAP_CONTROL_USER`, 종족 선택 불가, 시작 위치 0~3, 색 `ConvertPlayerColor(0~3)`), 5~8 = 중립/컴퓨터(적), **팀 0 = 사람 4명, 팀 1 = 적**(`SetPlayerTeam` [j 116080~116111]). 색은 시작 직후 3번을 보라·4번을 노랑으로 고정 [j 15198·15199].
- 시작 직후(`InitStart`, 0.02초 [j 15260]): 화면 가림·카메라 거리 3000·카메라 범위 제한·「잠시만 기다려주십시오」 6초 [j 15200~15209].
- **6.6초에 모드 선택 대화상자**(`Select1` [j 15263~15285]): 제목 「모드를 선택하세요.」, 단추 6개 — `쉬움`(하늘색 00bfff)·`보통`(연보라 ee82ee)·`어려움`(빨강 ff0000)·`지옥`(보라 9400d3)·`신`(금색 ffd700)·`악몽`(금색) + 뒤에 「 모드」. **방장(1번 플레이어)에게만** 표시 [j 15280], 나머지에겐 「방장이 모드를선택하고있습니다. 잠시기다려주세요.」 30초 [j 15279]. **투표는 없다 — 방장 단독 선택.**
- 모드 선택 뒤(`Select_effect`): 「로드(load) 명령어…-load 코드…모드선택후 1라운드 전 20초동안」 안내 [j 15483], **「1라운드 시작까지」 타이머 창 21초** [j 15484~15487], 그 뒤 점수판 생성 [j 15488].

- 메인 패널: 닉네임 · 방 만들기 · 방 코드로 참가 · 다시 참가.
- 방 패널(1120×760): 방 코드(+복사) · **슬롯 4줄**(번호·이름·상태 꼬리표) · **난이도 6버튼**(방장만, 선택=노랑) · 준비/시작/나가기 · 대기실 채팅(별도 입력).
- ⚠️ 원작 대조: 우리는 난이도를 **방 안에서 로비 단계에 미리** 고른다(원작은 판 시작 6.6초 뒤 대화상자). `DifficultySelectHud`도 혼자 하기용으로 남아 있음 — **둘 다 원작과 다르지만 이미 사장님이 쓰는 흐름**이라 순서를 바꾸자는 제안은 아님(워크3 로비엔 난이도 칸이 없어 우리 방식이 합리적).

### 3-3. 개편안 — 「워크3 커스텀 게임 로비」 모양으로
레이아웃(1920×1080 기준, 목업 ③):
1. **왼쪽: 맵 정보 카드** — 맵 이름 「구 랜 디」, 버전(0.3.x), 난이도 설명 한 줄(선택에 따라 총 라운드·데스카운트 한계 — 원작 모드 사양: 쉬움 50R/보통 60R/어려움 이상 75R, 한계 70 등, `DifficultyModeData`에서 읽음), 방 코드(크게 + 복사).
2. **가운데: 플레이어 슬롯 목록(워크3 로비 표)** — 열: `색 칩 | 이름(닉네임·칭호) | 상태(방장/준비/대기/끊김) | (팀)`. 워크3처럼 **슬롯마다 원작 색**(빨·파·보·노), 빈 슬롯은 「열림」, 방장은 왕관 모양 표시. 팀 칸은 원작이 사람 4명 한 팀이라 **고정 표기만**(바꿀 수 없음).
3. **오른쪽/아래: 난이도 6버튼 = 원작 색**(쉬움 하늘 · 보통 연보라 · 어려움 빨강 · 지옥 보라 · 신/악몽 금) — 방장만 누름, 나머진 잠금(원작 「방장이 모드를 선택하고 있습니다」문구 그대로 표시).
4. **아래: 채팅 창**(로그 영역 + 입력, 워크3 로비처럼 방 안에 고정) — 지금은 알림 자리에 줄이 쌓임.
5. **시작/준비/나가기**는 오른쪽 아래, 워크3의 「시작 게임」 위치.
6. 시작 직후 연출은 원작 흐름 그대로 유지 옵션: 「잠시만 기다려주십시오」 → (이미 고른 난이도라면 대화상자 생략) → 「1라운드 시작까지 21초」 타이머.
- 시각 톤: 짙은 남색 바탕 + 금테(하단 콘솔과 같은 `SlotColor`·금 테두리) — 게임 안과 같은 톤으로 맞춘다.
- 구현 난이도: 중. 건드릴 파일: `Net/NetLobbyUi.cs`(BuildRoomPanel 재배치 — 로직 `NetLauncher`는 그대로), `UI/GameHud.cs`의 색 상수 재사용.
- 멀티 영향: **새 [Networked] 없음**(슬롯·준비·난이도·닉네임은 이미 복제됨). 칭호를 슬롯 줄에 보이려면 ①과 같은 클리어 횟수 복제 1개.

### 교체 가능 구조 제안 (구현 시)
- `Assets/Resources/UI/UiSkin.asset`(ScriptableObject) 하나에 9-slice 스프라이트 슬롯(콘솔 틀·칸 틀·멀티보드 틀·버튼 틀·로비 틀)과 색 팔레트를 모은다. 코드는 `UiSkin.Current.xxx`만 읽는다 → 정품 그림을 같은 슬롯에 넣으면 끝, 코드 수정 없음.
- 근사 그림은 `Tools/blender` 아닌 **Python(Pillow)로 생성하는 스크립트**(`Tools/ui/gen_ui_skin.py`)로 만들어 재현 가능하게 — 생성물은 우리 소유.
- 맵 안 아이콘을 꺼낼 때는 변환 스크립트(`Tools/ui/extract_ord_icons.py`: mpqread + BLP→PNG)를 두고, 꺼낸 PNG를 `Assets/Art/UI/Original/`에 넣는 **그 커밋마다** `Docs/REPLACE_BEFORE_PUBLIC.md` 🔴 표에 한 줄(예: 「UI 아이콘(ord.mpq 추출 N개) / Assets/Art/UI/Original/」).
- 난이도: 슬롯 구조 자체는 하~중(UI 코드가 지금 `Image.color`로 칠하는 것을 스프라이트로 바꾸는 작업). 그림 근사 생성은 반나절 안팎. 멀티 영향 없음.
