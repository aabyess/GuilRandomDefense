# 영원함 강화소 — 유닛 전용 트랙 설계 (2026-10-06, 구현담당3)

사장님 지시(10-06): 「강화소에서 영원함이 전체(등급) 업글로 돼 있는데, 원랜디는 해당 유닛만 업글한다 — 원랜디처럼 고쳐라」.
**상태: 설계 — PM 확인 전 구현 안 함.**

## 1. 원작 (근거 = `war3map.w3q`·`war3map.w3u` 직접 디코드, `Tools/w3x/w3q.py`·`w3u.py`, 2026-10-06)

- 강화소 `h06R`의 연구 목록(`ures`) = `R032,R02O,R015,R00X,R013,R007,R014,R016` **8개**. 선행조건(`ureq`)·연구별 `greq` 모두 빈 값, `war3map.j`에 `'R0xx'` 등장 0건(트리거 개입 없음)
  → **그 유닛이 필드에 있든 없든 8개 버튼이 늘 보이고 누구나 살 수 있다.**
- 8개는 전부 **21렙 · 골드 110(첫 구매) + 이후 레벨당 80(`gglb` 110 / `gglm` 80, 목재·시간 0)**. 효과는 공속(`gba1` 첫 렙 / `gmo1` 렙당) + 공격력 가산(`gba2`=`gmo2`).
- 각 연구는 영원한 유닛 **하나(또는 둘)에만** 붙는다(`upgr`): 미호크 R007 · 에이스 R00X · 비비 R013 · 버기 R014 · 카벤딧슈·하쿠바 R015(공유) · 핸콕 R016 · 오뎅 R02O · 우타 R032. 니카·음표병사 우타·토트 무지카 3기는 초월 트랙 R003을 쓴다.
- 등급 공통 `R009`(영원 업그레이드)는 `upgr` 참조 0건 · `j` 0건 = **죽은 업그레이드** (Docs/reference/R009_AND_GRADE_UPGRADE_SPEED.md ①을 w3q로 재확인: R009는 glvl 25·gba1 0.11 존재하나 어디에도 안 붙음).

## 2. 우리 쪽 현재

- `UnitUpgrade_영원함 강화.asset` = 등급 트랙(`targetGrades: 9`, 21렙 아님 maxLevel 5, `hasOriginalResearch 0` = 잠김, 값은 자리표시자). `UnitUpgradeShop`에 영원함 강화소(트랙 1개)가 물려 있다.
- 읽는 길: `UnitUpgrades.SpeedMultiplierForGrade/BonusForGrade/LevelForGrade(grade)` ← `UnitAttacker`(3043·3053). 키가 **등급**이라 유닛 전용을 못 담는다.
- 멀티 복제: `NetCatalog.gradeTracks`(순서 목록) ↔ `NetPlayer.GradeLevels[16]`(상한 16). 지금 등급 트랙 10개 + 유닛 트랙 8개 = 18 > 16 → **배열 상한을 올려야 한다**(NetPlayer 302행 `i < 16`).
- 우리 영원함 유닛 = 사장님 새 8종(김영원·조세민·이지원·문필환·서민성·김정래·윤현모·최상호 킹카). 원작 8 트랙과 **이름 1:1이 아니다**.

## 3. 설계안

**구조**: `UnitUpgradeTrackData`에 맨 뒤 필드 `UnitData targetUnit`(없으면 기존 등급 트랙). 유닛 트랙은 `targetGrades` 비우고 `targetUnit`을 채운다.
- `UnitUpgrades.SpeedMultiplierForGrade/BonusForGrade(grade)` → `…(UnitData unit)` 호출로 바꾸고(UnitAttacker 두 줄), 안에서 「`targetUnit == unit`인 트랙」을 먼저 보고 없으면 등급 트랙. 유닛 트랙은 `targetGrades` 매칭에서 제외(안 그러면 등급 전체에 퍼진다).
- 영원함 강화(등급 공통) 에셋·슬롯 **삭제**. 영원함 강화소 슬롯 = 유닛 트랙 8개(원작 강화소 h06R과 같은 8칸).
- 비용 `costBase 110` · `costGrowthPerLevel 80`(엔 = 원작 골드 값 그대로, 히든 60/50과 같은 대응), `maxLevel 21`, `hasOriginalResearch 1`.
- **유닛이 없을 때 버튼**: 원작대로 **항상 보이고 살 수 있다**(선행조건 없음). 안 사 놓고 나중에 유닛이 생기면 그때부터 적용된다.
- 슬롯 이름: 「[영원함] {유닛 이름} 강화」, 툴팁에 「{유닛}의 공격력 +N · 공속 +N%」.
- 세이브/멀티: 레벨은 트랙 에셋 단위 정수라 기존 `legacyGradeLevels`·`GradeLevels` 경로에 그대로 실린다(배열 상한만 24쯤으로, `NetCatalog.gradeTracks` 순서에 8개 뒤에 추가 — 맨 뒤 추가라 기존 인덱스 불변). 세이브 코드(10-06 클리어 판)가 트랙 이름/인덱스를 쓰는지 구현 때 확인.

## 4. 수치 대응 — **PM·사장님 결정 필요**

원작 8트랙은 값이 서로 다르고(미호크 공격력 10,800 vs 에이스 4,000 …) 우리 영원함 8종은 이름이 1:1이 아니다. 후보:

- **(가) 대표값 하나**: 8종 모두 같은 트랙값 — 공속 L1 +15% / +15%렙(원작 8개 중 4개가 정확히 이 값 R015·R016(렙당)·R02O·R00X 근사), 공격력 +4,500/렙(중앙값). 단순·공평, 단 원작의 유닛 간 차이(미호크 특화 등)는 사라진다.
- **(나) 원작 8값을 우리 8종에 배정**: 값은 그대로, 누가 어느 값인지만 정한다(예: 영원함 유닛 강한 순서 ↔ 원작 공격력 큰 순서). 배정은 창작이라 사장님 확인 필요.
- **(다) 유닛마다 사장님이 값 지정**.

내 권장: **(가)로 구현하고 (나)로 갈 수 있게 트랙 에셋을 유닛마다 따로 둔다**(값만 바꾸면 됨). 어느 쪽이든 구조는 같다.

## 5. 구현 범위 (설계 확인 뒤)

`UnitUpgradeTrackData`(필드 1) · `UnitUpgrades`(조회 2곳 유닛 키) · `UnitAttacker`(호출 2줄) · `UnitUpgradeShop`(필터 없음 — 트랙 목록만) · `NetPlayer`/`NetCatalog`(상한) · 트랙 에셋 8개 생성 Apply + 영원함 강화 에셋·`MapGenerator` 물림(1477행) 정리 · 구현담당2와 슬롯 표시(「유닛 이름 + Lv」) 한 줄 맞춤. 에디터 실측: 한 영원함 유닛만 공속/공격력이 오르고 다른 영원함·같은 등급 다른 유닛은 불변.
