# 75라운드 곡선 설계안 (2026-09-02, 리서치담당)

> **이 문서는 조사가 아니라 설계 제안이다.** 원작 원랜디에 라운드별 체력·공격력 곡선이 수치화된 적이 없다는 게 `Docs/ORIGINAL_GAME_RESEARCH.md` 11번 섹션 조사 결과다. 여기서부터는 **전부 우리 설계**이고, 원작 근거가 없다. 사장님이 판단할 자료로 제시하는 것이지 확정안이 아니다.
> 그라운딩 방법: 원작 수치가 없으니, 대신 **우리 게임에 실제로 존재하는 데이터**(`Assets/Data/Units/Roster/` 234개 유닛 에셋의 실제 스탯)를 근거로 삼았다. 아래 3번 참고.

## 1. 지켜야 할 제약 (PM 지시 + 기존 조사)

| 제약 | 값 | 출처 |
|---|---|---|
| 총 라운드 | 75 | `ORIGINAL_GAME_RESEARCH.md` §1 |
| 보스 주기 | 10라운드마다, 신세계 진입 후 5라운드마다 | 동일 |
| 보스 수 | 9종 (기존에 이미 확정) | 프로젝트 상태 |
| 데스카운트 | 라인 카운트 70 초과 시 10→0 차감, 0에서 패배 | 동일 |
| 시작 자원 | 30엔 + 목재 1 + 랜덤위습 5 | 사용자 확정(기존 메모리) |
| 유닛 등급 | 13단계(실질 강도는 8티어로 묶임 — 3번 참고) | `UnitData.cs` |

**보스 라운드 확정**: 10라운드 간격을 60라운드까지 채우면 6개(10,20,30,40,50,60), 남은 15라운드(61~75)를 5라운드 간격으로 채우면 3개(65,70,75) — **합 9개, 기존에 확정된 "보스 9종"과 정확히 맞아떨어진다.** 이걸 근거로 **신세계는 61라운드부터 시작한다**고 확정한다(원작 조사에서 "어려움 미만은 60라운드 종료, 신세계 미돌입"이라 했으므로 61부터가 자연스럽다) — 이 역산 자체가 이번 설계의 핵심 확인이다.

**⚠️ "8라운드 뒤 백수생활"에 대한 정정**: `STORY.md`에 따르면 백수생활 5분 대기는 **8번째 스토리(사이버넷)를 깼을 때** 나오는 것이지, **웨이브 8라운드**와는 무관하다. 스토리는 라운드와 별개로 연쇄 진행되는 시스템이라(`STORY.md` "라운드가 아니라 연쇄"), 이 라운드 곡선에 반영할 항목이 아니다. PM 메시지에 라운드처럼 언급돼 있어 혼동될 수 있어 짚어둔다.

## 2. 스코프 밖 — 이 문서가 안 다루는 것

- **데스카운트 자체의 구현**(70 초과 판정, 리셋 여부)은 이미 별도 시스템이다. 이 문서는 그 시스템이 트리거되는 "압력"(마리 수·이동속도)만 설계한다.
- `EnemyData.cs`에는 현재 **`attackPower` 필드가 없다** — 적이 방어선을 직접 공격하는 코드도 안 보인다(`EnemyDummy.cs`에 없음). PM이 요청한 "적 공격력" 컬럼은 **아직 스키마에 없는 값**이라, 이 문서는 수치만 제안하고 **필드 추가는 구현 판단(코딩 영역)**으로 남긴다.

## 3. 데이터 그라운딩 — 실제 유닛 로스터가 이미 깔끔한 등비수열이다

`Assets/Data/Units/Roster/*.asset` 234개 파일에서 등급·hp·attackPower를 직접 뽑아봤다. **등급별로 완전히 균일한 값**이 들어 있었다(개별 유닛차 없음 — 플레이스홀더 정책과 일치). `UnitData.cs`의 `Tier()`가 13개 등급을 8단계 실강도(0~7)로 묶는데, 그 티어별 값이 놀랍도록 깔끔한 공식을 따른다:

| Tier | 해당 등급 | HP | 공격력 |
|---|---|---|---|
| 0 | 흔함 | 100 | 5 |
| 1 | 안흔함 | 180 | 11 |
| 2 | 특별함 | 324 | 24.2 |
| 3 | 희귀함/히든/랜덤유닛 | 583.2 | 53.2 |
| 4 | 특수함 | 1,049.8 | 117.1 |
| 5 | 전설적인 | 1,889.6 | 257.7 |
| 6 | 제한됨 | 3,401.2 | 566.9 |
| 7 | 초월/불멸/영원함/다른세계 | 6,122.2 | 1,247.2 |

**검증**: `HP(tier) = 100 × 1.8^tier`, `ATK(tier) = 5 × 2.2^tier` — 8개 티어 전부 오차 없이 들어맞는다. 이건 사용자/이전 세션이 유닛 스탯을 채울 때 이미 이 등비수열로 설계해뒀다는 뜻이다. **이 문서는 그 기존 설계를 그대로 이어받아 적 곡선에 적용한다** — 그래야 "이 등급까지 조합해야 이 라운드를 넘긴다"는 감각이 유닛 쪽과 몹 쪽에서 서로 어긋나지 않는다.

보스 라운드 9개를 티어 0~7에 순서대로 대응시키고, 마지막 75라운드만 티어7을 넘어서는 "합산 대응 구간"으로 뒀다:

| 보스 라운드 | 요구 티어 | 의미 |
|---|---|---|
| 10 | 0(흔함) | 시작 자원(위습5)만으로 빠듯하게 통과 |
| 20 | 1(안흔함) | 흔함만으론 부족 — 조합 강제 |
| 30 | 2(특별함) | |
| 40 | 3(희귀함/히든) | |
| 50 | 4(특수함) | |
| 60 | 5(전설적인) | 어려움 난이도 마지막 보스 |
| 65 | 6(제한됨) | 신세계 진입, 페이스가 2배로 빨라짐(10→5라운드 간격) |
| 70 | 7(초월) | |

## 5. 공식

### 5-1. 몹 체력·공격력 (일반 라운드)

**1~60라운드**(10라운드=1티어):
```
mobHP(r)  = 100 × 1.8^((r-10)/10)
mobATK(r) = 5   × 2.2^((r-10)/10)
```

**61~75라운드(신세계, 5라운드=1티어)**:
```
mobHP(r)  = 1889.6 × 1.8^((r-60)/5)
mobATK(r) = 257.7  × 2.2^((r-60)/5)
```

두 공식은 r=60에서 정확히 이어진다(연속함수). 신세계에서 지수가 2배 빨리 도는 것 자체가 "페이스가 빨라진다"는 체감을 만든다 — 별도 배율을 추가할 필요가 없었다.

### 5-2. 보스 배율

```
bossHP  = mobHP(그 라운드)  × 8
bossATK = mobATK(그 라운드) × 5
```

배율 근거: 원작 조사에서 "신세계 보스는 무적 상태 건물로 2개의 추가 게이지를 가지고 등장"한다는 서술이 있다(`ORIGINAL_GAME_RESEARCH.md` §1) — 보스가 일반 몹보다 훨씬 두꺼운 존재감을 가진다는 것만 참고하고, 정확한 배율은 원작에 없어 **HP×8/ATK×5는 순수 제안**이다. 65·70·75라운드 보스에 한해 "게이지 2단계" 연출(예: 체력바 두 개로 표시)을 넣으면 원작 감각과 더 맞을 수 있다 — 이건 구현 아이디어라 코딩 판단 몫으로 남긴다.

### 5-3. 이동속도 (구간별, 로스터와 무관한 독립 설계)

로스터의 `moveSpeed`는 전 등급 22로 고정이라(유닛은 등급별로 안 빨라짐) 참고할 근거가 없다 — 적 이동속도는 순수하게 새로 설계했다:

| 구간 | 이동속도 | 근거 |
|---|---|---|
| 1~20 | 15 | 초반은 반응할 시간을 준다 |
| 21~40 | 18 | 원작 조사 "난이도가 높아질수록 요구되는 이속감소 디버프량이 증가"(`ORIGINAL_GAME_RESEARCH.md` §2)와 감각을 맞춤 |
| 41~60 | 21 | |
| 61~75 | 24 | 신세계는 전 요소가 빡빡해지는 구간 |

### 5-4. 마리 수

| 구간 | 일반 라운드 | 보스 라운드 |
|---|---|---|
| 1~60 | **35마리** (원작 조사 그대로) | **보스 단독 1마리** |
| 61~75 | **40마리** (신세계는 압박 증가) | 보스 단독 1마리 |

**보스 라운드에 잡몹을 동시에 넣을지는 원작에서도 확인 못 한 부분이다**(`ORIGINAL_GAME_RESEARCH.md` §1) — 이 설계는 "보스 단독"을 택했다. 이유: 보스 HP가 이미 그 라운드 몹의 8배라 잡몹까지 겹치면 난이도가 이중으로 뛰어 조정하기 어렵다. 잡몹을 곁들이고 싶으면 보스 HP 배율을 낮추는 트레이드오프가 필요하다.

### 5-5. 라운드 클리어 보상 (골드)

`WaveData.wispRewards`는 이미 있으니(위습 지급), 여기서는 **골드**만 설계한다. HP/ATK와 같은 형태(1.8배 성장)를 쓰되 기준값만 다르게 잡았다:

```
1~60:  roundGold(r) = 20 × 1.8^((r-10)/10)
61~75: roundGold(r) = roundGold(60) × 1.8^((r-60)/5)
```

이건 **라운드 클리어 시 전원에게 지급되는 보너스**이고, 몹 처치당 골드(`EnemyData.goldReward`, 개별 킬 보상)는 별도다 — 둘을 합쳐야 실제 수입이 된다. 이 보너스만으로 후반 조합 비용(예: 다른세계 조합 "골드 10,000")을 못 채우는 게 정상이다 — 누적 킬 골드·도박·판매가 나머지를 채워야 경제가 성립한다.

## 7. 어느 라운드가 고비인가 — 설계 의도

- **10, 20, 30, 40, 50, 60라운드(어려움 구간 보스)**: 각각 "그 티어 유닛을 확보했는가"를 시험한다. 여기서 막히면 **조합이 그 등급까지 안 올라간 것** — 뽑기 운이 아니라 진행 속도 문제라는 신호로 설계했다.
- **60→61 전환**: 신세계 진입. 페이스가 갑자기 2배 빨라진다(10라운드→5라운드 간격). 여기서부터 확 어려워지는 걸 의도했다 — "어려움 미만"은 60에서 끝나는 난이도이므로, 60을 넘기는 순간부터는 신세계 난이도로 다뤄야 자연스럽다.
- **65, 70라운드**: 신세계 보스. 초월/불멸/영원함 등급을 요구한다 — 이 등급들은 조합 재료 자체가 희귀(행운토큰·다른세계 등)해서, 여기서 막히면 **경제(골드·목재·행운토큰) 축적이 부족한 것**이지 전투력만의 문제가 아닐 수 있다.
- **75라운드(최종보스)**: 로스터 최고 티어(7)를 넘어서는 값이다. 의도적으로 "단일 최상위 유닛 하나로는 못 이긴다" — 여러 초월/불멸/영원함 유닛을 동시에 굴리거나 도움소 광역 스킬(불비/버스터콜/지진/해일 계열)을 써야 넘어가게 설계했다. 이게 "그냥 스탯 싸움"이 아니라 "팀 구성"을 요구하는 지점이다.

## 8. 사용자가 확인해야 할 것 (원작 근거 없이 순수 제안한 것들)

- 보스 HP×8 / ATK×5 배율 — 임의값, 플레이테스트로 조정 전제
- 이동속도 4단계 구간(15/18/21/24) — 임의값
- 마리 수 61라운드부터 40으로 증가 — 임의값
- 보스 라운드에 잡몹을 안 섞은 것 — 설계 선택, 원작 확인 불가라 임의 결정
- 라운드 클리어 골드 보상 공식(20 기준값) — 임의값, 전체 경제 밸런스와 맞물려야 해서 특히 조정 가능성 높음
- `EnemyData`에 `attackPower` 필드가 없다는 것 — 스키마 추가가 필요한지 PM/구현담당 판단 필요

## 9. 검증 방법 제안 (구현 후)

수치를 코드에 넣기 전에, `Assets/Data/Units/Roster/`에서 각 티어 유닛의 DPS(공격력×공속)와 이 문서의 `mobHP`를 비교해 "그 티어 유닛 1기가 몹 1마리를 몇 초에 잡는가"를 계산해보면 체감 난이도를 대략 가늠할 수 있다. 이건 리서치 범위 밖이라 제안만 남긴다 — 실제 검증은 플레이테스트가 정확하다.
